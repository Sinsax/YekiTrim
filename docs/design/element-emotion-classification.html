文字元素 · 情绪分类样式方案 候选稿 · 先给几种类型

按你说的三个输入合起来：comic-draft 的形态 × 动态、工作台的 39 档动效、 LLM 情绪。下面先给**三套"分几类"的候选**（4 / 6 / 9）， 每套都标清**要改什么、代价多大**——你挑一套我再落地。

⚠️ 先摊开三个硬约束（不先说清，方案就是空谈）
  1. LLM 现在只能选 4 档 style，而且它根本不知道 anim 存在。 提示词里写的是"style 四选一"（crates/yekitrim-polish/src/llm/segment.rs:120）， anim 在整个提示词里出现 0 次（我 grep 过）。 ⇒ 要让 LLM「结合情绪挑动效」，必须先改提示词，不是改界面就完事。
  2. TextStyle 是 Rust 枚举（hook/chapter/comment/count）， 认不出的一律当 comment（最保守档）。 ⇒ 加档位 = 改契约：Rust 枚举 + source 串 + 前端下拉 + 重建 dist。
  3. 元素层的 source 串只有 9 格（详见 docs/design/element-text-style-presets.html） ⇒ 形态那部分自由度受限；而动效（anim）是另一条独立通道， 不受那 9 格限制 —— 这恰恰是本方案的空间所在。
✅ 三套候选共用的一条设计原则
形态决定「长什么样」，动效决定「怎么动」，情绪只负责「挑哪一个组合」。
两个轴正交（comic-draft 原话："同一句话，动法不同情绪也不同：『啊？！』砸进来是惊吓、 慢慢推近是紧张"）⇒ 所以「分类」本质上是在给组合起名字，而不是再造一批形态。

① 候选甲 · 4 类 零契约改动：把 anim 接到现有 style 上

不动 TextStyle 枚举，只做一件事：给现有的 4 档各定一套 默认形态 + 默认动效，并让 LLM 在挑 style 时**同时挑一个情绪**（用于微调动效幅度）。

为什么这是最省的一档：现在的 4 档已经有语义（钩子/章节/吐槽/计数）， 而且 LLM 已经在选。只要补上"每档默认配哪一档动效"， 今天就能出片 —— 不碰 Rust 枚举、不碰 source 串。

③ 候选丙 · 9 类 按 comic-draft 的情绪族铺满

完全按那 7 族形态 + 6 族动态铺开，每类对应一个明确的情绪族。 表达力最强，但要动的面也最大（枚举 + source + 前端 + 提示词 + dist）。

④ 我的建议：选乙（6 类），分两步走 理由与代价

甲 · 4 类

零契约改动，最快出片

  • ✓ 今天就能用：只加"默认动效映射"，Rust 一行不动
  • ✓ 老工程逐字节不变（不动 source 串）
  • ✗ 惊呼与泄气仍只能塞进 comment ⇒ 最抢眼的两类情绪没有入口
  • ✗ 等于"39 档做出来了，但只有 4 个抽屉"

乙 · 6 类推荐

补上两个高频情绪，代价可控

  • ✓ 把已经做好的砸入族 / 收缩族真正接上
  • ✓ 6 个抽屉对 LLM 仍是可枚举的（再多就开始乱选）
  • ✓ 改动面清楚：枚举 +2、提示词 +2、前端下拉 +2
  • ⚠️ 要改契约：老工程重跑 process 后行为可能变（需 R4 判据）
  • ⚠️ 认不出的 style 仍落 comment ⇒ 兜底档必须最保守

丙 · 9 类

表达力最强，但风险最高

  • ✓ 每种情绪都有专属形态 + 动效组合
  • ✗ LLM 选不准：9 选 1 且语义相近（"惊呼"vs"惊叹"），实测会乱选
  • ✗ 改动面最大，且很多形态底座还不支持（逐字能力）
  • ✗ 与"文字元素整段最多 1~2 条"的现实不匹配 —— 用不到这么多档
为什么推荐 6 而不是 9：LLM 的选择精度是瓶颈，不是表达力。
提示词里已经写着「整段最多 1~2 条文字元素」—— 一集里真正出现的元素很少，9 个抽屉大部分永远空着， 而每个抽屉都会让 LLM 多一次选错的机会。
⇒ 先上 6 类，观察一段时间真实分布，哪一类用得最多、哪一类从没出现，再决定要不要铺到 9。

⚠️ 一个必须先决定的岔路：LLM 要不要真的产出 anim？
现在 anim 是人工在界面上选的，LLM 完全不碰（提示词里 0 次出现）。 两条路：
  • 只让 LLM 选"类"（6 选 1），动效由类默认决定 ⇒ 提示词改动小、可控。 本页的三个候选都是按这条写的。
  • 让 LLM 同时选类 + 动效（6 × 39 组合）⇒ 表达力最强， 但组合空间 234 种，LLM 选不准的概率很高，而且报告里没法归因。
⇒ 建议走第一条：类决定默认动效，用户想改再在界面上改（那是人工的强项）。
