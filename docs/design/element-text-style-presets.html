文字元素样式 · 设计靶子 4 档 → 重新设计

元素层（时间轴上那种"贴在画面上的情绪字"）自己的样式。与字幕层的 24 字段、 与动效层的 39 档都不是一回事 —— 那两层各有自己的设计稿。

⚠️ 先立规矩：这一层能表达的只有 9 个量。
元素样式不是一堆独立字段，而是 process 解析后写回 event.source 的 一条竖线分隔的串（权威：crates/yekitrim-polish/src/process/mod.rs:1864）：
<style>|<font_px>|<stroke_px>|<r,g,b,a>|<sr,sg,sb,sa>|<weight>|<backdrop>|<tilt_deg>|<squash_y>
⇒ 任何设计只要落不进这 9 个量，就表达不出来（下面每条都逐字段核过）。
⚠️ 而且 字段只能往末尾追加 —— Rust 那边写着：插在中间会让既有字段 静默错位（backdrop 被读成 tilt_deg，症状是"底衬没了、字歪了"， 而两边单测各自都过）。

① 现状：4 档实际上是同一个方块字 这是要改掉的东西

下面四张图是**照着现值 1:1 画的**（值来自 placement.rs::base_font_px 那一组）。 看一遍就会发现：四档之间只有字号与有没有底衬的差别，其余三个量 （描边色、字重档位、倾斜）几乎没拉开。

现状的三个问题
  1. 拉不开：chapter(84px/700) 与 count(64px/800) 在手机上几乎分不出； hook 与 count 都靠"大"来表达，语义是重叠的。
  2. 描边色四档完全相同（[26,26,26]）—— 这一格现在是浪费的， 而它恰恰是最能拉开"气质"的一格（近黑 = 硬；暖褐 = 复古；描边=填色 = 空心字）。
  3. 倾斜只有两档非零（hook +6° / count -4°）， 而 chapter 那格压扁 0.92 的差别肉眼基本看不出 —— 值域本来就窄（±7° / ≥0.85），与其"每个都动一点"，不如让该动的动满、不该动的彻底不动。

② 重新设计：四档各自的"语气" 同样 4 个档位，不动契约

设计原则：四档要能"一眼认出是哪一档"，而且差别要落在**不同的量**上 （不能全靠字号大小 —— 那是最容易撞车的维度）。

分工：四档各占一个"说话的姿势"
hook喊出来最大 + 最重 + 歪到上限（"停下来听我说"）
chapter标出来中等 + 压扁 + 底衬（卡片感，像章节标题条）
comment嘀咕最小 + 暖黄 + 底衬（旁白，与正文分得开）
count数出来中等 + 极重 + 反向倾斜（"第 3 次"的节奏感）

③ 每档逐字段核一遍 能不能落进那 9 个量

下面这张表是本页最要紧的部分：每一格都要能写进 source 串。 落不进去的，我把替代方案写出来（而不是假装它能做）。

⚠️ 三个"想得到但做不到"的（现在做不到，别写进设计里当既有能力）
  1. 不同字不同色（比如关键词染红）—— source 里 fill 是整条一个值。要做只能：
      · 用底衬色模拟（现在 backdrop 只是个 0/1，没有颜色字段）；   · 或者走字幕层的高亮（那边有 highlight_color，元素层没有）。
  2. 圆角底衬 / 自定义底衬色 —— backdrop 只有"有没有"，颜色与圆角都是写死的。 要改就得往 source 末尾追加字段（Rust + JS 两侧一起改）。
  3. 字间距 / 行距 —— 这一层完全没有这两个量（字幕层才 line_height）。

④ 样式 × 动效：两个下拉，正交组合

样式决定"长什么样"，动效决定"怎么动"。它们是两个独立的下拉 —— 所以下面每组都是"样式 + 动效"的合成，不是一回事。 动效那边的完整设计见 docs/plan/text-styles-comic-draft.html（39 档）。
