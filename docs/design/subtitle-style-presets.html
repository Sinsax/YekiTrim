YekiTrim 字幕样式预设 设计靶子 · 不是新契约

底座 SubtitleStyle 的**全部 24 个字段**逐档摊开，每张卡片都标出它对应的 [style.subtitle] toml 键 —— 用来确认"**设计得出来，也表达得出来**"。 权威实现：Dhampir/crates/dhampir-timeline/src/layer.rs::SubtitleStyle。

① 先看清五条口径（逐条都是踩过的坑）

  1. 描边是「外侧宽度」：stroke_ratio 是 ffmpeg borderw 的语义 —— 判据在字的轮廓外、整条宽 r。 而 CSS 的 -webkit-text-stroke: r 是居中的（里外各 r/2） ⇒ CSS 要画两倍，否则预览看着比成片细一半。
  2. 两种单位不许混：font_ratio / bottom_margin / stroke_ratio / shadow_blur_ratio 是比例（× 目标高度）； anchor_bottom 是归一化坐标（1.0 = 整个画面高）。 两者同量纲、能相减，但不是一个东西。
  3. anchor_bottom 的接管条件：< 1.0 时它说了算； 否则走老式子 1.0 - bottom_margin ⇒ 不写这两个字段的老工程逐字节不变。
  4. vertical = true 时忽略 anchor_bottom，且列容量 = 安全比例 ÷ 字号比例 ⇒ 字号一大就只排得下很少几列。
  5. 三态陷阱：vertical 是 Option<bool> —— 缺省与 false 语义相同，但只有缺省不写键。 转译器永远不写 vertical: false（写了会让老工程键集变大）。

这四个旋钮决定"能不能看清"

其余字段都是修饰；先定这四个。

font_ratio字号 = 目标高 × 它。缺省 0.055
stroke_ratio外侧描边宽 = 目标高 × 它。缺省 0.0（= 从字号推）
stroke_color描边色。缺省 [0x40,0x3c,0x3b]（深灰，不是纯黑）
outline总开关。缺省 true
✅ 2026-10-13 修完"描边糊团"之后，描边颜色真的会被用上 —— 以前填充与描边都是白墨，深色描边被静默丢弃（两个字面值相同）。

③ 描边：外侧 vs 居中（预览与成片差一倍）

这是本仓最容易出"预览看着对、成片偏粗/偏细"的地方。 下面两侧是**同一个 stroke_ratio** 的两种画法。

同一个数值，两种画法

左 = 成片口径（外侧 12px）· 右 = CSS 原生口径（居中 12px，看着细一半）

成片 / ffmpeg：外侧 12px
CSS 直接写 12px：居中（错）
⚠️ 想让 CSS 看起来与成片一样，必须写 -webkit-text-stroke: 24px（两倍）—— 因为居中描边里外各占一半。 预览要画 2×，成片画 1×，两边才对得上。

描边宽度扫一遍

压在亮背景上，太细压不住、太粗糊成一块。

可用区间大致是 stroke_ratio ∈ [0.004, 0.014] （1080p 下 4–15px）。⚠️ 再往上会开始吃掉笔画间隙（汉字间隙只有 4–8px）。

④ 纵向位置：anchor_bottom vs bottom_margin

两条路，别混着用

上 = 老式子（bottom_margin = 0.06）· 下 = 新字段（anchor_bottom = 0.72）

bottom_margin = 0.06（贴底）
anchor_bottom = 0.72（抬到上方）
⚠️ 为什么必须有 anchor_bottom：bottom_margin 原本兼两职（"距底边" + 左右安全宽），于是要把字抬上去就得给它 ≈0.6， 而安全宽被锁死成 0.875 ⇒ max_width 变负数 ⇒ 一个字都排不出来，而报告里一行差异都没有。

三档纵向位置（宿主就是这么表达的）

YekiTrim 的"上 / 中 / 下"三档 = 三个 anchor_bottom 值。

上  anchor_bottom = 0.30标题位，避开下方弹幕
中  anchor_bottom = 0.58画面中部
下  anchor_bottom = 1.00= 不写（走老式子）
⚠️ anchor_bottom = 1.0 与"不写"是等价的， 所以转译器在"下"这一档**不写这个键** —— 保证老工程逐字节不变。

⑤ 竖排：vertical = true 的四条边界

竖排的实际容量

列容量 = 安全比例 ÷ 字号比例。字号一大，列数立刻塌。

font_ratio 0.055（缺省）
font_ratio 0.12（大字，装不下）
⚠️ 竖排会忽略 anchor_bottom（自己定纵向）。 ⚠️ 且列容量算得不对时的症状是只画出头两个字，而不报错 —— 转译器那边专门有一条注释记着这事。

竖排相关字段

verticalOption<bool>。⚠️ 缺省 ≠ 写 false（见口径 ⑤）
safe_width_ratio显式配了就只认它管左右（不再从 bottom_margin 推）
max_lines缺省 3。竖排下 = 最多几列
keep_all_linestrue = 装不下就缩字号，不丢行
shrink_min_scale缩字号的下限（0.0 = 用内置下限）
⚠️ keep_all_lines = false（缺省）时超出 max_lines 的行直接丢掉 —— 字幕不该盖住半屏，但要知道它会丢。

⑥ 阴影：四个字段，与描边可以叠加

阴影 vs 描边，两种"压背景"的办法

描边更硬、阴影更软。叠起来最稳，但别两个都拉满。

只描边
描边 + 阴影
shadow_colorOption<[u8;4]>，缺省 None（不画）
shadow_dx_px / dy_px偏移，像素（不是比例）
shadow_blur_ratio模糊半径 = 目标高 × 它
⚠️ 有 shadow_color 时走单遍路径（描边那条两遍路径 只给"有描边、没阴影"用）—— 这是 2026-10-13 修糊团时有意保留的取舍， 记在 Dhampir/docs/plan/defect-outline-blob.md。

其余修饰字段（一次看全）

color填充色 RGBA，缺省白
highlight_colorOption，缺省 None。高亮词用它
font_familyOption<String>。⚠️ 要写真族名不是库内 id —— libass 传 id 会静默落 ArialMT
font_weight⚠️ 实测 400/700 逐字节相同（底座不消费；本仓已把它从"能救糊团"的假设里划掉）
line_height0.0 = 用内置（1.2 em）
fade_in_ms / fade_out_ms0 = 硬出现/硬消失
rise_in_px / rise_out_px进场/退场的纵向位移（像素）
⚠️ font_weight 那一行不是"没做完"，是实测结论： 它与 outline 一起试过，400 与 700 的渲染结果字节相同 —— outline 才是唯一那个开关。
