这套在解决什么

  • 用户真正的问题是「哪个任务用哪支」，而接口/密钥是几个月才碰一次的资源 —— 首屏据此排。
  • 「继承」被显式画出来：灰字 = 跟随，深色 = 覆盖，不再靠脑补优先级。
  • 一个动作只改一处：点行 → 改这一条链路，不会顺手动到全局。

代价 / 什么时候别用

  • 只有一支接口的人，首屏那五张卡全是同一个答案 —— 信息密度大于需求（见方案 B）。
  • 「哪支模型被几条链路引用」看不出来（见方案 C 的引用列）。
  • 接口级故障（密钥失效）不在首屏，只在「已覆盖」chip 的颜色上泄露。
