建议的落地顺序（不是四选一）

  1. B 当默认首屏 —— 只有一份接口时，「模型配置」子页直接是三行 + 测试；高级里才是分配。
  2. A 当"链路配置"子页 —— 现在的链路表已经是这个语义，只是把表格行换成"任务卡 + 继承线"，改的是排版不是数据。
  3. D 的横幅塞进两个子页顶部 —— 只在"有接口不通"时出现，一条横幅 + 一键切换，不新开视角。
  4. C 先不做主视图 —— 它的引用计数可以先长在「模型池」列表里（"被 2 条任务使用"），等模型数真的过 10 再考虑矩阵。

四套都必须守住的硬约束

  • 编辑对象 ≠ 生效对象：左栏点一行只切 editingId，改 active 只有显式按钮。
  • 停手 1.2s 自动保存，但自动路径不重读（否则输入框被换掉、焦点丢失）。
  • 「额外参数」JSON 不合法时拒绝落盘，保存条常驻红字。
  • 草稿可测：填了 key 没保存也能测，不然"先存再试"永远绕不开。
  • 链路模型候选按本行生效接口过滤，选了别家的当场标黄。
  • 行内文案 ≤20 字，细节进 title（右栏内容宽只有 266px）。
这些页是什么：纯静态参考稿（假数据、无构建、不参与门禁）。用来对着讨论"先动手的是哪一块"， 不是可直接替换 SettingsView.vue 的实现 —— 真落地要走 webui/src 的组件纪律与 npm --prefix webui run build。快捷键：T 切主题（点右上角也行）。
