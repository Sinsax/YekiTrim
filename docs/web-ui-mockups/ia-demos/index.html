YekiTrim WebUI 框架对比

同一套流水线（转写 → 事件检测 → 切片 → 精修 → 渲染导出），四种根本不同的交互逻辑

均为自包含静态 Demo（假数据）· 配色沿用 sakura-cream · 点击卡片进入体验
方案 A

流水线步骤条 · 线性引导

项目页顶部常驻可点击步骤条 + 右下角「下一步」按钮。任务跑完自动跳下一步，随时知道走到哪。

方案 B

侧边栏工作台 · 空间常驻

IDE 式常驻侧栏：项目 × 阶段树永远可见，单击任意节点一击直达，没有「返回」概念。多项目横跳最快。

方案 C

看板 + 抽屉 · 状态即导航

列 = 阶段，卡片按状态落位，一眼纵览全部项目的生产进度；动作在右侧抽屉完成，完成后卡片流动到下一列。

方案 D

单屏聚焦 · 向导式

一次只呈现"现在该做的一件事"，大卡片 + 单主按钮，任务完成自动滑入下一屏。零迷失，自由度也最低。

导航方式顶部步骤条 + 下一步按钮常驻侧栏树状态列 + 卡片抽屉单卡推进 + 底部圆点
流程引导感强（显式推进）弱（自己找下一步）中（位置即状态）最强（零迷失）
任意跳转 / 自由度中最强（一击直达）中（经抽屉）弱（线性锁死）
多项目总览弱（回总览）强（侧栏常驻）最强（一眼全局）弱（单项目）
学习成本低中低极低
适合场景单项目从头做到尾，兼顾新手多项目并行、高频操作的老手项目多、管理型 / 批处理纯新手、或"无人值守"节奏
体验建议 每个 demo 都能走通「进入项目 → 切换阶段 → 切片/精修工作区」：A 里点项目卡进当前步骤、点右下角「下一步」推进；B 里展开侧栏项目、随便点节点横跳；C 里点卡片开抽屉、点「一键全切」看卡片流到下一列；D 里从头点主按钮走完全程。对比后告诉我倾向哪种（或哪几种的组合），我再出对应正式重构计划。
