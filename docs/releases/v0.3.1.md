## 这一版在治什么

**一个病：同一份资产有两个可能的位置。**

v0.3.0 把**字体库**固定在用户目录 `%USERPROFILE%\.yekitrim\fonts`，理由是想躲开
"换个构建目录资产就全没了"。代价是那个东西从**一个位置**变成了**两个**（用户目录 + 程序目录回落），
于是必然有地方只查了一处。实测踩到两次，两次都是"界面看不出异常"的那种：

1. **字体库两份**：CLI 解析到 `target/debug/resources/fonts`，WebUI 解析到 `~/.yekitrim/fonts`
   —— 两边列出的字体**完全不同**；
2. **模型两份**：界面按 `<exe>/.yekitrim/models` 判"未下载"，而 qwen3-asr 实际躺在 `~/.yekitrim/models`
   —— 显示未下载、转写却一直在用它。

本版把资产**全部收回程序目录**，位置只剩一个，这类 bug 从根上没有发生的条件。
外加修掉一处**同源但方向相反的**同类问题（`webui/dist`，见 §3）。

> 口径（用户拍板）：**所有内容围绕程序目录来，不要用户目录。**

## 1. 资产全部收回程序目录（§核心）

新增 `path::data_dir()` 作为**程序资产的唯一根**：

```
data_dir()  =  $YEKITRIM_DATA_DIR  ??  exe_dir()
yekitrim_home() =  data_dir()/.yekitrim
```

| 资产 | v0.3.0 | **v0.3.1** |
|---|---|---|
| 配置 / 账本 / 日志 | 程序目录 | 程序目录（不变） |
| **ASR 模型** | `~/.yekitrim/models` | `<数据目录>/.yekitrim/models` |
| **字体库** | `~/.yekitrim/fonts` | `<数据目录>/resources/fonts` |
| 贴纸库 | 程序目录 | 程序目录（不变） |

三处解析同时改掉（它们原本是**同一个设计的三个副本**）：`path::font_dir`、
`asr::resolve_model_dir`（删掉 `ModelDirSource::UserHome` 那一档）、
`fonts::ensure_dir`（删掉"老库一次性复制 + `.migrated-from-program-dir` 记号"，
现在只做 `create_dir_all`）。

**`YEKITRIM_DATA_DIR` 是唯一的口子**，留着它解决一个具体问题：`target/debug` 与 `target/release`
各是一份程序目录，**1.19 GB 的模型会被复制两份**。想共用就指到同一处：

```powershell
set YEKITRIM_DATA_DIR=F:\yekitrim-data
```

## 2. 旧用户目录：**只报不删**

升级后 `~/.yekitrim/` **不再被读取**。老机器上可能还留着 `fonts/` / `models/` / `config.toml`，
启动时会**如实报出**：

```
WARN init_config 发现旧字体库 C:\Users\你\.yekitrim\fonts（2 支 / 20.0 MB）
     —— 它已不再被使用，可以按需删除；字体请放到 <程序目录>\resources\fonts 里
```

⚠️ **程序不会替你删、也不会替你搬**：那是你的磁盘，里面可能有你手工放进去的字体。
确认没问题后自己删：

```powershell
Remove-Item -Recurse -Force "$env:USERPROFILE\.yekitrim"
```

## 3. `webui/dist` 候选次序改正

**问题**：候选第一条是 `CARGO_MANIFEST_DIR/../..` —— 一个**编译期烧死的绝对路径**，
永远指向**构建时那台机器的源码树**。于是「exe 同级」那条**永远轮不到**。

**后果同样隐蔽**：把 exe 拷到别处、或从别的 cwd 起服务，它照旧端出开发机源码树里的界面，
**一切看起来都正常**。这是 §核心 那个病的镜像 —— 那次是"资产挂到了程序目录外"，
这次是"程序内容挂到了程序目录外"。

**改法**：照 `find_translator` 的既有形状，由 `current_exe()` 派生的候选排前面：

```
exe同级 → exe上两级 → CARGO_MANIFEST_DIR/../.. → cwd
```

**三条测试钉住次序**（`web.rs` 原来没有测试模块）。判据刻意落在**次序**上而不是"能不能找到"
—— 后者在本机恒为真，钉不住这个 bug。

## 4. 顺带修掉

- **「自带」判据改成动态的**：`builtin = meta.builtin && id 仍在 BUILTIN_FONTS 清单里`。
  只看 `FONT.toml` 的 `builtin=true` 会让**换下来的旧自带字体永远删不掉**
  （v0.3.0 把中文那支从霞鹜文楷换成 Noto Sans SC，旧目录带着过期的 `builtin=true` 留在了盘上）；
- **xtask 烟测注释**修正（它还在描述一条已经删掉的回落链）；
- 新增 `docs/file-layout.md` 把目录形状写成契约。

## 5. 删掉「全局当前工程」（发布前的代码清理）

同一个病在**代码里**还留着一处：`AppState` 存了一份 `workspace` / `workspace_root`（"全局当前工程"）——
**单工程时代**的遗留。P2 起归属由 DB 的 `projects` 表决定，每个请求经 `scope::Scope` 按
`?project=<id>` **现解析**出自己那份 `Workspace`，全局那份于是成了一条**没人查的旁路**，
只会跟着"上次打开的工程"漂。

删它之前全仓普查过，只剩两个消费者，且都站不住：

1. **`/api/media/<绝对路径>`（过渡期契约）** —— 它靠全局工程把相对路径解析成绝对路径，
   再用 `find_project_for_dir` **反查**归属。那是**第二套归属判据**（与 `find_owned_project` 并存）。
   而且前端早就明确不认这条路：`utils.js::mediaUrl` 的注释写着"不接受绝对路径，也不做旧契约的兼容"。
   **现在媒体路径必须带项目 id**，归属只看一处。
2. **`/api/project/list` 回显的 `workspace_root`** —— 那个接口自己就标着 deprecated。

顺带拆开一件本来就该分开的事：`/api/config` 与 `/api/project-data/config` 曾共用一份实现，
于是项目相关字段（`config_file` / `root_dir` / `yekitrim_raw` / `config`）被挂在**项目无关**的接口上。
现在前者是**纯程序配置**（`config.toml` / `llm.toml`），后者才是"这个工程"。

### 顺带修掉一个真事故隐患

启动流程以前**无条件**把"当前工程"写进 `server.toml` 的 `projects[]`。在 `~` 下启动（不带工程）时，
那是个**从不存在的路径**；而另一条迁移逻辑会把 `projects[]` 里"文件还在、DB 没行"的路径
**重新登记成 admin 的项目** —— 哪天那个路径真出现了，它会自己变成一个项目。
本版起 `server.toml` **只留记忆**（`last_config_file`，供启动恢复上次工程），不再留状态。

日志里那两行误导（`Workspace: C:\Users\para\yekitrim.toml` / `Workspace root: C:\Users`）随之消失。

## 升级与备份

- **从 v0.3.0 升级**：替换 `yekitrim.exe` 与 `webui/` 即可（`dhampir/` 没有变化）。
- ⚠️ **字体要自己搬一次**：如果你在 v0.3.0 里导入过自备字体，它们还在
  `%USERPROFILE%\.yekitrim\fonts`，**新版不会读**。把它拷进程序目录的 `resources/fonts/`
  （或在 WebUI 设置页重新导入）。自带的两支（Noto Sans SC / Noto Color Emoji）内嵌在 exe 里，
  首次启动自动落盘，**不需要任何动作**。
- ⚠️ **模型重新下一次最省事**：`yekitrim download` 会把它们装到新版读的位置
  （`<程序目录>\.yekitrim\models`），装完就能用。
  想省掉那 1.16 GB 流量的话，也可以把 `~/.yekitrim/models` 整个目录挪过去 —— **等价**，
  怎么方便怎么来。（旧位置新版不会读。）
- **备份**：拷贝 `<程序目录>\.yekitrim/`（`config.toml` / `llm.toml` / `server.toml` / `yekitrim.db` /
  `cloud/logs/` / 模型）与 `resources/fonts/`、`stickers/`，以及各工程的 `yekitrim.toml` / `output/`。
  **该目录含 LLM key 与明文邀请码，不要公开或打进任何分享包。**
