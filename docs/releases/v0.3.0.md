## 本版主题

**这一版是「渲染链路换底座」的一版**：V-Trim 原来自己带一套 Chrome/wgpu 渲染，
本版把它整条删掉，出片与预览**只剩 Dhampir 底座**一条路。同时落下**自带字体**、
**封面切 Takumi**、**动图贴纸原生解码**。

1. **出片与预览只剩底座**（§1）—— 删掉 Chrome 链路与 Rust 逐帧接缝；
2. **自带字体，开箱即用**（§2）—— Noto Sans SC + Noto Color Emoji 内嵌进 exe，首次启动自动落盘；
3. **封面改 Takumi**（§3）—— 封面与出片共用同一套字体与排版；
4. **动图贴纸原生解码**（§4）—— 贴纸的 GIF 交给底座解，预览进页面不再卡 6 秒；
5. **预览提速与计时修正**（§5）—— wasm 压缩 + ETag/304，动图走 ETag 不再重收；
6. **多用户与安全面收紧**（§6）—— 初始密码文件随改密处置、贴纸路径收口；
7. **门禁扩容**（§7）—— 新增 9 个 `scripts/check-*.mjs`。

## 1. 出片与预览只剩底座

**删掉的东西**（`f9d7a50`、`2e2c056`）：

- `polish/src/render/native/` 的 wgpu 逐帧接缝（`FrameRenderer` / `create_backend` / `render_chunk_sync` / `context.rs`）；
- headless Chrome 出片链路，以及 `/api/health` 的 `wgpu_render`、`POST /api/polish/render-frame`；
- `vtrim-wasm` 与 `webui/src/wasm/` 两份 wasm-bindgen 生成物。

**为什么删**：同一条渲染逻辑在**三个宿主**里各有一份（native / wasm / Chrome），
行为对不上时"哪一份说了算"永远说不清。现在**只有底座一份**，本仓只负责
「把精修工程转译成底座工程」+「音轨」。

> **画面归底座、音轨仍归本仓** —— 这个分工是刻意的，别把音频并回去。

## 2. 自带字体，开箱即用

- 内嵌 **Noto Sans SC**（正文）与 **Noto Color Emoji (CBDT)**（彩色 emoji），
  经 `include_bytes!` 进二进制，**首次启动自动落盘**到字体库（`e441063`、`3581d7a`）；
- 两支都是 **SIL OFL-1.1**，正文明确允许 bundled/embedded，许可原文一并内嵌、随字体落盘；
- 字体库**正式位置是用户固定目录** `%USERPROFILE%\.vtrim\fonts`（v2 布局：一支一个目录 + `FONT.toml`）；
- 前端新增 **FontLibrary 组件**（字体管理从独立页面并入组件层），支持拖拽上传与「设为默认」；
- 常用命令：

```bash
vtrim fonts list        # 看看库里有什么
vtrim fonts install     # 万一被删了，重新装回来（幂等）
```

> 其余字体请自行获取并遵守其许可（见 README「字体」）。

## 3. 封面改 Takumi

- 封面默认通道从浏览器渲染切到 **Takumi**（`cf6915f`），与出片共用同一套字体与排版；
- 封面**背景层与帧层分开取图**：缺图的后果不同（背景层缺 = 模糊底没出来；
  帧层缺 = 封面主体没了），所以兜底与提示也分开（`CoverDesigner.vue`）；
- 高亮词新增**只作用于高亮那一段的字号**（前端 ⇄ 出片同源 `--hl-fs`）；
- **封面参照帧被冻结**，门禁改为可脱离 Chrome 运行（`d9fddab`、`check-cover-takumi.mjs`）。

## 4. 动图贴纸原生解码

- 贴纸的 **GIF / 动画 WebP 整段交给底座解码**（host_api v6），预览期**零请求**；
- 之前是**逐帧**请求（`235e2bc`：冷解码一张 GIF 要 6.5~8.8 秒，而且每帧都发一次）；
- 出片不再白解 26 秒贴纸帧，预览改为**加载时预热**（`df7ab42`）；
- 帧延迟表以**解码器为准**（工程 JSON 里那份退为诊断），不一致时**必须报警**而不是静默漂
  （`ec9e983`；症状是"贴纸越播越偏"，最难归因的那种）。

## 5. 预览提速与计时修正

三个改动叠起来，进精修页的等待明显变短：

1. **wasm 路由加 gzip + ETag/304**：`dhampir_wasm_bg.wasm` 7.66 MB → 1.49 MB（19%），
   命中 ETag 时**一个字节都不传**（`d9fddab` 之后那批）；
2. **`/api/media/*` 加 ETag/304**：精修页进 Dhampir 会把工程引用的**全部动图**整份取一遍
   —— 实测 5 张贴纸合计 **15.72 MB**，而这条路此前**没有任何校验符**，每次进页面都重收。
   现在第二次进页面**一字节都不重传**（有用例断言 `total == 0`）；
3. **修正宿主侧的计时区间**：原来 `tFetched` 打在 `fetch` **之前**，
   于是"取字节"量的只是字符串拼接（恒为 0ms），而 `fetch` + `arrayBuffer` 被算进了"解码"
   —— "解码很慢"这个结论**是被错计时喂出来的**。现在三段（取字节 / 解码 / 上传）分开。

> ⚠️ **不能对带 `Range` 的请求开压缩**：压缩后字节与"原始文件的第 start..end 字节"不再
> 一一对应，会直接破坏视频播放。所以媒体路由**只加校验符、不加压缩**。

## 6. 多用户与安全面收紧

- **初始密码文件必须随改密处置掉**（`5d455c8`）—— 否则它会对用户撒谎；
- 贴纸路径收口进 scope 中间件；字体库固定到用户目录（`f38eb4e`）；
- 修掉一批前端事故：拖拽改事件后不跑后处理（`e777e40`）、底座预览被自己的版本断言挡掉
  （`a69228c`，断言问错了对象）、预览音效"无声"误导文案（`b08fdaf`）。

## 7. 门禁扩容

新增（`scripts/`）：`check-cover-takumi`、`check-dhampir-drop-list`、`check-dhampir-wiring`、
`check-effect-registry`、`check-font-inputs`、`check-preview-audio`、`check-preview-engine`、
`check-timeline-done`、`check-vtrim-translator`。

其中 `check-preview-audio` 有 **13 处变异自证**（把判据改坏，看它是否真的红）；
`check-dhampir-wiring` 是 **89 项**的跨仓接线判据。

## 前置条件

- **出片与预览都要底座**：`dhampir/` 已在包内，**不需要额外安装**；
- 需要 **WebGPU** 的浏览器看预览（Chrome/Edge 113+ 默认可用）；
- 其余同 v0.2.x：Windows x64、Python 3.10+（仅开发时）、首次跑 ASR 会下载模型。

## 快速开始

```bash
# 图形界面（本机使用）—— 默认 127.0.0.1:26320，浏览器自动打开
vtrim server

# 命令行全流程
vtrim process <录像>            # 音频 → 转写 → 事件 → 切片
vtrim polish preview <项目>     # 打开精修预览
vtrim polish export <项目>      # 出片（走包内底座）

# 多用户 / 采集 / 运维
vtrim user add <名字>           # 加账号
vtrim doctor                    # 环境自检
```

## 已知限制（请按此边界使用）

1. **只监听 `127.0.0.1`**：对外必须显式加 `--allow-remote`，且仍用初始密码时**拒绝启动**。
   服务本身没有 TLS，公网部署请走反代 + HTTPS，并加 `--trust-proxy`。
2. **仅中文**：ASR、LLM prompt、事件类型与摘要均为中文场景。
3. **`wgpu_render` 字段已从 `/api/health` 移除**（本仓不再自带 GPU 管线）；
   出片只剩底座。
4. **P5 未做**：容量/运维增强仍在 ROADMAP。
5. **上传入口只有两处**（贴纸 zip、封面背景图），服务器文件来源永不接受上传。
6. **任务队列是内存态**：排队与运行中的任务在服务重启后不会恢复（工程产物不受影响）。
7. **底座需要 WebGPU**：没有可用适配器的环境下预览会明确报错，不会静默降级。
8. **精修页的计时探针**会在控制台打十几行 `[dhampir]`（排查用）；不影响功能。

## 升级与备份

- **从 v0.2.1 升级**：替换 `vtrim.exe`、`webui/` **以及整个 `dhampir/` 目录**
  （本版新增，缺了它出片与预览都不可用）；
  `<exe同级>/.vtrim/`（配置、模型、贴纸、字体库、账本）保留。
- **字体**：**不需要任何动作** —— 自带字体内嵌在 exe 里，首次启动自动装进字体库。
  你原先自己放的字体不受影响（用户目录优先）。
- **出片结果的变化**：渲染从 Chrome/wgpu 换成底座，**同一份工程出来的像素可能不同**
  （抗锯齿、字体栅格化、采样细节）。如果对某条片子的观感有强要求，建议**重跑一次后对比**。
- **封面**：默认通道改为 Takumi；已有封面的 `polish.toml` 配置不需要迁移。
- **备份**：拷贝 `<数据目录>/.vtrim/`（`config.toml` / `llm.toml` / `server.toml` / `vtrim.db` /
  `logs/` / 模型 / 贴纸 / 字体）与各工程的 `vtrim.toml`、`output/`。
  **该目录含 LLM key 与明文邀请码，不要公开或打进任何分享包。**
