## 本版主题

1. **多用户服务（P1–P3 全部落地）** —— 账号、邀请码、项目隔离、录播姬自动入库；
2. **工程结构** —— `vtrim-service` / `vtrim-server` 两个新 crate，`api/` 按领域拆分，版本单一来源；
3. **许可与构建链** —— Apache-2.0，sherpa-onnx 换 TTS-off 预编译库，构建期强制产物门禁；
4. **WebUI v5 工作台** —— 侧栏项目树、首页新增项目、三段式项目路由、切片卡片墙、精修编辑器；
5. **质量与稳定性** —— 检测传播潜力评分、片段目录名稳定化、任务三档闸门、同步 IO 全部搬离 async 线程。

## 1. 多用户服务（P1–P3 已落地）

单机多账号部署（≤10 人），**单人/多人共用同一套认证**：没有免登录分支，loopback 也要登录。

- **账号与鉴权**：首次启动生成 `admin` + 随机初始密码（日志打印一次并写入
  `<data_dir>/initial-admin-password.txt`，首次登录成功后自动删除）；会话在 SQLite `sessions` 表，
  `vtrim_sid` 为 HttpOnly cookie（7 天滑动续期），写请求需带 `X-CSRF-Token`（双提交）；
  登录失败 5 次/15 分钟按「用户名 + 对端 IP」锁定；仍用初始密码时除改密/登出外一律 403。
- **邀请码自助注册**：`vtrim user invite [--note 给谁] [--days N] [--count N] [--disable]` /
  `vtrim user invites` / `vtrim user invite-revoke`，设置页「注册与邀请码」卡同样可生成、
  查看明文、复制与撤销；一个码只能绑一个账号（原子消费），注册即登录且永远只得到 `user` 角色。
- **项目托管与隔离**：归属由账本 `projects` 表决定，`/api/projects` 只回本人项目；
  所有项目级接口用 `?project=<id>`，polish 用 `{project, dir}`；`/api/media/<project_id>/<项目内相对路径>`；
  `vtrim-core/src/tenant.rs` 是唯一路径拼接入口（拒绝绝对路径 / UNC / `C:foo` / `..` / 符号链接逃逸）。
  「移除项目」**只注销登记、零文件改动**；「删除源录播」是唯一的手动释放空间手段。
- **录播姬（采集）**：`vtrim ingest token` 生成 webhook token（明文只显示一次，库内只存 scrypt 哈希）
  后即可在录播姬里填 `http://<host>:26320/api/ingest/bililive/<token>`；收到 `SessionEnded`
  或空闲窗口后由入库 worker 落位（同盘 rename / 跨盘 copy+校验+删源）、多分片 `ffmpeg -f concat -c copy`
  合并、弹幕一并搬入、建项目并按 `auto_pipeline` 自动跑管线。兜底扫描覆盖漏推送与历史录播，
  未映射房间进「待分配池」由管理员指派。首页可登记直播间并直接导入单条录像。
- **运维**：`vtrim doctor` 输出安全与运行状况摘要（账号/初始密码/锁/磁盘/服务探测）；
  `vtrim usage [--days N]` 与设置页「LLM 用量」卡按天/链路/项目/模型聚合 token、缓存命中与耗时。

## 2. 工程结构

- `crates/vtrim-service`（CLI 与 WebUI 共用的领域逻辑）与 `crates/vtrim-server`（axum API + WebUI
  宿主 + 任务队列）从原 `vtrim-cli` 中拆出；`vtrim-server/src/api/` 按领域分成
  `auth`/`invite`/`logs`/`rooms`/`config`/`projects`/`project_data`/`pipeline`/`render`/`polish`/`core`。
- 依赖方向是**单向**的：`vtrim-service` 不引用 `vtrim-server`，`vtrim-server` 不引用 `vtrim-cli`。
- 版本改为 `[workspace.package] version` + `version.workspace = true` 单一来源：
  `/api/health` 的版本、`vtrim doctor` 的版本与发行包名（`vtrim-v<版本>-win-x64`）不再可能分叉。
- `cargo xtask scan|package` 取代全部 PowerShell 脚本：`scan` 扫描已链接产物里的
  espeak-ng 标记（GPL 门禁，不可跳过），`package` = 构建 → 门禁 → 组装 → zip。

## 3. 许可与构建链

- 项目协议由 `GPL-3.0-or-later` 切换为 **Apache-2.0**（README「许可」一节记录取舍）。
  依据：改用 [TTS-off 预编译归档](plan/sherpa-onnx-no-tts-switch-guide.md) 后 espeak-ng
  退出二进制，依赖审计确认随二进制分发的包内无 GPL/LGPL/AGPL；
  `v0.1.0` 从未对外分发，因此不产生历史义务。
- `vendor/sherpa-onnx-sys` 是构建图里唯一的上游 fork（只改 `build.rs`）：钉死归档名与 sha256、
  校验失败即删、缓存命中时也断言占位库仍是占位库、非 Windows-x64-static 目标直接失败。
- 发行包**强制**附带 `LICENSE` 与 `THIRD-PARTY-NOTICES.md`（缺任一个打包直接失败）。

## 4. WebUI v5 工作台

- **壳**：常驻左侧栏（品牌 / 项目过滤 / 项目树〔名称 + 来源徽标 + 进度徽标 + 可展开的
  预处理·切片·精修节点 + 占用〕/ 底部首页·设置 / 用户 chip），可向左折叠成 64px 图标轨；
  面包屑 + 内容区；任务抽屉、Toast/Dialog 挂在壳上。登录页不套壳。
- **首页**：按来源新增项目 —— 服务器文件（仅管理员，内嵌目录浏览器）、录播姬录制
  （非管理员只看到「配置直播间」）、B 站链接（未实现，如实标注）；下方是「表情包」库
  （仅管理员：上传 zip / 生成 tags / 卡片墙预览）与「录制导入（最近）」。
- **路由**：`#/workbench`、`#/p/:pid/{prepare,slices,polish,polish/:clip,settings}`、`#/ingest`、
  `#/settings`（仅管理员）、`#/login`、`#/register`；旧路径 `/project/:cfg/**`、`/polish`、`/jobs`、
  `/models`、`/projects` 全部 redirect。换项目会让视图整块重挂（`:key = pid`）。
- **预处理页**：播放器 + 滚动式字幕轨道（像素刻度、缩放 0.5~120 px/s、拖动平移 / 拖缘改起止 /
  双击删除）+ 常驻「字幕属性」横排条 + 右侧「预处理 / 切片」两张卡；弹幕与字幕文件可随时切换
  （候选由服务端扫描项目目录，管理员可浏览任意目录），改完需重新检测才生效。
- **切片页**：已剪切片段与未剪切事件**同一面卡片墙**混排，按热度（数值）排序、四档筛选；
  未剪切事件可区间预览（播放头锁在入点/出点、带标记的进度条、滚轮缩放视窗、叠加原片字幕）、
  编辑、单条剪切；`一键全切（N）`；卡片可删除（连带精修产物，二次确认）。
- **精修页**：片段小卡条 + 预览（可选区域框选：人物 / 弹幕区域）+ 生成与导出
  （LLM 剪辑参数 + 贴纸来源 + 渲染导出）+ 时间轴编辑器（7 条泳道、响度包络线、字幕/屏蔽/事件编辑、
  「去静音」与「撤销去静音」）+ 封面设计器（文字 / 关键帧 / 背景三层、4:3 与 16:9 安全区、
  首次自动排版塞进 4:3 区）+ 产物栏。所有保存类操作即时落盘并自动跑后处理（`process` 幂等）。
- **设置页**：全局配置表单/源码双模式、LLM 测试、模型管理、LLM 用量、注册与邀请码、
  录播姬采集、运行日志（实时 SSE + 级别过滤）、项目设置（含删除源录播 / 移除项目）。

## 5. 核心管线

- **ASR 断句重做**：SenseVoice 出时间轴（逐字）、qwen3-asr 出文本（hybrid，默认模式）；
  标点与强停顿（`segment_gap`）决定切几条，气口（`breath_gap`）决定切在哪一刻，
  字数（`max_segment_chars`）只做硬上限；中间产物落 `output/asr/`（原始 token / 时间轴 / 切点来源）。
  `qwen3-asr` 单次解码输出上限固定为 `max_new_tokens = 256`。
- **弹幕热度**：ASS / SRT / 录播姬 XML 三种弹幕统一解析；`danmaku_file` 相对工程目录解析
  （历史 bug：相对进程 CWD 导致弹幕永远读不到，热度静默退化成纯字幕密度）。
- **事件检测**：分批窗口 LLM 调用（30 段/窗、重叠 5 段）+ checkpoint 断点续传 + 单窗失败拆半重试；
  基础热度 = 弹幕峰值/均值 + 字幕密度，再叠加 **LLM 传播潜力评分**
  （`detection.llm_score_weight`，默认 0.3，只喂标题 + 摘要，0 = 关闭）；
  后处理：边界吸附 ASR 段 → 合并 → 最短 30s → 重名标题加序号，**不做最长时长等分**。
- **切片命名稳定化（本版新增）**：`events.json` 里新增 `clip_dir`，检测时优先复用已有片段的目录
  （保住精修产物），否则用标题 slug 生成唯一名；目录名不再等于 rank，`clips/index.json` 是目录索引，
  可从磁盘重建；「不覆盖别人的片段」判据改为按 `clip_dir` + 标题/区间 IoU。
- **LLM 客户端**：统一 `LlmClient`（core 与 polish 共用），并发由 `[llm] max_concurrent`（默认 3）
  一处控制；`send` 内统一记账（`llm_usage` 表：token / 缓存命中 / 耗时 / 尝试次数），
  失败只 warn 不影响调用结果。

## 6. 精修引擎

- **时间模型 = 开始 + 结束**（事件不再有 `duration`，老 `polish.toml` 反序列化前自动换算）。
- **时间轴编辑器**：分段 / 事件 / 字幕 / 屏蔽四类块统一「体拖移动 / 左缘改开始 / 右缘改结束 /
  双击删除」；自动保存（700ms 防抖）+ 操作完成后重跑后处理 + 实时预览；误删可撤销 15 秒。
- **贴纸**：本地贴纸库（上传 zip / 服务器目录导入 / LLM 批量生成 tags）、落点按
  人物 / 字幕带 / 弹幕带反选安全区后**在安全区中心**撒点；手工放的事件不会被后处理改写或抽稀。
- **运镜**：聚焦 / 位移 / 画中画 / 硬切；倍率只有一张表；画中画一个切片只有一条、
  自动对齐字幕与分段边界、到点自动回镜头（幂等）。
- **音效与特效**：小森平音效库（两级分类 + 候选注入）、瞬时特效、覆盖层色档契约
  （单色一律「该色 → 同色零透明」淡出，canvas 与 CSS 预览一致；
  `node webui/scripts/check-overlay.mjs` 对拍 `templates/index.html` 与 `engine.js`）。
- **封面**：文字 / 关键帧 / 背景三层各自独立（背景支持纯色、关键帧模糊、导入图片），
  设计器与出片共用同一套公式（字体栈、描边、阴影、图层序、特效公式）；
  导出产物同名不覆盖（`_1` / `_2`），界面显示磁盘上的实际文件名。
- **字体库**：`<程序目录>/resources/fonts/` 放开 `.ttf`/`.otf`/`.ttc` 即出现在
  字幕字体与封面字体下拉；库内字体经 `/vt-fonts/:name` 与 `@font-face` 注入预览与出片。
- **出片**：`chrome-render` 为默认路径（headless Chrome + ffmpeg）；GSAP 从 jsDelivr 加载失败时
  按序回退 unpkg / cdnjs；`data/*.json` 直接注入页面（不再 fetch，避免网络盘上出片假死）；
  全局 GPU 编码探测（NVENC / QSV / AMF，缺失回退 libx264）。

## 7. 稳定性与可观测性

- **任务队列**：资源域互斥（`p{pid}:out` / `:idx` / `:clip:<目录>` / `models` / `stickers` / `dir:`）
  + 三档闸门（轻活不限 / 略重 3 / 重活 2）+ 前后台优先级；资源冲突不再 409 而是排队；
  5 秒自愈 tick 与「谁挡住谁」的 warn 日志（`docs/job-queue.md`）。
- **同步 IO 不占 async 线程**：所有读项目目录的 handler 走 `spawn_blocking`，管线任务体走专用线程，
  外部进程（ffmpeg / Chrome）带超时；渲染子进程登记 pid、取消时杀进程树、启动时清扫孤儿、
  180 秒无进度报错退出。
- **可见性**：访问日志（每次交互一行，≥400 带错误文案，webhook token 已脱敏）+
  运行日志 LogBus（2000 条环形缓冲 + SSE + 落文件），设置页「运行日志」可级别过滤。
- **路径面**：body 路径字段白名单、项目配置路径键校验、封面图二次校验三道防线；
  `/api/fs/list` 仅管理员；全站按 IP 限流 + 登录/注册/任务创建各自额度。

## 8. 本版收尾批次

- 检测：LLM 传播潜力评分（见 §5）与配置项、设置页滑杆、`README`/`AGENTS`/设计稿同步。
- 切片：`clip_dir` 稳定目录名 + `clips/index.json`（见 §5）；
  服务端资源键与前端 `clipMatchesEvent` / `mediaUrl` 同步收敛。
- 精修/切片体验：未剪切事件区间预览（自写控件 + 播放范围标记 + 滚轮缩放 + 字幕叠加）、
  「独立」「序号被占用」chip、删除后静默刷新、产物实际文件名、贴纸来源 chip、预览音量落到 `<video>`。
- 渲染：`data/*.json` 注入 HTML、GSAP CDN 三级回退。
- 侧栏折叠轨项目标识取标题末尾相邻两个字（过滤数字与标点）。

## 前置条件

| 依赖 | 说明 |
|---|---|
| `ffmpeg` + `ffprobe` | **必需**，需在 `PATH` 中（音频提取、剪切、截图、静音检测、渲染） |
| Chrome / Edge | 精修**渲染**与**封面**需要（headless Chrome 出图）；`/api/health` 给出探测结果 |
| ASR 模型 | 首次转写时自动下载到 `~/.vtrim/models`（或 `<exe同级>/.vtrim/models`）；`vtrim download` 可预取 |
| 磁盘 | 源录播 GB 级；精修渲染产物最大（1080p60 约 3.6–5.4 GB/小时输出） |
| GPU 编码（可选） | NVENC / QSV / AMF 自动探测，缺失时回退 `libx264` |
| 网络 | 出片需能访问 GSAP 的 CDN 之一（jsDelivr / unpkg / cdnjs）；LLM 链路需要能访问所配的 OpenAI 兼容端点 |

## 快速开始

```powershell
# 图形界面（本机使用）—— 默认 127.0.0.1:26320，浏览器自动打开
vtrim.exe server --open
# 初始密码：启动日志打印一次，或看 <exe同级>/.vtrim/cloud/initial-admin-password.txt

# 命令行全流程
vtrim.exe init D:\records\stream.mp4 --danmaku D:\records\stream.ass
vtrim.exe process                # 提取音频 → 转写 → 事件检测 → 剪切
vtrim.exe status                 # 查看进度

# 精修（对某个切片）
vtrim.exe polish init output\clips\clip-01
vtrim.exe polish process output\clips\clip-01
vtrim.exe polish render  output\clips\clip-01

# 多用户 / 采集 / 运维
vtrim.exe user invite --note 给剪辑师 --days 7
vtrim.exe ingest token
vtrim.exe doctor
vtrim.exe usage --days 7
```

## 已知限制（请按此边界使用）

1. **默认只监听 `127.0.0.1`**：对外监听必须显式加 `--allow-remote`，且仍用初始密码时**拒绝启动**。
   服务本身**没有 TLS**，公网部署请走反代（Caddy/nginx）+ HTTPS，并加 `--trust-proxy`。
2. **仅中文**：ASR 语言、LLM prompt、事件类型与摘要均为中文场景（见 ROADMAP「多语言 ASR」）。
3. **wgpu 真渲染仍不在默认构建内**（该功能暂缓）：`/api/health` 的 `wgpu_render` 为 `false`，
   浏览器内真渲染按钮不显示；出片路径是 headless Chrome。
4. **已知既有编译错误**：`vtrim-polish/tests/text_*.rs` 与 `vtrim-render-core` 的 wgpu test 模块
   在**工作区级 `cargo check --all-targets`** 下仍会报错（引用只在 `wgpu` feature 下的模块，
   与运行无关）；按包检查 `cargo check -p vtrim-cli --all-targets` 为 0 warning。
5. **P4 / P5 未做**：B 站链接转项目（次要通道）与容量/运维增强仍在 ROADMAP；
   界面里的 B 站来源如实标注为不可用。
6. **上传入口只有两处**（贴纸 zip、封面背景图），服务器文件来源永不接受上传。
7. **任务队列是内存态**：排队与运行中的任务在服务重启后不会恢复（工程产物不受影响）。
8. 出片依赖 headless Chrome 与至少一个可访问的 GSAP CDN。
