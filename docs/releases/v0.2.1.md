## 本版主题

1. **片头渐入事件化**：内建 `intro-black` 整条退役，改由 overlay 的 `fade_in` / `fade_out` 承担 ——
   时长、颜色、不透明度都可在时间轴上改，也能删（删掉后重跑 `process` 不会再补回来，§1）；
2. **竖素材横屏出片修复**：画面不再被拉成宽屏、衬底不再是黑边，竖素材禁用运镜在**出片路径**同样生效（§2）；
3. **崩溃与安全面收紧**：去掉 `panic="abort"`、改密门覆盖 admin 路由、消除 HTTP 可达的 panic（§3）；
4. **取消与 IO 纪律**：批量 LLM 链路补齐取消探针（并加上成对判据门禁）、高频路径的同步 IO 搬出 async worker（§4）；
5. **P4 B站链接通道**：粘贴链接 → 解析分P → 下载 → 自动建项目，下载器是独立端口与适配层（§5）；
6. **WebUI 批次**：切片筛选口径、作用域收口、精修页文案预算与状态栏常驻（§6）；
7. **工程结构**：35 张模块卡 + 两道结构门禁，server/service 内部按领域模块化（§7）。

## 1. 片头渐入：从内建表现改成 overlay 事件

原内建片头黑场（`intro-black`，固定 0.5s 正弦淡出）**整条退役** —— 它硬编码在四条路径上、
没有任何手动入口，而用户的诉求是「能改时长、能删」。替代物是 overlay 事件里的两个新档：

```toml
type = "overlay"; time = 0.0; end = 0.5
overlay_type = "fade_in"    # "color" | "gradient" | "fade_in" | "fade_out"
color = "#000000"           # 缺省黑；fade 两档用
opacity = 1.0               # 遮罩色的最大不透明度
```

- **语义**：`fade_in` = 起点全遮 → 末端全透（`opacity × (1 − dt/dur)`），`fade_out` 镜像。
  「整窗就是过渡本身」，**不叠**常规覆盖层那 0.4s 进出包络（求值顺序上排在包络之前）；
  窗口之外照常是正常画面 —— 想让画面**停在**黑场就把末端拖到片子结束。
- **复用 overlay 通道**：没有新字段、不进 `default_end` 兜底，`color` / `opacity` 的解释与纯色档同源。
- **`process` 只在初次后处理自动补片头**（Step 3c，排在音效规则之后 —— 否则这条纯视觉事件每次都会被音效规则扫一遍）：
  给**时间最早**且起点 < 0.5s 的段补一条 `fade_in`（`#000000` / `opacity 1` / 0.5s 或到段末）。
  两条前提：该段跨度 ≥ 0.2s；**整片**没有任何覆盖事件与这 0.5s 窗口重叠。补出来的是**普通事件**：
  补种时机**用掉一次就落盘** —— `polish.toml` 记 `intro_fade_seeded = true`（片头窗口判定过就算用掉，
  包括已被覆盖事件盖着的情况），**删掉之后不再补**；想拿回默认片头就删掉那一行再跑。
  片头还不存在时（空段表 / 最早段起点 ≥ 0.5s / 段跨度 < 0.2s）不记，下次 `process` 仍会补。
- **旧工程零迁移**：`intro_fade_seeded = false` 不写入文件，所以 v0.2.0 的 `polish.toml` 原样可读、
  跑一次 `process` 就补上片头；反过来见到有这条也只是「已经补过」。
- **编辑器**：覆盖类型下拉新增「淡入（黑场）」「淡出（黑场）」，切到这两档时面板只留颜色
  （整块时长 = 渐变时长，拖右缘改）。
- **三处求值面同步**：出片模板 `templates/index.html`、预览 `webui/src/polish/engine.js`、
  原生 `vtrim-render-core/src/timeline.rs`（含 wgpu uniform/shader 里的旧字段清零）；
  对拍脚本 `webui/scripts/check-overlay.mjs` 扩到 **77 项**（含「模板/预览/出片都不再有 `intro-black`」
  三条否定判据）。`docs/polish-events-reference.md` 与 6 张纪律卡同步。
- **LLM prompt** 加一句约束：fade 两档只用于片头片尾，片头那份系统只在初次后处理时自动补、不要重复写。

**实测**（沙箱二进制真出片，1920×1080 / h264+aac，逐帧亮度 YAVG 与公式逐点吻合）：
片头 `fade_in` 0.02s=5.40 / 0.10s=16.92 / 0.25s=45.44 / 0.40s=69.07，基准段 0.7–7.0s = 88.0–88.8；
片尾手注 `fade_out` 7.55s=76.61 / 7.75s=39.77 / 7.95s=5.40。

## 2. 竖素材横屏出片修复（2026-09-21 用户报告）

现象：竖屏素材在横屏导出时**被拉伸成宽屏**，而不是「竖屏素材 + 模糊关键帧衬底」；
且竖素材的运镜门控在预览里生效、在成片里不生效。两个成因都在**出片 canvas 路径**：

- 视频层被硬铺满整块画布（`drawImage` 的 dst 直接写画布尺寸），`stageDrawRect` 推导出的
  `axis/position/scale/padding` 只有 DOM 预览在消费；
- `getActiveCamera` 的竖素材门控只存在于 DOM 预览分支，canvas 逐帧路径照旧套运镜。

修法：canvas 路径按 `stageDrawRect` 的摆放矩形 + CTM 变换画视频层（衬底仍先于视频层绘制、
内容框之外是同一帧的模糊衬底而不是黑边），竖素材门控进 canvas 路径。

这类事故不报错、不崩溃（「改好了 DOM 预览」看起来照样正常），所以证据必须是像素级：
新增忽略型探针 `crates/vtrim-polish/tests/portrait_stage_fit.rs`（自造竖屏探针素材 +
**A/B 三段变异**：硬铺满 / 去掉竖屏运镜门 / 不画衬底，每段都断言"翻面"，只断言真模板等于
不知道探针是不是空转）；`webui/scripts/check-stage-backdrop.mjs` 加几何断言；
`project/config.rs` 固定出片模板的三个消费面（`function stageDrawRect` / CTM `translate+scale` /
竖素材门控），顺序钉子写明「摆放矩形要在衬底之后、视频层之前算」。

## 3. 崩溃与安全面收紧

- **去掉 `panic = "abort"`**：server 是单进程，渲染/转写/入库/下载都在同一进程里，
  abort 会把「一个人的一次 panic」放大成「所有人的任务一起死」；改成 unwind 后它退回成
  **一次任务失败**（`api::spawn_job` 的 `catch_unwind` 兜底这才真正生效）。
  同时逐点消除生产代码里可触发的 panic —— 例如切片页的 `latest_numbered_file`
  在 `cover_.jpg` 上算出 `&name[6..5]`（start > end）会直接 panic、HTTP 可达；
  单帧预览的槽锁中毒（一次 panic 之后每次预览都 panic）。
- **改密门覆盖 admin 路由**：admin 是另一条路由树，原先只挂 `require_admin` ——
  持初始密码的会话可以直接读 `GET /api/config` 拿到明文 LLM API key、并调
  `/api/admin/invites` 铸造邀请码。新层必须写在 `require_admin` **之内**（axum 后加的 layer 在外层），
  回归钉子把 `must_change_password` 用例扩到 admin 路由的 7 条 URI。
- 初始密码判据与 ingest 路径键的修正各带回归钉子。

## 4. 取消探针与同步 IO 纪律

- **批量 LLM 调用的取消探针补齐 5 条链路**：热度评分、字幕订正、精修事件生成、
  贴纸精挑、贴纸打标 —— 一律 `llm::Agent::with_cancel(probe)`，在**派发每批之前**与
  **每收一批之后**各查一次，命中即 `abort_all` + 报「任务已取消」。此前只在阶段边界查过，
  用户点了停止后台仍会把十几个窗口跑完（实测 18 窗、十几分钟）。
  评分路径的探针刻意上提到 `process_with_llm` 之前与窗口路径共用一份，避免
  「检测阶段停得下来、评分停不下来」；探针检查放在建客户端之前，顺手成为一条不需要网络的单测。
- **新的成对判据门禁**：`scripts/check_module_boundaries.py` 增加 `PAIRED_RULES` ——
  「命中 `Agent::new(` 的文件必须同时出现 `with_cancel(`」（文件级，刻意做粗，目的是别漏掉新的批量循环）。
- **高频路径的同步 IO 搬出 async worker**：`scope::enforce_scope`（挂在 `/api/polish/*` 整个子树的
  每请求中间件）、配置类 GET、项目目录解析等走 blocking 池。只搬调用、不重排判据 ——
  这是安全守卫本体，行为逐字等价，由既有越权用例（404/400）兜底。

## 5. P4：B站链接通道与下载器

`vtrim-service` 源码按领域拆成 `bilibili/` / `downloader/` / `ingest/`（`capacity` L 与 `landing`）/
`net/` 四个模块并各带卡，边界按门禁隔离（`net` 不许知道 B站、`downloader` 不许开子进程也
不许知道 B站）：

- **B站链接 → 项目**：首页粘贴链接 → 解析预览（标题 / 时长 / 分P）→ 勾分P → 下载 → 自动建项目，
  **每个 P 一个会话、一个项目**。弹幕 XML 的响应体是**裸 deflate**（`wbits = -15`，非 zlib 包装），
  必须手工解压 —— 这条写在模块卡里。
- **下载器是端口 + 适配器**：yt-dlp 适配器的注册表**钉 sha256**，下载后校验；新增
  `vtrim-server/src/download_worker.rs` 作为唯一的子进程 spawn 处（下载槽 + 无输出超时 kill + 僵尸回收）。
- **设置页新增下载器配置卡**：存放位置（与录播姬入库、本机导入共用同一个根）、并发
  （**建议保持 1**：B站的 412 风控与 IP 频次相关）、B站 cookie 文件。

## 6. WebUI 批次

- **切片页二级筛选改口径**：`未精修 / 已精修` → **`精修中 / 已导出`**。原因不是文案：
  剪切收尾会给每个已剪片段都建好 `polish.toml`，所以旧判据 `polish_ready` 对已剪片段**恒为真**
  —— 「未精修」永远空、「已精修」等于全部。新判据 = `rendered || cover`（出过片或出过封面），
  与卡片上那枚 chip 同一套。旧 localStorage 值一并迁移。
- **作用域收口**：`scopeQ` 只在 `webui/src/api/` 里拼（`projectData.paths` 是原始路径的唯一出处），
  越界的三处（`router.js` / `ProjectSettingsView` / `PolishView`）全部改走 api 层；
  门禁判据从匹配不到的 `[?&]pid=` 改成 `[?&]pid=|\bscopeQ\(|\bscopeQuery\(`，并把 `router.js` 纳入路径表。
- **端口只有一份定义**：dev 代理改读 `VTRIM_PORT || 26320`，注释写明它是 Rust 侧
  `doctor::DEFAULT_PORT` 的镜像。
- **精修页文案预算**：「行内 ≤ 20 字、硬上限 40」成了卡里的规矩（细节挪 `title` 悬停显示；
  右栏卡片行内容宽只有 266px）。「改落点」并入「人物 / 弹幕 / 贴纸」同一行（四颗按钮必须同行，
  加第五颗就会折成 3+1）；**任务状态栏常驻**（空闲态 = 「任务」+ chip `空闲`），
  同一件事不再说三遍（任务名 + 状态 chip + 进度条已说清），但**失败原因仍然必须显示**。
- **任务日志不再打印产物长路径**（成功只报「成片已写出」/「封面已写出」）：写出的路径是
  `\\?\E:\media\…\vtuber-clip_1.mp4` 这种 verbatim 长路径，塞进单行高的任务框只会撑满，
  实际文件名在精修页「产物」区与切片卡片上都能看到。
- **进精修页不再白等**：剪切收尾顺带预热每个新片段的整段响度曲线（`<片段>/data/loudness.json`），
  只补缺失、命中缓存一个字节都不动；`measure_loudness_curve` 补 `-vn`（此前不带它，
  ffmpeg 会把整段视频也解码一遍再丢掉 —— 同一片段实测 **5.6s → 0.4s**，曲线 1330 个采样点全等）。
- **前端批次**：新增组件 `SliderField` / `HomeClipsOverview` / `DownloaderConfig` / `prepare/MaterialList`；
  `api/jobs`（SSE + 轮询 + 资源键）、`polish`、`projectData`、`ingest` 收口；
  契约脚本从 1 个扩到 6 个（`check-caption-wrap` / `check-cover-stage` / `check-handheld` /
  `check-stage-backdrop` / `check-sticker-anchor` + `check-overlay`）。
  `webui/dist` 与 `src` **同提交重建**（dist 是服务端唯一界面来源，陈旧时是静默 200 + 旧界面）。

## 7. 工程结构与卫生

- **35 张模块卡**（`**/AGENTS.md`）+ `docs/module-map.json` 模块注册表 + 两道结构门禁：
  `scripts/check_module_map.py`（索引一致 / 覆盖率 / 预算）与 `scripts/check_module_boundaries.py`
  （15 条规则：分层方向、P4 隔离、前端边界、成对判据）。根卡有 20 KB 硬预算 ——
  模块级内容不许再往根文件里塞。
- **server 内部模块化**：`download_worker` / `pipeline_boot` / `tool_probe`；
  路由表与中间件层序保持既有语义（`require_user` 在外层、`require_password_changed` 在内层，顺序不能反）。
- **静默失败收口**：`ingest_session_add_file` 的 JSON 解析失败不再「当成空列表写回去」
  （那会让这一列里本来记着的其它路径永久消失）；迁移前备份失败、初始密码文件写失败不再 `let _ =`。
- **`llm_debug` 转储治理**：不再回退进程 CWD（那是「仓库根堆 70+ 个 log」的来源）、
  保留最新 50 份、单份上限 256 KB。
- **换行策略**：新增 `.gitattributes`（`* text=auto eol=lf` + 常见二进制标记），
  源码统一 LF 存储 + LF 检出。
- 清理：仓库根 74 个 `vtrim_llm_debug_*.log`（3.16 MB）与 `crates/vtrim-wasm/target`（1.27 GB）。
- **版本单一来源**：`[workspace.package] version` + `version.workspace = true`；
  本版把版本固定为 **0.2.1**，四处传播点实测一致（`vtrim --version` / `vtrim doctor` /
  `vtrim polish doctor` / `/api/health` 的 `version`）。

## 前置条件

| 依赖 | 说明 |
|---|---|
| `ffmpeg` + `ffprobe` | **必需**，需在 `PATH` 中（音频提取、剪切、截图、静音检测、渲染） |
| Chrome / Edge | 精修**渲染**与**封面**需要（headless Chrome 出图）；`/api/health` 给出探测结果 |
| ASR 模型 | 首次转写时自动下载到 `~/.vtrim/models`（或 `<exe同级>/.vtrim/models`）；`vtrim download` 可预取 |
| 磁盘 | 源录播 GB 级；精修渲染产物最大（1080p60 约 3.6–5.4 GB/小时输出） |
| GPU 编码（可选） | NVENC / QSV / AMF 自动探测，缺失时回退 `libx264` |
| 网络 | 出片需能访问 GSAP 的 CDN 之一（jsDelivr / unpkg / cdnjs）；LLM 链路需要能访问所配的 OpenAI 兼容端点 |
| B站下载（可选） | 需要 `yt-dlp`（设置页可配路径 / cookie 文件）；未配置时只用录播姬与本机导入 |

## 快速开始

```powershell
# 图形界面（本机使用）—— 默认 127.0.0.1:26320，浏览器自动打开
vtrim.exe server --open

# 命令行全流程
vtrim.exe init D:\records\stream.mp4 --danmaku D:\records\stream.ass
vtrim.exe process                # 提取音频 → 转写 → 事件检测 → 剪切
vtrim.exe status                 # 查看进度

# 精修（对某个切片）
vtrim.exe polish init output\clips\clip-01
vtrim.exe polish process output\clips\clip-01
vtrim.exe polish render  output\clips\clip-01

# 多用户 / 采集 / 运维
vtrim.exe user invite --note 给剪辑师 --days 7
vtrim.exe ingest token
vtrim.exe doctor
vtrim.exe usage --days 7
```

## 已知限制（请按此边界使用）

1. **默认只监听 `127.0.0.1`**：对外监听必须显式加 `--allow-remote`，且仍用初始密码时**拒绝启动**。
   服务本身**没有 TLS**，公网部署请走反代（Caddy/nginx）+ HTTPS，并加 `--trust-proxy`。
2. **仅中文**：ASR 语言、LLM prompt、事件类型与摘要均为中文场景（见 ROADMAP「多语言 ASR」）。
3. **wgpu 真渲染仍不在默认构建内**（该功能暂缓）：`/api/health` 的 `wgpu_render` 为 `false`，
   浏览器内真渲染按钮不显示；出片路径是 headless Chrome。
4. **P5 未做**：容量/运维增强仍在 ROADMAP。B站链接通道（P4）**已落地**（§5）。
5. **上传入口只有两处**（贴纸 zip、封面背景图），服务器文件来源永不接受上传。
6. **任务队列是内存态**：排队与运行中的任务在服务重启后不会恢复（工程产物不受影响）。
7. 出片依赖 headless Chrome 与至少一个可访问的 GSAP CDN。
8. **片头淡入是「默认观感」而不是用户意图**：`process` **只在初次后处理**补一条 `fade_in` 并记
   `intro_fade_seeded`，删掉之后**不再补** —— 想拿回默认片头就删掉 `polish.toml` 里那一行再跑（§1）。

## 升级与备份

- **从 v0.2.0 升级**：替换 `vtrim.exe` 与 `webui/` 即可；`<exe同级>/.vtrim/`（配置、模型、贴纸、
  字体库、账本）保留。
- **片头观感的变化**：原来那 0.5s 内建黑场不再存在，改由 `process` **只在初次后处理**给首段补 `fade_in`
  事件；**老工程跑一次 `process` 就会补上**，之后在时间轴上删掉就不会被补回来（也可以自己加/改）。
  `intro-black` 从来不是 `polish.toml` 的字段；新增的 `intro_fade_seeded` 同样不是必填项 ——
  文件里没有它就按「还没补过」处理，**没有需要迁移的配置**。
- **导出产物**：同名不覆盖（`_1` / `_2`），实际文件名以精修页「产物」区显示为准。
- **备份**：拷贝 `<数据目录>/.vtrim/`（`config.toml` / `llm.toml` / `server.toml` / `vtrim.db` /
  `logs/` / 模型 / 贴纸）与各工程的 `vtrim.toml`、`output/`。**该目录含 LLM key 与明文邀请码，
  不要公开或打进任何分享包。**
