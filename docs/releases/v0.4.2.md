## ⚠️ 最重要的一处变更：目录布局统一为**多用户**

**只有一种布局了：多用户。** 「单人模式」这个概念被删掉了 —— 托盘 / `--local-no-auth` / CLI
里的「本机」身份**就是当前管理员**，与管理员账号登录后**逐字节相同**，都落在

```
<数据目录>/users/<uid>/{.yekitrim,resources}/
```

**顶层不再有 `resources/`**（就是以前那个"单人的素材库"）。

### 升级时会发生什么

启动时**自动**把单人时期的存量**移动**到**第一个管理员**名下（幂等，只做一次）：

```
<数据>/resources/*              →  <数据>/users/<管理员>/resources/
<数据>/.yekitrim/config.toml    →  <数据>/users/<管理员>/.yekitrim/
<数据>/.yekitrim/llm.toml       →  <数据>/users/<管理员>/.yekitrim/
```

日志会写一行「已把单人时期的 N 项存量归入首个管理员名下」。

⚠️ **是 `rename` 不是复制**：素材可能几个 GB。跨盘失败会**如实报错并保持原状**，
不会"尽力而为"地复制一半。**升级前建议先备份 `resources/` 与 `.yekitrim/*.toml`。**

### 新增 `global/`：公用素材库

```
<数据>/global/resources/{fonts,stickers,videos}/    ← 公用素材，所有账号共享
```

- **读**两层：**用户库优先、全局补缺**（自己库里有就用自己那份，能覆盖公用的同名素材）；
- **写**只有一处：**自己的库**。⚠️ 不是"往第一个存在的目录写"—— 那会让公用素材变成"谁先写谁占用"；
- 程序自带的 2 支字体（Noto Sans SC / Noto Color Emoji）**装在 `global/`**，不再是每个账号各落一份；
- `global/` **只管素材、不装配置**（配置是账号无关的，在顶层 `<数据>/.yekitrim/`）。

### 还会看到

- **账号配额**：管理员可给单个账号设配额（`users.quota_bytes`，0 = 跟随全局默认）；
  以前这个值只在建号时能设、且恒为 0，等于形同虚设 —— 现在有接口和界面。
- 界面上的**素材库路径**会分别显示"用户库 / 公用库"两个位置。

## ⚠️ 另一处变更：出片底座升到 **Dhampir 0.2.0**，**字幕像素会变**

本版随包携带的出片底座从 **0.1.0 换成 0.2.0**。这是**唯一**一处会让人对着两版成片看出差别的地方，
所以单独放在最前面。

### 变了什么

底座的**字幕栅格化器从 ffmpeg 的 `drawtext` 换成了 libass**。其它一切照旧：
工程格式、宿主接口、调色、运镜、特效、贴纸、弹幕、音轨链路**都没有动**。

### 你会看到什么

| | 现象 |
|---|---|
| **字幕** | 字形、字距、行高、描边/阴影的渲染会有**肉眼可见的区别**（同一句话在成片里的像素不一样） |
| 其它画面元素 | **不变** |
| 音轨 | **不变** |
| 工程文件 | **完全兼容**，不用改任何东西 |

> 换句话说：**这不是 YekiTrim 变差了，是字幕换了渲染器。** 老工程直接拿来出片即可，
> 只是字幕长得和上一版不完全一样。介意的话对着看一遍，绝大多数情况下是"更规整了"。

### 为什么没有别的提示

底座这一版**一个版本契约号都没有动** —— `project_schema` 还是 1、`host_api` 还是 6。
两个数字都合法，所以**没有任何自动信号**会告诉你"字幕像素变了"。
这是刻意的（契约保证的是"能读、能跑"，不是"逐像素不变"），但意味着**升级风险不会自己冒出来**，
只能写在发行说明里。底座侧的完整说明见 Dhampir 仓 `docs/upgrade-0.1.0-to-0.2.0.md`。

## 同批修掉的一个真缺陷：字体名对不上时**静默换字体**（已修）

底座 0.2.0 的 libass **按「字体族名」找字体**，而 YekiTrim 的 `polish.toml` 里存的是**字体库 id**。
两者**真的会不一样**：

| | 值 |
|---|---|
| 字体库 id（存在 `polish.toml`） | `GenJyuuGothic-Bold` |
| 真正的族名（libass 要的） | `Gen Jyuu Gothic Bold` |

对不上时 libass **不报错** —— 它会**静默退回 `ArialMT`**，而转译报告里依然写着
`lines_failed: 0`、`issues: []`。也就是说：**成片里字幕用了错的字体，而所有检查都是绿的。**

- 现在出片前会把「库 id → 真族名」的映射交给转译器（Rust 侧 `write_font_families`，
  经 `--font-families` 传给 `tools/polish-to-dhampir.mjs`）。
- **库外的值原样返回** —— 老工程里 `font = "LXGW WenKai"`（系统字体族名、不在字体库里）
  行为**一个字都不改**，仍然走系统字体栈。
- 判据：转译器守卫里新增 **9 项**检查钉住这条契约，并加了 **2 处变异自证**
  （"库 id 不再解析成真族名" / "库外的值也被改写" 都必须打红）。
  `--mutate` 现为 **42 处变异全部打红**。

> ⚠️ 这条**只有 0.2.0 底座才需要**：0.1.0 的 `drawtext` 不吃族名。若你把底座换回 0.1.0，
> 这个修复不产生作用，也不会出错。

## 同批修掉的另一个真缺陷：打包时可能**静默装进旧底座**（已修）

`cargo xtask package` 从 `../Dhampir/dist/` 挑底座产物时，原先**只按文件修改时间取最新那一份**。
而 `dist/` 会**同时留着好几个版本**（现在就有 `dhampir-0.1.0+edf0f3c` 与 `dhampir-0.2.0+60197a2`）。

后果：在旧版本目录里随便碰一下文件、或重跑一次旧版本的打包脚本，
`dist/` 里"最新"的就成了 **0.1.0** —— 于是**0.1.0 被静默装进这一版的发行包**。

这在 0.2.0 之前不致命（相邻版本差别小），但**现在致命**：装错的包出来的是**另一套字幕像素**，
而且按上面那节说的，**没有任何自动信号会报出来**。

- 现在按**版本号**挑（`dhampir_version_key`，逐段数值比较，所以 `0.10.0 > 0.9.0`），
  认不出版本的目录排最后；唯一的兜底是"再退回 `out/`"，**永远不退回 mtime**。
- 钉子：`older_version_wins_never_even_when_touched_later` —— 把实现换回 mtime 排序、
  或换回按目录名排序，**两条变异都打红**。

## 其余内容（自 v0.4.1 以来的 94 个提交）

以精修链路与字体一致性为主，逐条详见各模块卡：

- **字体**：`cmd_init` 改读「库里设为默认」那一支（此前"每次切出切片，字体都不是字体库设置的默认字体"）；
  弹幕跟随字幕字体栈；补齐三处一致性判据。
- **精修预览**：出声契约（Dhampir 默认开启后预览曾完全没声音）、预览引擎运行期守卫。
- **出片**：`doctor` 增显 ffmpeg / 底座产品版本 / 版本契约三行；就绪位新增 libass 探测
  （按 `ffmpeg -filters` 里**有没有 `subtitles` 滤镜**判定，**不**去 grep 构建配置字符串）。
- **封面**：Takumi 通道的字体注册与标题合成加粗收口。
- **贴纸包构建**（本次会话）：构建跑在 **server 进程里**，却用"单人固定位置"去找包 ——
  实际包在 `users/<uid>/` 下，于是永远报「包不存在」。这是上面「布局统一」那一节的连带面：
  **凡是进程内调用、不是子进程的，`YEKITRIM_OWNER` 环境变量一点用都没有**（它只传给子进程），
  必须显式按当前账号取路径。同类的还有 `load_llm_config`（读过已被搬走的顶层 `llm.toml`
  ⇒ 即使配了 key 也永远说"未配置"）、CLI 的 `fonts list` / `stickers list`。已全部按账号取。
- **素材库路径显示**（本次会话）：界面把字体/贴纸的目录都显示成视频库的路径（**只是显示错，
  写一直是写对的**）；现在三类各自按自己的库显示，并额外给出公用库路径。

## 打包

```bash
cargo xtask package --smoke-test                      # Windows zip
cargo xtask package --target linux --smoke-test       # Linux tar.gz
```

⚠️ 打包前确认 `../Dhampir/dist/` 里**最高版本是 0.2.0**（本版修了自动挑选，
但手工 `--dhampir-artifact` 指错目录仍然会装错，且只有对着 `dhampir/VERSION` 才看得出来）。
包内 `dhampir/VERSION` 应满足 `version=0.2.0`、`project_schema=1`、`host_api=6`。
