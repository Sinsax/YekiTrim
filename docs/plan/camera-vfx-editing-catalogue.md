## 0. 底座原语清单（**分析的地基**）

### 0.1 有的

| 族 | 原语 | 关键限制 |
|---|---|---|
| **变换 / 关键帧** | position(x,y)、scale、rotation、anchor/origin | 逐帧采样；插值取相邻键的 **b 值 + 缓动**（`curve.rs::channel_from`） |
| **相机** | zoom 三档 `中≈1.3` / `近≈1.5` / `远≈0.55`；focus origin（百分比坐标）；`from→to` 移动；`cut` 瞬跳；`handheld` 摇摆 | **只有三档**；`handheld` **仅近景**允许（`process::fx::cap_handheld_sway` 会剔除其余） |
| **ColorMask 族** | `overlay`（Solid/Linear/Radial + angle，最多 4 color stop）、`flash`（带色）、`vignette`、`hue`、`noise` | `overlay` 的 `angle` 底座是 `(cos,sin)`（0=向右），本仓是 CSS 约定（0=向上）⇒ 转译器换算 `base = css − 90` |
| **调整图层** | 高斯 `blur`（**≈16px 上限**）、`contrast`、`brightness`、`opacity`、`saturation` | **有素材的图层只执行 `SeparableBlur`** —— 色彩类挂在普通层上会被**整条丢掉**（现在是校验错误 `effect_would_be_ignored`）⇒ 必须挂调整层 |
| **Warp 族** | `shake`、`pulse`、`zoom_bounce`（缩放 ×1.10） | 走调整图层；**`zoom_bounce` 底座完整支持，本仓转译器发 0 次**（只出现在注释里） |
| **文字 / 字幕** | 逐行颜色、描边、阴影、字重、高亮 span（**静态**） | 缺 `stroke` / `highlight_color` / `entrance` 一等字段 |
| **图像序列** | 贴纸 / GIF（`loop_source`） | 见 `polish-translation.md` §5 |
| **音频** | gain / mix（本仓混音，不走底座） | `amix:normalize=0` **等权硬叠**；有 `afade=t=out`、**无 `afade=t=in`** |
| **时间轴** | 源帧号重映射、区间裁剪（`mute_ranges` / `cut_ranges`） | **重复区间 = 让某段被采样两次**，本仓已具备 |

### 0.2 **没有**的（本节决定了所有 C 层的划分）

空间遮罩/划像、位移贴图（displacement）、**各向异性（方向性）模糊**、
色差/RGB 分离、运动跟踪、人脸检测、**源片变速（speed ramp）**、
**源片转场（dissolve/xfade）**、invert/posterize。

> ⚠️ 注意最后两条的措辞：**"源片变速"与"转场"没有，但"整段快放"和"裁剪重复"有**
> —— 这是后面 §4 里几条判断的分水岭。

### 0.3 一条贯穿全文的几何事实：**底座是"整帧缩放"，不是"分区变换"**

`polish-translation.md` §7 实测：本仓的 `camera` 放大的是**整个图层**（整帧），
而 `Transform.scale=1.3` 一平移就**露出边界**（实测右侧露 **622px** 空带）。
转译器的处理是**夹住偏移**让画面始终铺满，代价是"聚焦"变弱，报 `CLAMP` 而非假装没差。

> 📌 **这条决定了下面几乎所有"pan / tilt / dolly / tracking"的判断**：
> **纯平移会露边** ⇒ 本底座能干净表达的只有「**缩放 + 聚焦原点**」这一族，
> 即 **zoom / reframe / push / pull**。**横向平移（pan/truck/tracking）必须以"缩放 + 原点移动"合成，且要被夹住。**

## 1. 运镜（Camera Moves）

> **分类依据**：日文维基 [`カメラワーク`](https://ja.wikipedia.org/wiki/%E3%82%AB%E3%83%A1%E3%83%A9%E3%83%AF%E3%83%BC%E3%82%AF)
> 给了学界口径的 7 分类（引用吉高淳夫 2006《カメラワークを利用した感性情報の抽出》，《情報処理学会論文誌》47(6):1696–1707）：
> **PAN / チルト / ドリー（トラック）/ クレーン / ズーム / フィックス**，
> 外加**跟（フォロー）**与**画面动・ブレ**（不按操作分类）。本文采用这个分类学骨架。

### 1.1 推 / 拉（Push In / Pull Out）—— ⭐ ⭐ ⭐ **本底座最擅长的**

| 项 | 内容 |
|---|---|
| **中文/英文/日文** | 推镜 Push In / Dolly In ｜ ドリーイン・トラックアップ（T.U.）<br>拉镜 Pull Out / Dolly Out ｜ ドリーアウト・トラックバック（T.B.） |
| **具体长相** | 摄影机沿光轴靠近/远离主体，主体在画面中**变大/变小**。 |
| **使用时机/情绪** | 推 = **强调、聚焦、情绪升温、揭示细节**；拉 = **展现环境、疏离、结束感、释怀**。 |
| **怎么表达** | ✅ **原生**。`camera` 的 `from→to`：起点 `中`、终点 `近`（或反之），`origin` 固定。转译器已有：`zoom` 档位 + `origin` + `anchor_to` → 底座 `Transform` 关键帧。<br>**过渡时长 0.6s**（`placement::TRANSITION_SECS`，模板口径 `td = min(duration*0.5, 0.6)`）。 |
| **自动化 + 触发** | ✅ **已自动化**。LLM 按段写 `zoom`（"情绪爆发/名场面推近景"）。<br>**可加的信号**：① 弹幕密度峰值（`danmaku::peak_density`）；② 字幕密度（`compute_transcript_density`）；③ `popularity` 高分时刻。 |

⚠️ **"推"实际上是"变焦"，不是"移动"** —— 见 §1.12。

#### 📌 关于「推近 = 情绪升温」的证据等级

**社区约定为主，但有方向一致的学术线索**：

- **社区/教学口径（强共识）**：A 层教程里反复出现"缓慢推近=情感亲密/审视，快速推近=紧张/威胁"
  （[运镜专业知识库](https://www.cnblogs.com/VisionGo/p/19831789) §十二"情绪-运镜映射表"给了完整对照）。
- **学术线索（较弱，需谨慎）**：该文 §27 引用了**近体反应（Looming Response）**
  —— 物体在视野中快速变大触发杏仁核的威胁检测。**这是视觉神经科学的既有概念**，
  但"**推镜速度决定情绪强度**"这个**具体推论是该文作者的归纳**，我没找到直接把"推镜速度"当自变量的实验。
  ⇒ **标记为「有理论支撑的行业约定」，不是「已被证实的定律」。**

### 1.2 摇 / 俯仰摇（Pan / Tilt）

| 项 | 内容 |
|---|---|
| **中文/英文/日文** | 摇（横摇）Pan ｜ パン（横PAN）<br>俯仰摇 Tilt ｜ チルト（縦PAN） |
| **具体长相** | **机位不动，机身转动**。横摇扫过水平空间，俯仰摇扫过垂直空间。<br>日文维基引坂井甚太 2022 的定义：**"(B) パン・チルト：カメラを水平方向または垂直方向に回転させる撮影技法…カメラの姿勢は変化するが位置は固定である"**。 |
| **术语陷阱** | **严格定义里 PAN 只指横摇**，但**动画业界大量把纵向也叫 PAN**（[アニメ制作メモ](https://w.atwiki.jp/aniken/pages/279.html) 明确写："正確にはPANは横の振りのみを指す言葉だが、最近は一概にPANと言ってしまう事が多い(アニメ界では特に)"）。 |
| **使用时机/情绪** | 跟随运动、揭示空间、建立环境；快摇=紧迫，慢摇=沉思。 |
| **怎么表达** | ⚠️ **只能近似**。底座没有"机位固定 + 转动"这个自由度 —— 它是**整帧 2D 变换**，不是 3D 相机。<br>**能做的**：`Transform.rotation` 关键帧 = **滚转**（那是 §1.11 荷兰角，不是 pan）。<br>**近似的办法**：把 pan 当成"**用一个更宽的景别 + 平移偏移**"—— 但 §0.3 说了**一平移就露边**，转译器会 `CLAMP`。⇒ **效果会退化成"跟随式 reframe"**。 |
| **自动化 + 触发** | ⚠️ 判据（"该摇向哪边"）**本仓完全没有** —— 需要**画面内容**的方向性（VTuber 站位、游戏画面运动），本仓只有 transcript + 弹幕。 |
| **层** | **C 层**（要"真 3D 相机"或至少"更大的源缓冲 + 平移不露边"）。<br>**降级方案**：用 `anchor`/`anchor_to` 在**两个聚焦点之间移动**——**这本质是 pan 的 2D 等价物**（见 §1.4 / §1.7）。 |

### 1.3 移 / 升降（Truck / Pedestal / Crane）

| 项 | 内容 |
|---|---|
| **中文/英文/日文** | 移（横移）Truck / Track ｜ ドリー（トラック）<br>升降 Pedestal Up/Down、Crane Up/Down ｜ クレーン |
| **具体长相** | 机位**平行于画面平面**平移（横移），或整体升高/降低（升降）。与 pan 的区别：**pan 是转，移是走**。 |
| **使用时机/情绪** | 横移=展现横向空间/关系；升=俯瞰、上帝视角、揭示全貌；降=压迫感、回到人物视角。 |
| **怎么表达** | ❌ **不能干净表达**。理由同 §1.2：整帧 2D 变换 + 平移露边。<br>转录器的 `cameraOffset` 公式（`polish-to-dhampir.mjs:2881`）本身就是"围绕不动点缩放"的产物，**不含自由平移**。 |
| **层** | **C 层**（同 §1.2）。 |

### 1.4 跟（Follow / Tracking Shot）—— ⭐ 可以**降级表达**

| 项 | 内容 |
|---|---|
| **中文/英文/日文** | 跟拍 Follow / Tracking ｜ フォロー（撮影技法）、付けPAN |
| **具体长相** | 摄影机跟随运动中主体，**主体在画面中的位置保持不变**，背景在动。 |
| **日文的细分**（[アニメ制作メモ](https://w.atwiki.jp/aniken/pages/279.html)） | **付けPAN / Follow PAN** —— 动画里用"大判背景 + スライド"或"足踏み作画 + 背景スライド"实现。<br>⚠️ 该页自己也说这是"アニメでしか使わない半ば意味不明な造語"。 |
| **使用时机/情绪** | 行走、追逐、情感流动；前跟=情感连接最强，背跟=代入/旅程感，侧跟=展现环境。 |
| **怎么表达** | ⚠️ **降级可做**：VTuber 直播里主播**通常原地不动**（坐姿），所以"跟"的实际观感 ≈ **保持主播在画面中的位置**。<br>⇒ 用 `camera` 的 **`anchor: "liver"` + `origin` 固定** 就能达到"锁定主播"的效果。<br>**但这不等于跟拍** —— 它没有背景的运动视差。 |
| **自动化 + 触发** | ✅ 触发信号有：**贴纸/字幕密度高的连续段**（"主播在连续讲"）。但**判"主播在动"需要画面** ⇒ 本仓给不出。 |
| **层** | **B 层**（降级版：锁定主播）/ **C 层**（真跟拍）。 |

### 1.5 急推变焦 / 甩镜（Snap Zoom / Crash Zoom · Whip Pan）

| 项 | 内容 |
|---|---|
| **中文/英文/日文** | 急推变焦 Snap Zoom / Crash Zoom ｜ 香港ズーム（[アニメ制作メモ](https://w.atwiki.jp/aniken/pages/279.html)）<br>甩镜 Whip Pan / Swish Pan ｜ **SWISHPAN**（同页）、**QUICKPAN（Q.PAN）** |
| **具体长相** | **Snap zoom**：从广角**瞬间**变到特写（无缓动的推）。<br>**Whip pan**：快速横摇，**中间帧严重运动模糊**，常用于**转场**。<br>日文页给了 QUICKPAN 与 SWISHPAN 的区分：**"Q.PAN 是单纯快；SWISHPAN 是快到画面ブレる（抖）"**，动画里用 `流背`（速度线背景）叠上去模拟。 |
| **使用时机/情绪** | 突然发现、震惊、强调；whip pan 用作**时空跳转**的转场。 |
| **怎么表达** | ✅ **Snap zoom 可以**！`camera` + **`cut: true`**：事件起点直接给到目标 `zoom` 与不动点，**不做 0.6s 缓动**。转译器已支持（`event.cut === true` → 底座 `cut`）。<br>⚠️ **但这是"瞬跳"不是"快速变焦"** —— 中间没有加速过程。<br>⚠️ **Whip pan 不行**：缺**方向性模糊**（§0.2）。用 `blur`（高斯）近似会**糊成一团而不是拉丝**。 |
| **自动化 + 触发** | ✅ **切点信号已经存在**（本仓的剪切点 = `cut_ranges` 的边界）。<br>⚠️ 但"**哪一次切该配 snap zoom**"需要判据 ⇒ 建议**只在 `cut:true` 与切点重合时**用。 |
| **层** | Snap zoom = **A 层**（`cut` 已经在，只是 LLM 不用）；Whip pan = **C 层**（缺方向模糊，见前文 C2）。 |

### 1.6 慢推 / Ken Burns（Slow Push · Ken Burns Effect）

| 项 | 内容 |
|---|---|
| **中文/英文** | 慢推 / 缓慢推镜 ｜ **Ken Burns effect**（[Wikipedia](https://en.wikipedia.org/wiki/Ken_Burns_effect)） |
| **具体长相** | 极缓慢的推近/平移，让**静止照片**产生生命感。 |
| **使用时机/情绪** | 沉思、怀旧、仪式感；**纪录片/图片叙事**的标准手法。 |
| **怎么表达** | ✅ **完全可做**。就是**长时长的 `camera` from→to**（0.6s 过渡 + 长时间驻留）。<br>⚠️ **但要注意**：本仓的 `camera` 是**状态机**（"跟到下一条运镜"），不是"一次性动画" —— 见 `polish-translation.md` §2 的教训：**每条事件画两个端点画不出状态机**。 |
| **自动化 + 触发** | ✅ **本仓已有最好的判据**：**"任何 >6s 无事件的区间自动插一个最低强度的推近"**（前文 §4 的"节奏约束求解器"）。<br>文献支持：**每 3–6 秒一次视觉变化**（前文引 [Zella](https://zellahq.com/blog/cut-cadence-how-often-should-you-cut/)）。 |
| **层** | **A 层**（能力已有，缺的是"自动补"的守卫）。 |

### 1.7 重构画面（Reframe）

| 项 | 内容 |
|---|---|
| **中文/英文** | 重构画面 / 二次构图 ｜ Reframe / Recrop |
| **具体长相** | 不改变景别，只**改变画面里主体的位置**（把偏左的人挪到画面中央/三分位）。 |
| **使用时机/情绪** | 修正构图；把注意力从画面边缘拉回主体。**短视频竖屏裁剪**的核心手法。 |
| **怎么表达** | ✅ **原生**。就是 `origin`（聚焦中心）的改变，**zoom 不变**。<br>`anchor: "liver"` → `anchor_to: "danmaku"` → 再回 `liver`，**都是 reframe**，本仓 LLM 提示词里已经教了这套（`llm/segment.rs`："主播→弹幕→回主播 = 两条事件"）。 |
| **自动化 + 触发** | ✅ **已自动化**。信号：`anchor` 的语义目标（主播/弹幕/贴纸/中央）。 |
| **层** | **A 层**。 |

> 📌 **Reframe 是这个底座上第二值钱的能力**（第一是 push/pull）。
> 因为 **pan / tilt / truck / tracking 在 2D 里全都退化成 reframe** ——
> 也就是说，**本底座用 `origin` 一个自由度，覆盖了电影语法里 4 个运镜术语的"观感意图"**，
> 代价是**没有真实的视差与背景运动**。

### 1.9 环绕 / 视差（Arc / Orbit · Parallax）

| 项 | 内容 |
|---|---|
| **中文/英文** | 环绕跟 Orbit / Arc Shot ｜ 视差移动 Parallax Shot |
| **具体长相** | 环绕：摄影机**绕主体旋转**，主体居中、**背景旋转**。<br>视差：前景快速掠过、中景恒定、远景缓动 —— **三层空间差异化运动**。 |
| **使用时机/情绪** | 环绕 = 英雄时刻、高潮、觉醒；视差 = 立体感、穿越感、梦境。 |

| **层** | **C 层**，且**优先级低**（成本高、切片语境收益小）。 |

### 1.10 移焦 / 焦点拉动（Rack Focus · Focus Pull）—— ⭐ **能用 blur 伪造**

| 项 | 内容 |
|---|---|
| **中文/英文** | 移焦 / 焦点转移 Rack Focus · Pull Focus ｜ 焦点锁定 Focus Lock ｜ 跟焦 Follow Focus |
| **具体长相** | 焦点从 A 主体滑到 B 主体：**A 从清晰变糊，B 从糊变清晰**。视线被引导。 |
| **怎么表达** | ⚠️ **只能伪造**，而且**是不对称的伪造**。<br>底座的 `blur` 是**整帧高斯**（挂调整层，作用它下面的一切）。<br>⇒ **能做的**："全部变糊 → 恢复清晰" = **失焦感**（转译器已有：`blur` 只在瞬间失焦/眩晕/被击中/闪回用）。<br>⇒ **不能做的**："**只有背景糊、前景清晰**" —— 这需要**空间遮罩**（§0.2 没有）。 |
| **使用时机/情绪** | 引导注意力、切换关注对象、迷茫/眩晕。 |
| **自动化 + 触发** | ⚠️ **本仓完全没有判据**：要判"画面里有两个主体、该换焦点了" = **需要人脸/主体检测**。<br>⇒ **建议不做**。 |
| **层** | **降级近似 = B 层**（"全糊→清"）；**真移焦 = C 层**（缺空间遮罩 + 缺主体检测）。 |

> 📌 **诚实结论**：**"用 blur 表达移焦"这个想法方向对，但结果不是移焦。**
> 移焦的信息量在**"谁清谁糊"的对比**里；整帧模糊**把这个对比抹掉了**，
> 只剩下"失焦"这一个语义。**这两件事在观感上差得很远**，不该混为一谈。

### 1.11 荷兰角 / 滚转（Dutch Angle · Roll / Canted Frame）—— ⭐ **原生**

| 项 | 内容 |
|---|---|
| **中文/英文** | 荷兰角 / 斜角构图 Dutch Angle · Canted Frame ｜ ロール（Roll / Barrel Roll） |

### 1.12 ⭐ **变焦 vs 移动：透视差异**（**决定本底座的天花板**）

| 维度 | 变焦（Zoom） | 移动（Dolly / Truck） |
|---|---|---|
| **光学本质** | 改变**焦距**（画角） | 改变**机位** |
| **透视** | ❌ **不改变** —— 只是把**整张图放大**，近处与远处物体的**相对大小不变** | ✅ **改变** —— 近处物体放大得更多，**背景相对变小** |
| **权威表述** | [Wikipedia: Zooming (filmmaking)](https://en.wikipedia.org/wiki/Zooming_(filmmaking))：**"unlike changes in camera position, zooming does not change the perspective (the relative sizes of near and far objects); it only magnifies or reduces the size of the entire image as a whole."** | —— |
| **画面观感** | "压缩"、扁平 | 有"走进去"的空间感 |

**这条为什么关键**：底座的所有运镜**本质都是变焦**（`Transform.scale` + 原点）。
⇒ **本底座永远做不出"移动"的透视感**。这不是实现问题，是**数学上不可能** ——
因为**源素材里只有一张已经拍好的图，没有第二视角**。

#### 希区柯克变焦（Dolly Zoom / Vertigo Effect）—— **确定做不了**

- **定义**（[Wikipedia: Dolly zoom](https://en.wikipedia.org/wiki/Dolly_zoom)）：
  **同时**变焦与移动机位，使主体尺寸不变而背景尺寸剧烈变化。
  **"the subject maintains the same size in the frame while the background appears to stretch or compress."**
- **区别**：**推镜（dolly-in）改变透视，变焦不改变** —— 所以 dolly zoom 的**全部信息量就在这个"透视变化"上**。
- **怎么表达**：❌ **做不到**。要让背景"涨/缩"必须**重新渲染 3D 空间或换视角**。
  底座只有 2D 变换。⇒ **C 层，且我认为不该提需求**（成本极高、切片语境用不上）。
- **诚实的替代**：本仓能做的"眩晕"近似 = **`camera` push + `rotation` 倾斜 + `blur`**，
  但**它不会让背景涨缩**，只是"糊 + 歪"。**这是不同的东西，别命名为 dolly zoom。**

## 2. 镜头语言 / 语法（Shot Grammar）

> ⚠️ **本节先给一个诚实的总体判断**：
> **镜头语法绝大部分是"多条镜头之间的关系"，而本仓的产物是"一条连续切片"。**
> 因此**大多数语法条目在单切片语境下要么自动成立、要么无意义**。
> 下面逐条说清**哪一条是真的能做的**。

### 2.1 30 度规则（30-Degree Rule）

| 项 | 内容 |
|---|---|
| **定义**（[Wikipedia: Jump cut](https://en.wikipedia.org/wiki/Jump_cut)） | **"the camera position must vary at least 30 degrees from its previous position"**，否则观众会读成跳切。 |
| **它管什么** | **两个连续镜头之间**的机位角度差。 |
| **本仓能不能用** | ⚠️ **不适用**。理由：**本仓不产出"两个镜头"** —— 切片是**一段连续录像**，镜头是**源素材里已经定好的**。<br>本仓的硬切（`cut:true`）是**在同一段素材内部瞬跳构图**，它**不是"两个不同机位的镜头"**。 |
| **但有一条真用处** | ⭐ **作为一个"合法性判据"**：**如果 `cut:true` 前后两个构图太接近（原点几乎没动、zoom 档位相同），观众会读成"跳切/失误"** —— 这正是 30 度规则要防的。<br>⇒ **建议做成守卫**：`cut` 事件要求 `origin` 位移 ≥ 某个阈值，或 `zoom` 档位必须变化。 |
| **层** | **B 层**（守卫，不是新效果）。 |

### 2.2 动作剪辑（Cutting on Action · Match on Action）

| 项 | 内容 |
|---|---|
| **定义**（[Wikipedia: Continuity editing](https://en.wikipedia.org/wiki/Continuity_editing)） | **"some action occurring before the temporally questionable cut is picked up where the cut left it by the shot immediately following"** —— 在**动作进行中**剪，掩盖剪接点。 |
| **为什么有效** | 因为**运动的连续性**盖过了"镜头变了"这件事。 |
| **本仓能不能用** | ⚠️ **需要"动作"** —— 本仓只有 transcript + 弹幕，**没有画面运动检测**。<br>**但是**：本仓的剪切点**已经在动作/语音中间**了（`cut_ranges` 按去静音切）。 |
| **可用的近似判据** | ⭐ **"在语音音节中间切，不要在字与字的静默间隙切"** —— 这是**音频版的 cutting on action**，而本仓**有词级/字级时间戳**（ASR 产物）。<br>⇒ **建议：剪切点吸附到"字的中段"而不是"字间空隙"。** |
| **层** | **B 层**。 |

### 2.3 视线匹配（Eyeline Match）

| 项 | 内容 |
|---|---|
| **定义** | 角色看向画外，下一个镜头就是他看的东西。 |
| **本仓能不能用** | ❌ **完全不能**。需要**画面内容理解**（谁在看、看哪、那是什么）。<br>本仓连"画面里有几个人"都不知道。 |
| **层** | **不做**（判据不可得）。 |

### 2.4 正反打（Shot / Reverse Shot）

| 项 | 内容 |
|---|---|
| **定义**（[Wikipedia](https://en.wikipedia.org/wiki/Shot/reverse_shot)） | 对话场景中交替呈现两个人的视点。 |
| **本仓能不能用** | ⚠️ **在直播语境下部分成立**：**"主播 ↔ 弹幕"** 就是天然的"正反打"！<br>本仓已经会做：**`anchor: "liver"` → `anchor_to: "danmaku"` → 回 `liver`**（`llm/segment.rs` 里就是这么教的）。 |
| **层** | ⭐ **A/B 层，且已经在做** —— 只是**没被命名为"正反打"**。<br>**建议**：把它**当成一个命名的手法**写进提示词，让 LLM 更稳定地产出这个模式。 |

### 2.5 建立镜头→近景的递进（Establishing → Close Progression）

| 项 | 内容 |
|---|---|
| **定义** | 先给全景交代空间，再逐步推近到细节。 |
| **怎么表达** | ✅ **原生**！`camera` 的**多档递进**：`远(0.55)` → `中(1.3)` → `近(1.5)`。<br>⚠️ **但 `远`（画中画）有硬限制**：**整片最多一条**（`process::fx::cap_pip_shots` 兜底只留最早的一条），且是"短暂的戏剧性停顿"（1.5~3s）。 |
| **层** | **A 层**（能力在）。 |
| **自动化 + 触发** | ⭐ **本仓的段结构天然就是"递进"的载体**：一个切片内部按**话题/情绪转折**分段，每段给不同景别。<br>**信号**：`segment.fx`（low/med/high 情绪密度）。 |

### 2.6 库里肖夫效应（Kuleshov Effect）

| 项 | 内容 |
|---|---|
| **定义** | 同一张无表情的脸，接不同的下一个镜头，观众读出不同情绪。**意义产生于并列**，不产生于单镜头。 |
| **证据等级** | ⚠️ **有实验支持，但有条件**。Barratt et al. 2016 复现后结论是 **"some sort of Kuleshov effect does in fact exist"**，但**依赖于观众的既有电影经验**；后续对**首次观看者**的研究发现效应并不稳定。<br>⇒ 标记为「**部分证实的经典效应**」，不是铁律。 |
| **本仓能不能用** | ⚠️ **理论上有架构**：本仓有 **事件分段 + 字幕 + 贴纸**，"并列"是有的。<br>**但库里肖夫效应依赖"两个镜头的并置"**，而本仓**不并在**（它是连续的一整段）。 |
| **层** | **不做**（不是能力问题，是**载体不匹配**）。 |

### 2.7 J cut / L cut（声画错位）

| 项 | 内容 |
|---|---|
| **定义**（[Vimeo](https://vimeo.com/blog/post/guide-to-film-cuts)、[Adobe](https://www.adobe.com/creativecloud/video/post-production/cuts-in-film/l-and-j-cut.html)） | **J cut**：下一个镜头的声音**先于**它的画面出现。<br>**L cut**：上一个镜头的声音**延续**到下一个镜头的画面上。<br>两者都属 **split edit（分离剪辑）** —— 音视频的切换点**错开**。 |
| **本仓能不能用** | ⭐ ✅ **这是本仓"性价比最高"的一条** —— 因为**音轨完全归本仓**（画面归底座）。<br>前文已给出结论：**只需在 ffmpeg 混音时把音频段与视频段错开 ±0.3~0.5s**，**一行代码级**。<br>⚠️ **而今天本仓音视频是严格对齐的。** |
| **自动化 + 触发** | ✅ **信号齐备**：**字幕时间轴就是人声区间**（ASR 产物，必然存在）⇒ 不需要 VAD。<br>**触发**：段与段的交界处（`Segment` 边界）。 |
| **层** | **B 层**（纯本仓）。 |

> 📌 **J/L cut 值得排进第一批**：它是**唯一一个"成本极低、专业感极强、且触发信号现成"**的手法。
> ⚠️ **注意**：它**改变观感**（声音先到），建议**给开关**。

## 3. 视觉特效（VFX）

> **本节的组织方式**：按"**能不能用现有原语拼出来**"排序，并对每条给出**配方**。
> ⚠️ **一条贯穿全节的硬约束**（`polish-to-dhampir.mjs:3315` 的实测）：
> **有素材的图层只执行 `SeparableBlur`** —— `brightness` / `saturation` / `contrast` 挂在**普通视频层**上会被**整条丢掉**。
> ⇒ **所有色彩类必须挂"调整图层"**（无 `source`、只有 `effects`，`Layer::is_adjustment()`）。

### 3.1 A 层：底座已有、本仓没接（**最便宜**）

| # | 名称 | 具体长相 | 怎么表达 | 自动化 + 触发 | 证据 |
|---|---|---|---|---|---|
| **A1** | **缩放弹跳** `zoom_bounce` | 画面"咚"地弹一下（×1.10，0.4s 窗口，0.08s 处回落） | 底座 `Warp` 族，走调整图层 | ✅ 爆点 + 情绪=惊 | 转译器 `:3068` 注释给了精确参数；`p9` §2.1 第 6 条 |
| **A2** | **饱和度** `saturation` | 画面褪成灰 / 颜色浓到发腻 | 调整图层 `saturation`（**必须是调整层**） | ⚠️ 需语义判据（LLM 判"回忆/走神"） | 转译器 `:3445` 是**注释**，不是产物 |
| **A3** | **对比度** `contrast` | 画面骤然变硬/变平 | 调整图层 `contrast` | ✅ 与 `flash` 同一时刻 | 转译器**已在用**（`:3440`，背景色复刻），只需升级成事件 |
| **A4** | ⭐ **荷兰角/滚转** `rotation` | 画面整体倾斜 | 视频层 `rotation` 关键帧（**已有 `handheld` 波形在用 `rot`**） | ✅ 情绪=high / 弹幕爆发 | `render-core/src/types.rs::HandheldSway.rot` |
| **A5** | **去色→高饱和的"回忆"配方** | 老照片感 | `saturation(↓)` + `contrast(↓)` + `overlay`（暖黄 Solid，低 opacity） | ⚠️ 需 LLM 判"回忆" | 组合，见 §3.3 |
| **A6** | ⚠️ **真 `noise`**（不是白纱） | 雪花噪点 | 底座的 `ColorMask::noise`（**本仓从没发出过**） | ⚠️ 需先定"要白纱还是要噪点" | 转译器 `:2564` 的 `case 'noise'` **映射成白色 `flash`**，**并自己留了提醒** |

> ⚠️ **A6 是本文新发现的一条**，且它**推翻了前文的一个判断**：前文把"真噪声"列为 **C1（要向底座提需求）**，
> 但实际是 —— **底座早就有 `noise` 原语，本仓的出片模板却把它画成了"纯白薄纱"**，
> 转译器为了跟成片一致**主动复现了白纱**。
> ⇒ **这不是"底座缺原语"，是"本仓自己的出片模板名不副实"。**
> 📌 **教训**：**提需求之前先核"是不是本仓自己没接"。**（本节 A1–A4 全都是这一类。）

> ⚠️ **A1 与现有 `pulse` 的区别**（前文已论证）：<br>
> `pulse` = **持续脉冲**（心跳感，×1.06/×0.97，0.48s 窗口）；<br>
> `zoom_bounce` = **一次性弹跳**（弹性感，×1.10，0.30s 窗口）。**两者语义不同，不是重复。**

### 3.2 B 层：现有原语的**新组合**（配方级）

#### 3.2.1 泛光 / 辉光（Bloom · Glow）

| 项 | 内容 |
|---|---|
| **具体长相** | 亮部**溢出**一层柔光，画面"发光"。 |
| **工业实现**（标准做法） | **亮部阈值提取 → 大半径模糊 → 加性合成**。 |
| **本底座能拼吗** | ⚠️ **只能近似，且失真明显**。<br>**缺的是"阈值提取"**：底座没有阈值/亮度遮罩原语。<br>**能做的近似**：`blur`（调整层，最大 16px）+ **降低不透明度** → 得到"柔焦"而非"辉光"。 |
| **失真的地方** | 真 bloom **只让亮部溢出**（暗部不变）；<br>近似是**整帧一起糊**，**暗部也被拉亮**，结果是"发灰"而不是"发光"。 |
| **层** | **C 层**（缺亮度阈值 / 亮部提取）。 |

#### 3.2.2 双色调（Duotone · Gradient Map）

| 项 | 内容 |
|---|---|
| **具体长相** | 画面被映射到**两个颜色**之间（暗部=色 A，亮部=色 B），像丝网印刷。 |
| **工业实现** | **梯度映射**：按**亮度**查一张渐变表。 |
| **本底座能拼吗** | ⚠️ **只能近似**。<br>**近似配方**：`saturation(↓ 到很低或 0)` + `overlay`（Linear 渐变，两个 stop 就是两个色，`opacity` 中低）。<br>**失真**：`overlay` 是**加/叠色**，不是**按亮度重映射** ⇒ 得到的是"**单色染色**"而非"**双色调分离**"。 |
| **层** | **C 层**（缺 gradient map / 亮度驱动映射）。 |

#### 3.2.3 日拍夜（Day-for-night）

| 项 | 内容 |
|---|---|
| **具体长相** | 白天的素材调成夜晚：整体压暗 + **偏蓝** + 提对比 + 压高光。 |
| **配方** | ✅ **可做**：`brightness(↓)` + `contrast(↑)` + `overlay`（深蓝 Solid，`opacity` 中）+ 轻微 `vignette`。<br>⚠️ **本仓已实测过等价的换算**：转译器 `:3334` 记了 **`brightness(0.5)` = `contrast(0.5)` + `brightness(-0.25)`** —— 因为**底座的 `brightness` 是加性的，没有"乘法亮度"**。<br>⇒ **所有"按比例压暗"都要走这个换算。** |
| **层** | **B 层**（但需要"夜晚"这个语义判据）。 |

#### 3.2.4 上下黑边 / 画幅遮罩（Letterbox Bars）

| 项 | 内容 |
|---|---|
| **具体长相** | 画面上下各压一条黑边，做出 2.35:1 等宽银幕感。 |
| **配方** | ✅ **可做**：两条 `overlay`（Solid 黑，`opacity=1`）分别贴顶贴底。<br>⚠️ **底座没有"位置约束"**，要靠 `Transform.position` 摆。 |
| **使用时机** | 回忆/闪回、"电影感"片段、章节转场。 |
| **层** | **B 层**。 |

#### 3.2.5 胶片颗粒（Film Grain）—— ⚠️ **本文核实到一处更重要的事实**

| 项 | 内容 |
|---|---|
| **配方** | ⚠️ **本仓今天根本没有"噪点"** —— 我核了转译器 `:2564` 的 `case 'noise'`，**它映射成白色 `flash`，不是底座的 `noise` 特效**。 |
| **⚠️ 核实到的事实** | 转译器原文注释：**"参照出片里的 `noise` 是一层纯白薄纱，不是噪声"** ——<br>`getNoiseOpacity -> 0.08`（0.08s 升到峰值、0.72s 落回），然后 **`ctx.fillStyle = '#ffffff'; ctx.fillRect(...)`**。<br>⇒ **出片模板画的是白纱**（`templates/index.html` 的可疑处），**真正的噪声只在 DOM 预览的 `handlers.noise` 里**。<br>转译器因此**主动选择复现白纱**（"画面以参照成片为准"），并**留了一条提醒**："这是本仓出片模板的一处'名不副实'，值得本仓自己核。" |
| **🎯 由此得到一条更值钱的结论** | ⭐ **"噪点"这个名字在本仓是名不副实的** —— 用户以为有噪点，其实**出片里是白纱**。<br>这解释了为什么"胶片颗粒/噪点"这类需求一直没被满足：**不是底座没有，是本仓出片模板本身就没画**。<br>⚠️ **注意**：底座**确实有 `noise` 原语**（`ColorMask` 族），**本仓从没发出过它**。 |
| **可行的修法** | ① **短期**：把 `noise` 事件接到**底座的 `noise` 特效**（后者是**真 `ColorMask::noise`**）—— 但会**改变现有工程的成片观感**（白纱 → 真噪点），需评估；<br>② **中期**：修 `templates/index.html` 让它真的画噪点，再统一两端；<br>③ **长期**：见前文 C1（真噪声原语）—— ⚠️ **但按上面的发现，这条需求可能"底座早就满足了"**。 |
| **层** | ⭐ **A 层**（**底座有 `noise`，本仓发的是白纱**）—— 这**修正了前文把"真噪声"列为 C 层**的判断。<br>⚠️ **本文的建议**：**先核清本仓到底想要"白纱"还是"噪点"**，再决定接哪一支。**不要盲目向底座提需求。** |

#### 3.2.6 扫描线 / VHS / CRT

| 项 | 内容 |
|---|---|
| **具体长相** | 扫描线（横条纹）、色度偏移、暗角、亮度溢出、画面弯折。 |
| **本底座能拼吗** | ⚠️ **部分能**：`vignette`（暗角）+ `noise`（亮度噪）+ `overlay`（条纹？**不能** —— `overlay` 只能做渐变，**做不出周期性的线**）。<br>⇒ **扫描线必须逐行处理** ⇒ **C 层**。<br>⚠️ **变通**：**用一张贴纸（PNG 带透明通道的扫描线）** —— 前文 §3 的启示："**遇到'想要一个原语'时，先问'能不能用一张图解决'**"。 **零底座依赖**。 |
| **层** | **C 层**（原语）/ ⭐ **B 层**（贴纸变通，**推荐**）。 |

#### 3.2.7 故障风（Glitch）

| 项 | 内容 |
|---|---|
| **具体长相** | 画面**块状错位**（水平条带左右跳）、**通道分离**（红蓝边缘）、颜色撕裂。 |
| **本底座能拼吗** | ⚠️ **只能做最弱的一种**：`hue` 跳变 + `shake`（位移）+ `flash`（带色）。<br>**缺的是核心**：**块位移（block displacement）** 与**通道分离**。<br>**位移贴图**也在 §0.2 的"没有"里。 |
| **层** | **C 层**（缺位移贴图 + 通道分离）。<br>⚠️ **变通**：一张"故障"贴纸叠上去。 |

#### 3.2.8 色差 / RGB 分离（Chromatic Aberration · RGB Split）

| 项 | 内容 |
|---|---|
| **具体长相** | 红/蓝通道**沿一个方向错开**，物体边缘出现彩色描边。 |
| **为什么做不了** | 需要**按通道分别采样并位移** —— 这是**着色器级**的操作，底座的 `Transform` 是"整层变换"，**动不了单通道**。 |
| **层** | **C 层**（一次解锁：故障切 + CRT + 眩晕 + 老镜头感）。<br>**前文把它排为 C3**，本文同意，并认为**它是 C 层里性价比最高的一条**。 |

#### 3.2.9 冲击波 / 冲击环（Shockwave · Impact Ring）

| 项 | 内容 |
|---|---|
| **具体长相** | 从撞击点扩散的**圆环**，边缘亮，快速放大并淡出。 |
| **能拼吗** | ⚠️ **勉强**：一张**冲击环贴纸** + `Transform.scale` 关键帧（小→大）+ `opacity` 淡出。<br>⇒ **完全可行，且零新原语**。 |
| **层** | ⭐ **B 层**（贴纸方案，**推荐**）。 |

#### 3.2.10 冲击帧（Impact Frames）—— 日式作画

| 项 | 内容 |
|---|---|
| **具体长相** | 撞击瞬间插入 **1~2 帧** 的**反色 / 黑白 / 纯色**画面。 |
| **能拼吗** | ⚠️ **只能用 `flash` 近似**：**亮色闪 1~2 帧**。<br>**缺 `invert` 与 `posterize`**（§0.2）⇒ 做不出"反色闪"。 |
| **层** | 近似 = **B 层**；真反色 = **C 层**。 |

#### 3.2.11 速度线 / 集中线（Speed Lines · 集中線）

| 项 | 内容 |
|---|---|
| **具体长相** | 从焦点向外辐射的线条，制造"速度/冲击"感。 |
| **能拼吗** | ✅ **一张贴纸就能做**（前文已给这个结论）。<br>⚠️ **不能**用 `overlay` 生成 —— 那是渐变，**做不出周期性线条**。 |
| **层** | ⭐ **B 层**（贴纸）。 |

#### 3.2.12 移轴微缩（Tilt-Shift / Miniature）

| 项 | 内容 |
|---|---|
| **具体长相** | 画面**上下两侧糊、中间一条清晰**，看起来像**微缩模型**。 |
| **为什么有效** | 因为**真实的大场景不会只有一条窄带清晰** —— 大脑把"极浅景深"与"近距离小物体"关联起来。（[Wikipedia: Tilt–shift photography](https://en.wikipedia.org/wiki/Tilt%E2%80%93shift_photography) 把它归为 **selective focus / miniature faking**，机理是 **Scheimpflug 原理**让焦平面倾斜。） |
| **本底座能拼吗** | ❌ **不能**。<br>需要**空间变化的模糊**（上/下糊、中间清）—— 这**正是空间遮罩**（§0.2 没有）。<br>⚠️ 底座的 `blur` 是**整帧**的，糊就是全糊。 |
| **层** | **C 层**（缺空间遮罩 / 垂直渐变模糊）。 |

> 📌 **移轴这一条特别值得记一笔**：它是**"看起来像个小效果、其实要一整个原语族"**的典型。
> 想做出"上下糊"，**必须**有"按位置调模糊量"的能力 ⇒ **空间遮罩**。

#### 3.2.13 镜像 / 万花筒（Mirror · Kaleidoscope）

| 项 | 内容 |
|---|---|
| **能拼吗** | ❌ 不能。需要**空间采样翻转**（把画面的一部分镜像）。<br>⚠️ 底座能做的只有**整层翻转**（`scale` 取负），**不是镜像拼接**。 |
| **层** | **C 层**（优先级低，切片语境用不上）。 |

#### 3.2.14 残影 / 拖尾（Echo · Trail）

| 项 | 内容 |
|---|---|
| **具体长相** | 运动物体后面跟着几层**逐渐变淡的旧帧**。 |
| **为什么做不了** | 需要**帧历史缓冲**（读取 t−1、t−2… 的帧并叠加）。<br>底座的合成是**逐帧无状态**的 ⇒ **没有"上一帧"的概念**。 |
| **层** | **C 层**（缺帧历史缓冲，架构级）。 |

#### 3.2.15 频闪（Strobe）

| 项 | 内容 |
|---|---|
| **配方** | ✅ **可做**：`flash` 或 `overlay` 的 `opacity` **包络关键帧**做成方波（快速 on/off）。<br>⚠️ 转译器已有 **`placeEnvelope`** 做逐帧包络（`:1664`：`keyframes.push({ frame: i, target: 'opacity', value: shape(i / fps) })`）⇒ **机制现成**。 |
| **使用时机** | 疯狂/混乱/精神崩溃；**⚠️ 光敏性癫痫风险，需克制**。 |
| **层** | **B 层**。 |

#### 3.2.16 心跳脉冲 / 呼吸缩放（Heartbeat · Breathing Zoom）

| 项 | 内容 |
|---|---|
| **配方** | ✅ **两个都已有**：<br>**心跳** = `pulse`（×1.06/×0.97，0.48s 窗口，逐帧采样）；<br>**呼吸** = `handheld` 波形里的 `scale` 分量（`HandheldSway.scale`，"呼吸缩放倍率，1.0 = 不缩放"）。 |
| **层** | **A 层**。 |

#### 3.2.17 弹性挤压 / 果冻 / 摆动（Elastic Squash · Jelly · Wobble）

| 项 | 内容 |
|---|---|
| **具体长相** | 物体出现/受击时**被拉伸再弹回**（squash & stretch），或像果冻一样**缓慢扭动**。 |
| **同族性** | **`zoom_bounce` 就是这一族最简单的形态**（等比放大 ×1.10 再回）。 |
| **能拼吗** | ⚠️ **部分能**：<br>**等比弹性** = `zoom_bounce`（已有）；<br>**非等比（横向拉宽/纵向压扁）** = 需要**分别控制 scale.x / scale.y** —— 底座只有**统一的 `scale`** ⇒ **做不了**。<br>**扭动** = 需要**位移贴图** ⇒ **做不了**。 |
| **层** | 等比 = **A 层**；非等比/扭动 = **C 层**。 |

#### 3.2.18 伪造景深（Depth Fake）

| 项 | 内容 |
|---|---|
| **能拼吗** | ❌ **本质上不能** —— 需要**深度信息**才能决定"哪里该糊"。<br>本仓与底座**都没有深度**。 |
| **层** | **不做**。 |

## 4. 剪辑手法（Editing Techniques）

> ⚠️ **本节的第一原则**（前文 §0.3 已确立，本文重申）：
> **切片的转场语汇与电影不同。** ffmpeg 生态作者直言：
> **"对话内部同一个人物的两镜头间用叠化会读作失误；快剪社交媒体剪辑靠硬切活着"**
> （[FFmpeg Micro](https://www.ffmpeg-micro.com/blog/crossfade-between-clips-with-ffmpeg-xfade-no-editor)），
> 且 **>1 秒的转场"读作 2009 年的幻灯片"**。
> ⇒ **要的是可见的、有节奏的、带音效的硬切与跳切。叠化/划像不在需求里。**

### 4.1 硬切（Hard Cut）—— ⭐ 默认

| 项 | 内容 |
|---|---|
| **定义/长相** | 两个镜头直接相接，无任何过渡。 |
| **本仓** | ✅ **已经是默认做法**。底座的时间轴是源帧号重映射 ⇒ **相邻区间之间天然是硬切**。 |
| **层** | **A 层**（已有）。 |

### 4.2 跳切（Jump Cut）—— ⭐⭐ **本仓已经在做，只是没当手法用**

| 项 | 内容 |
|---|---|
| **定义**（[Wikipedia](https://en.wikipedia.org/wiki/Jump_cut)） | **"breaks a single continuous sequential shot of a subject into two parts, with a piece of footage removed to create the effect of jumping forward in time"**。<br>机位关系不变，**跳的是时间**。 |
| **两种**（同页） | **spatial jump cut**（两段非连续拍摄接起来）与 **temporal jump cut**（**从一段连续镜头里挖掉中间一段**）。 |
| **✅ 文献支持"加节奏"** | 同页：**"Jump cuts can add a sense of speed to the sequence of events."**<br>同页还给了**短视频语境的确认**：**"in many vlogs online, as popularized by the show with zefrank"**。 |
| **✅ 文献支持"去填充"** | [Shortzly 的节奏指南](https://shortzly.com/blog/short-form-video-pacing-editing-guide)：跳切"removes filler and keeps pace high"；**用于剪掉 `um, uh, long pauses`**。 |
| **本仓怎么表达** | ✅ **已经在做**！`mute_ranges` + `cut_ranges` —— **把静默段掐掉**（`polish-translation.md` §0.1 实测：三段 `mute_ranges` = 17.49s，成片正好短 17.49s）。<br>**这在剪辑术语上就是 temporal jump cut。** |
| **缺什么** | **只缺"把它当节奏工具用"** —— 今天它是**去静音的技术手段**，不是**设计手法**。 |
| **自动化 + 触发** | ✅ **信号最好的一个**：**静默区间**（已有）+ **字幕间隙**。<br>⭐ **建议升级**：除了"静默"，还可以**主动挖掉"低信息密度的冗余"**（同一句话里的重复、口癖）。 |
| **层** | **A/B 层**（机制已有，缺"当成手法"的编排）。 |

> 📌 **前文把跳切列为 B12，本文同意并加强**：<br>
> **跳切是短视频的"定义性剪辑"** —— Shortzly 原文：**"The jump cut ... is the defining edit of short-form video."**<br>
> ⚠️ **但同文也给了两个警告**（**很有价值，建议做成守卫**）：<br>
> ① **两段太像** ⇒ 读成失误；<br>
> ② **人物位置跳过了画面中线** ⇒ 空间混乱。<br>
> **修法**：**中间插一段 B-roll**（对本仓 = **插一张贴纸/一个 cutaway**，见 §4.14）。

### 4.3 匹配剪辑（Match Cut · Graphic Match · Match on Action）

| 项 | 内容 |
|---|---|
| **定义** | 靠**形状/动作/声音的相似**把两个镜头接起来，让切换"隐形"。 |
| **与跳切的关系** | **正好相反**：跳切**故意暴露**剪接点；匹配剪辑**故意隐藏**它。<br>（[Morphic 术语页](https://morphic.com/zh/ai-glossary/jump-cut)："跳切本质上是匹配剪辑(match cut)的反面"。） |
| **本仓能不能用** | ❌ **基本不能**。需要**画面内容**（找两个镜头里形状/动作相似的瞬间）。<br>本仓只有 transcript + 弹幕。 |
| **层** | **不做**（判据不可得）。 |

### 4.4 蒙太奇压缩（Montage Compression）

| 项 | 内容 |
|---|---|
| **定义**（[Wikipedia: Continuity editing](https://en.wikipedia.org/wiki/Continuity_editing)） | **"Montage is achieved with a collection of symbolically related images, cut together in a way that suggests psychological relationships rather than a temporal continuum."**<br>用**省略**压缩时间（"训练蒙太奇"）。 |
| **本仓能不能用** | ⚠️ **本仓的"分散事件合并"（`Event::ranges`）在结构上就是这个东西**！<br>多条源区间拼成一条切片（`scattered-events-merge.md`）—— **它把不连续的时间片段接成一条**。 |
| **层** | ⭐ **A 层，且已经在做** —— 只是**没被命名为蒙太奇**。 |
| **自动化 + 触发** | ✅ **已有**：`merge_scattered` 按 `topic` 归组 + `merge_gap_secs` 间隔阈值。 |

### 4.5 卡点 / 节拍同步（Beat Sync · Montage）

| 项 | 内容 |
|---|---|
| **定义** | 剪辑点落在**音乐节拍**上。 |
| **证据等级** | ⚠️ **行业教学共识**（Shortzly 把它列为"三维节奏"之一："**When cuts land on beats, the edit feels musical and satisfying**"），<br>并给了**可操作的口径**：**"cut on the beat, or one frame before it"** —— **"落在拍前一帧比正落在拍上更有能量"**。 |
| **本仓能不能用** | ⚠️ **前提缺失**：**本仓没有 BGM**（用户已明确：音轨全是直播原声）。<br>⇒ **没有节拍网格可对**。<br>**变通**：用**语音的节奏**当节拍（字/词的边界）⇒ 但那是**语音节奏**，不是"音乐卡点"。 |
| **层** | **阻塞**（需先有 BGM，见总方案 §11）。<br>⚠️ **不要假装能做** —— 没有音乐的"卡点"是没有意义的。 |

### 4.6 定格（Freeze Frame）

| 项 | 内容 |
|---|---|
| **定义** | 画面**冻住**若干秒。 |
| **本仓能不能用** | ⚠️ **时间轴层可做**（让某一段只采样同一帧）—— 但那需要**改源帧号映射**。<br>⚠️ **音频怎么办**？定格时人声还在说 ⇒ **声画会错位**。<br>⇒ **除非同时处理音轨**，否则不是一个干净的手法。 |
| **层** | **B 层**（需本仓自己做时间轴 + 同步处理音轨）。 |

### 4.7 重复 / 鬼畜 / 卡帧（Repeat · Stutter）

| 项 | 内容 |
|---|---|
| **具体长相** | 同一小段**重放 2~3 次**。 |
| **本仓怎么表达** | ✅ **可做**：**重复 = 让某段源区间被采样两次**。<br>⚠️ `Stutter` 在底座被**明确归为"时间轴行为、不进特效管线"**（`p9` §2.1 第 9 条；且 `stutter` 已于 2026-10-01 从本仓删除，见 `spec/effects.json` 的 `_note`）。<br>⇒ **本仓自己做**（`cut_ranges` 的自然延伸）。 |
| **⚠️ 纪律** | **前文已定：≤3 次，且每条切片 ≤1 处** —— 滥用立刻变 low。 |
| **层** | **B 层**（纯本仓）。 |

### 4.8 变速（Speed Ramp）

| 项 | 内容 |
|---|---|
| **定义** | 段内**速度曲线**变化（正常→慢→正常）。 |
| **本仓能不能用** | ⚠️ **要拆成两种**（前文的调和意见，本文同意）：<br>① **整段快放/慢放**（整段 ×2 / ×0.5）—— **不需要"动作临界点"判据**，只需判"这段拖沓"（**字幕密度/静默比例**能判）⇒ **可做**；<br>② **速度斜坡**（卡在动作临界点）—— **需要视觉动作检测** ⇒ **做不了**。 |
| **⚠️ 跨仓硬约束** | **画面归底座、声音归本仓** ⇒ **视频变速必须同时变音轨**，否则声画不同步。**这是真实成本所在**（不是判据，是两边要一起改）。 |
| **层** | 整段变速 = **B 层**；速度斜坡 = **C 层**（且缺判据）。 |

### 4.9 喜剧停顿（Comedy Beat · The Pause）

| 项 | 内容 |
|---|---|
| **具体长相** | 笑点之后**故意留白**，让笑声/反应发酵。 |
| **本仓** | ✅ **可做**，而且**本仓有天然优势**：**本仓已经在识别静默**（`mute_ranges`）。<br>⇒ **只需"分类"**：哪些静默是"废话"（掐掉，§4.2），哪些是"笑点后的停顿"（**保留甚至加长**）。 |
| **层** | **B 层**（前文 §7 已列）。 |

### 4.10 冷开场（Cold Open）

| 项 | 内容 |
|---|---|
| **定义** | 直接进内容，**没有铺垫/没有片头**。 |
| **本仓** | ✅ **可做且已有基础**：本仓的片头是**一条渐入覆盖事件**（`process::ensure_intro_fade_in`，Step 3c）。<br>⇒ **"冷开场" = 去掉/缩短这条**，或**把切片最炸的一句提到最前**。 |
| **层** | **B 层**。 |

### 4.11 呼应 / 首尾呼应（Callback · Bookend）

| 项 | 内容 |
|---|---|
| **定义** | **Callback**：后面重现前面的元素。<br>**Bookend**：结尾与开头呼应（同一句话/同一个画面）。 |
| **本仓** | ⚠️ **理论上可做**（把开头的一段复制到结尾）。<br>⚠️ **但没有判据** —— 要判"哪一句该被呼应"需要**理解内容**。<br>**可行的弱版本**：**Bookend = 首尾用同一个景别/同一个贴纸** —— **纯结构规则，不需要理解**。 |
| **层** | **B 层**（弱版本）。 |

### 4.12 切入镜头 / 插入（Cutaway · Insert）

| 项 | 内容 |
|---|---|
| **定义** | 切到**别的画面**再切回来。 |
| **本仓怎么表达** | ⭐ ✅ **贴纸就是本仓的 cutaway！**<br>VTuber 切片里"插一个表情包/反应图"在剪辑语法上**就是 cutaway** —— 它重置视觉参照、盖住跳切、补充情绪信息。<br>**这与 §4.2 里 Shortzly 给的"跳切修法"完全吻合**："insert a brief B-roll shot between jump cuts"。 |
| **层** | ⭐ **A 层**（能力已有，缺"当成剪辑手法"的意识）。 |
| **自动化 + 触发** | ✅ **已有**：LLM 产 `sticker` 事件，且会**对齐到最近字幕**（`align_stickers_to_subtitles`）。 |

### 4.13 反应镜头（Reaction Shot）

| 项 | 内容 |
|---|---|
| **定义** | 切到**听者/旁观者的反应**。 |
| **本仓** | ⚠️ **在直播语境下**：**主播本人就是唯一主体** ⇒ "反应镜头"与"主镜头"**是同一个**。<br>**但本仓有替代**：**"主播 + 弹幕区"** 的正反打（§2.4）**在语法上就是反应镜头的等价物** —— **弹幕是"观众的反应"，切到弹幕区 = 切到反应镜头**。 |
| **层** | ⭐ **A/B 层**（用 `anchor_to: "danmaku"` 实现，已有）。 |

### 4.14 非线性 / 闪回（Non-linear · Flashback）

| 项 | 内容 |
|---|---|
| **本仓能不能用** | ⚠️ **顺序可调**（本仓能选任意源区间拼装）⇒ **技术上能"把后面的一段放到前面"**。<br>⚠️ **但"闪回"需要叙事理解**（"这段是回忆"），**本仓没有**。 |
| **弱版本** | **"把最炸的一句提到开头当钩子"** —— 这是**冷开场**（§4.10），**是"倒叙"的实用形态**，且**判据现成**（`popularity` 高分 / 弹幕峰值）。 |
| **层** | ⭐ **B 层**（**强烈推荐**：它是"高留存"最直接的手段）。 |

### 4.15 章节结构（Chapter Structure）

| 项 | 内容 |
|---|---|
| **本仓** | ✅ **本仓的 `Segment` 就是章节**！<br>⇒ **可做**：每个章节前插一张**章节卡**（全屏文字 + `overlay` 底）。<br>⚠️ **依赖底座文字层的 `entrance` 字段**（见 §5）。 |
| **层** | **B 层**（前文 B5）。 |

### 4.16 "三拍"（Three-Beat Rule）—— ⚠️ **术语澄清**

| 项 | 内容 |
|---|---|
| **⚠️ 三个不同的东西共用这个名字** | ① **喜剧的 rule of three**：**三个一组**，第三个是包袱（setup-setup-punchline）；<br>② **剪辑的"三拍"**：**一个动作切三次**（不同景别/角度）—— 这是**动作剪辑**的强化版；<br>③ **三镜头法**：**主镜头 + 两个反应镜头**（好莱坞标准覆盖）。 |
| **哪个对本仓有用** | ⭐ **①** —— 它**不需要画面**，只需要**内容结构**。<br>本仓有 **LLM 分段的 `label`/`summary`** ⇒ **可以判"这三句是不是一组铺垫+包袱"**。<br>⇒ **可做成 LLM 提示词里的一条编排指令。** |
| **②** | ❌ 需要**同一动作的多机位素材** —— 本仓只有一路录像。 |
| **③** | ⚠️ 直播语境下退化成 §2.4 的"主播↔弹幕"。 |
| **层** | ① = **B 层**（提示词级）；② = **不做**；③ = **A 层**。 |

### 4.17 越轴 / 180 度规则 —— ⚠️ **不适用**

| 项 | 内容 |
|---|---|
| **定义** | 摄影机不能越过两个主体的**动作轴**。 |
| **为什么本仓不适用** | **本仓不产出"多个机位"** —— 切片是**一路连续录像**。<br>⚠️ **唯一相关的场景**：`cut:true` 瞬跳构图时，如果**主播在画面中的左右关系被翻转**，观众会混淆。<br>⇒ **可以做成一个弱守卫**：`cut` 事件**保持主播的相对屏幕方向**。 |
| **层** | **B 层**（守卫，很弱）。 |

## 5. 跨层：文字层（**真正的最高杠杆**）

> **前文 §0.1 的核心结论，本文核实并加强**：
> **VTuber 切片/短视频的视觉语法本质是"字幕即设计"。**
> 依据：**92% 移动用户静音观看、80% 说字幕让他们看到最后**
> （Verizon Media/Publicis 2019 调查，经 [KIRARI](https://www.kirari.io/blog/vtuber-clip-subtitle-guide) 引述）。
> ⚠️ **该调查的原始报告我没能直接核到**，标记为**「二手引述的行业调查」**。

### 5.1 三个"无"字段（**提需求**）

`p9-downstream-requirements.md` §2.2 明确记录：

| 层 | 字段 | 底座现状 | 解锁什么 |
|---|---|---|---|
| `SubtitleStyle` | `stroke` | ❌ 无 | **描边** —— 可读性基础（**白字黑边是万能解**） |
| `SubtitleStyle` | `highlight_color` | ❌ 无 | **高亮色** —— 卡拉OK / 强调的**全部前提** |
| `SubtitleStyle` | `entrance` | ❌ 无 | **入场动画** —— 打字机 / 弹跳入场 |
| `DanmakuStyle` | `highlight` / `direction` | ❌ 无 | 弹幕高亮 / 方向 |

> 📌 **一次改动解锁四项**（卡拉OK + 大字 + 打字机 + 弹跳入场）。
> ⚠️ **这三个字段属底座的"像素怎么算"** ⇒ **本仓提需求，不自造**。

### 5.2 字幕参数基准（可直接当默认值）

出自 [KIRARI](https://www.kirari.io/blog/vtuber-clip-subtitle-guide)：

|---|---|---|

| **描边粗度** | **字号的 5–8%** | 同 |
| 每行字数 | 15–18 字 | 同 |
| 语速 | 每秒 4 字 | 同 |
| 最多行数 | 2 行 | 同 |
| 位置 | 下 1/3 | 同 |
| 配色 | **白字黑边**（万能解）；强调用**主播应援色** | 同 |

### 5.3 弹幕颜色：**断点在转译器**（本仓自修）

| 路径 | 状态 |
|---|---|
| `DanmakuEntry.color`（数据层） | ✅ 字段在 |

**这是本仓单方面就能修的接线缺口。**

## 6. 总表与优先级

### 6.1 三层汇总

| 层 | 含义 | 数量 | 代表项 |
|---|---|---|---|
| **A 层** | **底座已有、本仓没接**（最便宜） | **10** | 缩放弹跳、饱和度、对比度、**荷兰角/rotation**、**真 `noise`（本仓发的是白纱）**、呼吸缩放、心跳脉冲、snap zoom(`cut`)、正反打、跳切(已有机制) |
| **B 层** | **现有原语的新组合**（不需要底座改） | **24** | **J/L cut**、闪白切、Ken Burns、reframe、letterbox、strobe、频闪、冲击环贴纸、速度线贴纸、VHS贴纸、蒙太奇压缩、鬼畜重复、喜剧停顿、冷开场、倒叙钩子、章节卡、cutaway(贴纸)、卡帧 |
| **C 层** | **需要底座加新原语** | **12** | RGB 分离、方向性模糊、空间遮罩（→移轴/真移焦）、位移贴图（→glitch）、通道分离、invert（→冲击帧）、亮度阈值（→bloom）、gradient map（→duotone）、帧历史（→残影）、3D/深度（→parallax/环绕）、透视变化（→dolly zoom）、帧历史 |
| **不做** | 判据不可得 / 载体不匹配 / 业务已覆盖 | **8** | 视线匹配、匹配剪辑、库里肖夫、跟焦、分屏、伪造景深、真闪回、越轴 |

### 6.2 ⭐ **建议的第一批（性价比排序）**

| # | 项 | 层 | 理由 |
|---|---|---|---|
| **1** | **J cut / L cut** | B | ⭐ **音轨归本仓 ⇒ 成本最低的专业感提升**。今天音视频**严格对齐**。信号现成（字幕区间）。 |
| **2** | **跳切当手法用**（升级 `mute_ranges`） | A/B | ⭐ **机制已经在跑**，只差"当节奏工具"的设计。**文献支持最扎实的一条**（Wikipedia + Shortzly）。 |
| **3** | **cutaway = 贴纸**（把已有贴纸重新定位成剪辑手法） | A | 零成本，且**正好是"跳切的修法"**。 |
| **4** | **倒叙钩子**（最炸一句提到开头） | B | 留存最直接的手段，**判据现成**（`popularity` / 弹幕峰值）。 |
| **5** | **荷兰角 / rotation** | A | 底座有 `rotation`、`handheld` 已在用 `rot`，**本仓没接**。表达力强、成本极低。 |
| **6** | **Ken Burns 自动补**（>6s 无事件插最低强度推近） | A | **零新基元**，直接改善留存（每 3–6s 一次视觉变化）。 |
| **7** | **闪白切**（`flash` 对齐切点） | B | 转译器已有 `flash`，只差"对齐切点"的守卫。 |
| **8** | **缩放弹跳 `zoom_bounce`** | A | 底座已有、本仓发 0 次（✅ Warp 级已修好）。 |
| **9** | **弹幕逐条颜色** | B | 本仓单方面就能修（§5.3）。 |
| **10** | **正反打 / 反应镜头**（命名 + 强化提示词） | A | 已经在做（主播↔弹幕），只是没被命名。 |

### 6.3 ⚠️ **明确建议"不做"的**

| 项 | 为什么不做 |
|---|---|
| **划像 / 遮罩转场** | 前文 §0.3 已定：**切片靠硬切活着**，且 ">1秒的转场读作 2009 年的幻灯片"。 |
| **分屏** | **直播画面本身就是双区构图**（主播 + 游戏），业务已覆盖。 |
| **真闪回 / 非线性叙事** | 需要**叙事理解**；弱版本（倒叙钩子）已经够了。 |
| **视线匹配 / 匹配剪辑 / 库里肖夫 / 跟焦** | **判据完全不可得**（需要画面内容理解与人脸/主体检测）。 |
| **dolly zoom** | **数学上不可能**（§1.12），成本极高、切片语境用不上。 |
| **环绕 / 视差 / 伪造景深** | 需要 **3D / 深度**，底座是"一张平面图"。 |
