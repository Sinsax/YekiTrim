## 1. 为什么要做：实测的现状

### 1.1 一个效果今天要被"知道" 11 次

```
spec/effects.json → types.rs(enum) → fx.rs(两张表) → 转译器 case
                 → templates/index.html(handler) → engine.js(求值器)
                 → TimelineEditor.vue(控件) → INDEXED_TYPES → LANE_OF_TYPE ×4
```

门禁覆盖 15 处，但**只剩 4 处无单一权威**（属性面板复杂控件 / `INDEXED_TYPES` /
`LANE_OF_TYPE` 四份 / 模板 handler 本体）。

### 1.2 枚举形状造成的纯冗余（实测）

`Event` enum 12 个变体，**两组字段完全相同**：

```
[Flash, HueShift]               → time,color,end,anchor,sfx,sfx_volume
[Blur, Vignette, Noise, Pulse]  → time,end,anchor,sfx,sfx_volume
```

通用字段：`time 12/12 · end 12/12 · sfx 9/12 · sfx_volume 9/12 · anchor 9/12`。
全仓 `Event::` 分派 **296 处**；按类型字符串分派的文件 **17 个**。

### 1.3 底座的现状：数据可扩展、渲染不可扩展

底座 `plan/effects-modularization.md` §0 原话：

> 一句话：**数据可扩展、渲染不可扩展。**

| 面 | 现状 |

| **管线** | ✅ `EffectPipeline` 4 条，**按管线派发而非字符串**（S3 已做对） |
| **着色器** | ✅ 9 份 WGSL 一份文本，**wasm 与 native 共用** |
| **槽位** | ❌ **16 条硬编码字符串** → **3 个定长 `#[repr(C)]` struct** |

#### ★ P2 暴露的一个**一直存在**的静默失效（已修）

变异台的 `loadVariant` 把转译器源码**复制进 `tmpdir`** 再 import，
而词汇表的两条相对路径（同目录 `./effects.json` / `../spec/effects.json`）在那时**全都落空**。

- **P2 之前**：只让报告文案退化成"不认识的事件类型"⇒ 没人发现；
- **P2 之后**：`dhampir_rule` 读不到 ⇒ **声明式派发整条失效、特效一个都不转**，
  而退出码仍是 0。实测：副本里一条 `flash` 事件**连层都不生成**，
  于是"窗口不许溢出所在段"那条变异**永远不红** —— 变异台只说"1 处没被打红"，
  看着像**被变异那行代码**的问题，真正的病根在**注入路径**。

修法：`YEKITRIM_SPEC_DIR` 显式指路（刻意**不写"从 CWD 找"** —— 那会让"跑在哪个目录"改变出片结果）；
并加 `assertVocabLoaded` 让这类洞**再也不能静默**。修完 **106 处变异全部打红**。

#### ★ P4 的**诚实边界**（写清楚，免得下次误以为"运镜全声明化了"）

运镜分两段，**只有第一段可声明**：

| 段 | 规模 | 可声明？ |
|---|---|---|
| ① **收集**：把事件字段搬成 `cameraEvents` 记录 + 默认值 | ~20 行 | ✅ **已声明化**（`collect.fields`） |
| ② **消费**：插值算法（过渡窗口 / 硬切 / 手持 / 荷兰角状态机 / 逐帧变换） | ~170 行 | ❌ **不在声明范围** |

⇒ 「加新运镜」的两种形态：
- **复用现成字段的新 preset**（例 `zoom=近 + speed=fast` 的"快推"）→ **只改 L0**（里程碑判据就是这条）；
- **带新字段的运镜**（例绕 Z 轴的 `roll`）→ 仍需 ① 词汇表加字段 + ② `types.rs` 加变体字段
  + ③ **写那一段新算法**。算法抄不了，**也不该假装能抄**（词汇表 `_scope` 里写明了这条）。

#### ★ P4 当场抓出的那个 bug（只有逐字节对拍抓得住）

第一版把 `...carried` 直接展开进记录，而 `collect.fields` 里的 **`origin` 是原始字符串**
（`"liver"`），记录里那个键放的却是**解析后的点** `{x,y}` ⇒ 原始值把派生值**顶掉** ⇒
`e.origin.x` 是 `undefined` ⇒ `NaN` ⇒ **同一层 806 个关键帧变成 `null`**（x/y 各 403 个）。

- 转译器**不报任何错**，DROP/NOTE 一条没变，报告看着完全正常；
- 单元级判据也全绿（它测的是曲线本身，不是"字段有没有被顶掉"）；
- **只有"演示工程产物逐字节相同"那条校验抓得住**。

修法：派生值**后写**（放在 `...carried` 之后）+ 把 `origin` 明确列进"由运镜自己解析"的集合。
这正是"原始字段与派生字段同名"的经典坑 —— 也是为什么 P2/P4 每一步都拿**整份产物 hash** 当判据。

**原先没有任何门禁钉住"默认进 Dhampir"**。那一处（`onMounted` 里的自动切换）掉了
**不会报任何错** —— 所有门禁照旧全绿，只是预览静默退回 DOM 腿，
于是"`engine.js` 是模板的手工复制副本"这整类耦合**又回来了**（P3 存在的唯一理由）。

⇒ 在 `check-preview-ab.mjs` 补 3 条 + 1 处变异自证（**17 → 22 项**）：
① 挂载后自动进；② 失败自动退回 DOM；③ DOM 兜底腿仍在。
**变异自证已实测**：把那行自动切换删掉，守卫**当场点名报红**。

⚠️ 判据刻意**不钉那个 300ms 延时值**（它是体验调参，钉死会让无害改动报假红）。

#### ★ 修正计划里两处**过期表述**

| 原文 | 事实 |
|---|---|
| P3 风险"**中高（需决策）**" | 代码已在仓库里，风险主要落在**体验回归**（起播时间 / 无独显场景），不是工程量 |
| §5“删掉 DOM 预览腿（P3 之外）” | 仍然成立 —— P3 的口径是"DOM **降兜底**"，删除是**独立决策**，本轮**没删** |

⇒ 计划 §6 第 2 条（"预览要不要与出片逐像素一致"）**仍然有效、仍待拍板**，
但它决定的是"**DOM 腿要不要删**"，不是"P3 做不做"。

### 3.3 P5 的关键事实（决定它安全）

> ⚠️ **P5 的完整实施方案另有一份**：`docs/plan/p5-dhampir-slot-removal-plan.md`
> （实测的三处 `match spec.kind` / 41 个定长槽位 / 四种 combine 规则 / 逐像素验收线 / 五步可回退顺序）。
> 下面这张表是它的**摘要**。

| 项 | 实测 |
|---|---|
| **要改的文件** | `render/warp.rs`(303) · `render/color_mask.rs`(354) · `render/color_adjust.rs`(347) · `effects.rs`(606) |
| **要不要动 `project_schema`** | ❌ **不用** —— `Effect.params` 已是自由 map（`additionalProperties:number`），工程文件形状不变 |
| **要不要动 `host_api`** | 通常不用（导出面不变）；若新增导出才要升 |
| **当前版本线** | `project_schema=1` · `host_api=6`（产物 `dhampir-0.3.0`） |
| **验证回路** | `scripts/yekitrim-compare.mjs`（自检 24 项全绿）：转译 → 两边出片 → 按事件窗口出表 |
| **开发时怎么用改过的底座** | `VTEDIT_DHAMPIR` 指文件，或自动找 `Dhampir/target/{release,debug}` |

**⇒ P5 是 schema 中性的**：工程文件格式不变、老工程仍可读，
只是**渲染器内部**从定长槽位改成按注册表布局。**这是它风险可控的根本原因。**

### 3.4 P5 的依据不是新提案

底座 `p9-polish-parity-design.md` §3 **原则 2** 已写下：

> **参数是 map 不是 struct。** 参照实现用 `EffectUniform`（定长、字段写死、
> 注释里编号复用 `misc.xyz`）。改成"**一个参数缓冲区 + 按注册表布局**"，参数个数不受限。

**⇒ 本计划是把底座自己已写下的原则执行到底，不是另起炉灶。**

## 4. 三条不可退让的约束

底座 `effects-modularization.md` §0 列了三条，本仓同样适用：

1. **两端一致**：同一份工程在 wasm 与 native 下结构一致、可比。
2. **逐字节稳定**：序列化逐字节可复现（`BTreeMap` 不是 `HashMap`）—— 本仓 R4 红线同此。
3. **不静默降级**：做不到的事要**报错**，不许按正常画过去。

**⚠️ 前置缺口**：本仓**没有 R4 的老工程 round-trip 金样门禁**。
**P2 之前必须先补**，否则数据模型迁移没有回归判据。

## 5. 明确不做 / 做不到

|---|---|
