## 1. 批 0 · 前置（**必须先做，否则后面两项无法定成败**）

### 0.1 ★ LLM 产出率实测（决定 §18-A / §5 E5 怎么修）

**为什么必须做**：重验已确认两条**性质不同**的断裂 ——
- `§18-A 特写`：提示词里**这个词根本不存在**（`segment.rs:83` 只有 `远/中/近`）；
- `§5 E5 文字元素`：词**存在**，但只有上限（`segment.rs:113`「**最多** 1~2 条」）、
  **无下限**，而同一份提示词里 `punch` 写着「**至少**要有一段」（`:363`）。

⇒ **后者到底产不产、产多少，只有真跑才知道**。不测就改提示词 = 可能白改一轮。

**做法**：拿真实 ASR 片段跑 `polish llm`，统计
`kind="text"` / `zoom="特写"` / `tilt` 的出现率（多次重复，温度 0 则记录确定性）。
⚠️ 现有工程**全是手搭夹具**（`reason`=0、`text`=0），需**新建一份真 LLM 工程**。

**验收证据**：产出率统计表 + 至少一次完整 `process → llm → 转译` 的真实工程。

### 0.2 ★ 修门禁的**维度漏洞**（系统性 ①）

**缺陷**：`check-preview-engine.mjs:49` 只比对 `INDEXED_TYPES` 的**成员集合**
⇒ 它证明"`element` **登记了**"，**完全不涉及"预览有没有真的画出来"**
⇒ 于是 `engine.js:890` 的 `continue` 让 text 预览一片空白、成片却画得出，**没有任何门禁会红**。

**做法**：新增判据口径 —— **"登记了"必须伴随"有绘制实现"**。
参考 `check-camera-zoom-parity.mjs`（五处逐值一致）的房规。
⚠️ **判据要能自证可红**：把 `engine.js:890` 改回 `continue` ⇒ **必须红**。

**验收证据**：变异自证（改回旧行为 ⇒ 红）。
