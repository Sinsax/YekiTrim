## 三、★ 唯一的错：§五 决策 2 的**数字前提是错的**

### 文档原文

> ### 决策 2：泳道 7 → 8 条（+26px）
> 卡上明写「布局必须保持紧凑：泳道 26px ×7 + 标尺 20px = **202px**」。
> 现在 **8×26+20 = 228px**。

### 实测

```
拆分前（915ef24^）：6 条   分段 / 字幕 / 运镜 / 「元素」 / 视觉特效 / 音效
拆分后（现在）  ：7 条   分段 / 字幕 / 运镜 / 「文字」/「贴纸」/ 视觉特效 / 音效
```

⇒ **是 6 → 7，不是 7 → 8。**

```
文档算： 8×26+20 = 228px   （多算了一条泳道 = 26px）
实际：   7×26+20 = 202px
```

### 后果：**这个"待决策"根本不存在**

卡上原文（`webui/src/components/AGENTS.md:26`）：

> 泳道 **26px ×7 条 + 标尺 20px = 202px**

**卡说的"7 条"就是现在的 7 条**，总数**正好 202px**，**与卡完全一致、零冲突**。

⇒ 决策 2 的三个选项（+26px / 并排 / 缩到 23px）**都不需要**。
⇒ 拆一条泳道刚好用掉原来那条「元素」的额度 —— 当初"7 条 = 202px"里的第 4 条
  本来就是「元素」轨，它拆成两条是 **+1**，而总数从 6 条起算 ⇒ 落回 7 条。

⚠️ **卡已经被更新过了**（现在是"7 条"），**但计划书的决策项还留着旧前提**。
如果照决策 2 去选 (1)「就 +26px」，会**平白把布局撑高 26px 并破坏卡上口径**。
