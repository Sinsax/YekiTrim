# 为什么「位置改了几轮都没变化」（2026-10-14 查清）

用户口径：「**这个文字层的位置问题，修了几轮？当前还是不正常的位置。**」
「**你这个位置没有一次有变化。**」

前四轮我都在改**算法**，改完自己跑纯函数验证"算对了"，然后回复"修好了"。
用户看到的**一点变化都没有**。这篇记的是**为什么**。

---

## 一、根因：文字元素被**画了两遍**，而变化落在被盖住的那一遍上

`PolishPreview.vue` 的图层栈（都是真 CSS，不是推测）：

| 层 | 选择器 | `z-index` | 谁在画 |
|---|---|---|---|
| 底座画面（含**它自己那份文字**） | `.dhampir-canvas` | **40** | wasm / Dhampir |
| DOM 覆盖层（字幕 / 弹幕 / 贴纸 / **文字元素**） | `.overlay-space` | **10** | `engine.js` + Vue |
| 点选 / 框选 | `.sel-layer` / `.point-layer` | 70 | — |

⚠️ `.dhampir-canvas` 的注释本身就写着「**画布盖在 DOM 预览之上**」——
**这是有意的设计**（要让贴纸/选框跟着 wasm 画面走），不是 bug。

**但文字元素是特例**：它**同时**存在于两边：

- **底座那份**：转译器把 `kind === "text"` 落成**独立 ASS 资产 + 单层字幕轨**
  （`tools/polish-to-dhampir.mjs` 的 `case 'element'`，注释里写明「底座没有自由文本图层，
  文字一律走字幕资产 + `SubtitleStyle`」）⇒ 底座**自己会画一遍**，用 `\pos` + 它自己的排版。
- **DOM 那份**：`getElements()` 也画一遍（`PolishPreview.vue` 的 `.text-layer`，
  没有任何 `v-if="!dhampirMode"` 门控）。

⇒ 在默认的 Dhampir 模式下**两份都在**，而 **40 > 10** ——
**用户看到的永远是底座那份，我改的永远是 DOM 那份。**

### 这解释了几个一直说不通的现象

* 「位置没有一次有变化」—— 因为变化全落在 `z-index:10` 那一层；
* 「两个方向都偏」—— 底座那份与我改的那份**是两套独立排版**，各自有各自的特征偏移；
* 「说不清偏多少」—— 我看的是 DOM 那份的数字，用户看的是底座那份的画面。

### ⚠️ 我前几轮的验证为什么全都"绿"

我跑的是：

```js
getElements(idx, t)[0].yPct === 47      // ✓
```

这只证明 **DOM 那一份算对了**，而那一份**用户根本看不见**。
「判据绿」在这里是**完全误导**的 —— 它测的东西与被抱怨的东西不是同一个。

---

## 二、正确的做法（二选一，**不能都画**）

### A. DOM 模式才画 DOM 文字（推荐，改动最小）

`.text-layer` 加 `v-if="!dhampirMode"`。
⇒ 一个时刻只有一份文字，**谁在画就是谁的位置**，我改 DOM 那份即刻可见。
⚠️ 代价：Dhampir 模式下的文字位置就**完全归底座**，DOM 那份的修复在那种模式下不生效
（但也不再**假装**生效）。

### B. 让 DOM 那份压到底座之上（改动大、风险高）

把 `.text-layer` 提到 `z-index > 40`。
⚠️ 不行：底座画的那份**还在下面**，会变成"重影/错位的双层字"，
而两套排版的差**恰好就是用户抱怨的那个偏移** —— 叠起来只会更糟。

⇒ **A 是唯一合理的**。⛔ 别选 B。

---

## 三、这条对「排版 / 逐字 / 描边」同样成立

用户另外三条（**厚描边 / 排版逐字 / 心跳**）我全都在改 **DOM 那一份**。
按同一条逻辑：**如果 Dhampir 模式下底座也在画，那三条同样"改了看不见"。**

⚠️ 需要逐条确认底座那边**画不画**：

| 那条 | 底座是否也画 | 依据（**已核实**，不是推测） |
|---|---|---|
| 位置 | **是** | `layout_text_elements` 写 `x`/`y`，转译器落成 ASS 的 `\pos` |
| 描边 | **是** | ASS `Outline` 四档 `3/2.5/1/2`（真产物实测） |
| 竖排（`vtext`） | **是** | 转译器 `case 'element'` 已把样式落成 `SubtitleStyle` |
| 逐字（`perchar_*`） | **是** | 底座有 `dhampir-timeline/src/text_perchar_anim.rs`（**6 个 `pub fn`**，实测） |
| 心跳（`heartbeat`） | **否** | 全底座搜 `heartbeat` ⇒ **0 命中**（实测）⇒ 底座**不画**，需求书写在 `docs/plan/dhampir-heartbeat-request.md` |
| `arc` | 两边都做不出真弧 | 见 `docs/anim/README.md` |

⚠️ **`heartbeat` 这一格很关键**：底座**不画**它 ⇒ **DOM 那份是唯一可见的**
⇒ **不能一律把 DOM 文字层关掉**（方案 A 要按档位来，不是整个 `.text-layer` 一刀切）。
⇒ 正确做法是**逐条判断"这一档底座画不画"**，只关掉**两边都画**的那些。

---

## 四、我要向用户确认的一件事（这次问对）

**贴纸与文字元素，你是看 Dhampir 预览（默认那个）还是 DOM 预览？**

* 如果是 **Dhampir 预览** ⇒ 我这些轮改的 DOM 层**你一次都看不见**，
  应该走方案 A（或直接在底座侧做）；
* 如果你**关掉过** Dhampir ⇒ 那才有第二个偏移源，要继续查。

⚠️ 这正是我早该问的。前几轮我问的是"偏哪个方向""跑没跑 process"，
**全是关于算法的**；而真问题是**"你看的是哪一层"**。
