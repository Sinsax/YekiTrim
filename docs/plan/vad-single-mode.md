# VAD 优化 SenseVoice 单模型（2026-09）

**目标**：single 模式先用 VAD 只解码"真有人说话"的区间，把转写墙钟降下来，
**字幕效果与原来的单模型输出对齐**（覆盖率不退化）——为服务端跑转写做铺垫
（hybrid 那份 qwen3 的成本是另一件事，见文末「没做的事」）。

## 结论（184 分钟真实录播实测）

| | VAD 关（原口径） | VAD 开 | |
|---|---|---|---|
| 墙钟（debug 构建，同机同素材） | **195.6s** | **83.7s** | **2.34×** |
| SenseVoice 解码音频量 | 13256s（= 音频 × 1.2） | 6515s（2.03× 更少） | |
| VAD 自身开销 | — | 22.0s（4 路并行） | 串行要 61s，所以必须并行 |
| 字幕段数 / 字数 | 1635 / 15119 | 1914 / 17219 | 多出的是唱段 |
| 30s 窗口"两版都有文本" | — | 345（**0 个窗口整块丢失**） | |
| 2s 栅格覆盖 | 3430 格有字 | 少 94 格（off 侧的 2.74%） | 残余损失 |
| 同一窗口文本一致度 | — | 中位 71.4%（同模型不同切块，字符级必然有差） | |

- **残余损失**：13 个 10s 箱的内容在 VAD 版里没有——9 处是 VAD 判成非语音的短促插话
  （"好冷啊空调关""哪有啊"），4 处落在语音区间内但那段太短、SenseVoice 没吐字。
  提高 `vad_rescue_db`（8 → 16）能把前一类捞回大半，代价只有 +1.6% 解码量。
- **新增内容**：137~154 个 10s 箱在 VAD 版里有字而基线没有，看内容是**唱段/歌词**
  （"我的脸庞""万世千秋求知求爱""妈妈妈妈啦"）。原因不是幻觉：固定分块把音乐和话音
  揉进同一个 60s 块，模型对整块只吐很少的字；按语音岛单独解码时唱段被正常转出来了。

## 怎么做的

`crates/vtrim-core/src/asr/vad.rs` + `local.rs::plan_vad_windows`：

1. **silero VAD**（`silero_vad.int8.onnx`，209KB，k2-fsa 导出）扫一遍音频，拿语音区间；
2. **合并近邻**（≤0.8s）→ **两侧各放 0.2s 保护余量** → **动态电平兜底**；
3. 区间 → **解码窗口**：`decode` 区间可含余量、`claim` 区间（token 归属）半开不重叠；
   超过一个 `chunk_duration` 的连续语音按**与固定分块同一套步进**切开；
4. 交给原来的 4 路并行解码循环（`RawChunk` / 时间轴 / 断句一个字都没改）。

三条**踩过的坑**（都在代码注释里）：

- ⚠️ **喂给 VAD 的块必须是一次窗口（512 采样）**。上游 `voice-activity-detector.cc` 的
  循环是"先把这批窗口全 push、再看这批有没有语音"，段边界按**这批结束时**的
  `buffer_.Tail()` 反推。喂 4 秒一块时，段边界会被量化到 4 秒——实测合成音频
  （真语音 20.75~25.59s）被报成 23.69~31.50s，**换模型、换阈值都不变**，因为那是块边界
  说了算。上游源码里 `NOTE(fangjun): Please don't use a very large n.` 说的就是这件事。
- ⚠️ **分块并行必须把时间戳加回块偏移**。`detect_speech` 报的是相对**喂入起点**的时间；
  忘了加回，第 2 块之后的段全落在 `[0, feed_len]`、与第 1 块大段重叠，
  一合并就整片消失（实测 1410 段塌成 79 段、覆盖掉到 24%）。
- ⚠️ **VAD 失败一律回退固定分块**（模型没下、判定异常），绝不让转写停在半路——
  退化成老口径就是"效果对齐"的底线。

## 动态电平兜底（参考精修字幕那套响度口径）

精修字幕按 `ebur128` 响度曲线实时跟随音量；这里同样**按这一场自己的电平**判断，
而不是固定 dB 门限（不同增益的录播都能用同一套参数）：

- 先量逐帧 RMS（20ms 帧，一遍扫描）；
- 本片语音电平 = VAD 判为语音的那些帧的 **75 分位**（实测这一场 -20.4dB）；
- `floor = 语音电平 − vad_rescue_db`（默认 **16dB**）；连响 ≥0.5s 且高于 floor 的空档
  **一律捞回来解码**。

关键性质：**兜底只做加法**，永远只多解码、不会少解码。所以它的失效方向是
"退化成固定分块"（省不到时间），而不是"字幕少一条"。

## 配置

```toml
[asr]
vad = true              # 仅 single 模式生效；Option<bool>，显式写了才覆盖全局
vad_threshold = 0.5     # silero 概率阈值：调高 = 更保守（多解码、少省时间）
vad_rescue_db = 16.0    # 动态电平兜底，0 = 关掉兜底
```

模型随 `vtrim download` 一起下（`<模型根>/silero-vad/silero_vad.int8.onnx`，209KB），
转写前 `ensure_models` 也会确保它在位（失败只告警，回退固定分块）。

## 诊断/复测

```bash
# 只跑 VAD（不跑 ASR）：覆盖多少、兜底捞回多少、各档阈值对比、VAD 用时
VT_ASR_WAV=<wav> VT_VAD_MODEL_DIR=<models 根> \
  cargo test -p vtrim-core --lib diagnose_vad_regions -- --ignored --nocapture
# 还能 VT_VAD_DUMP=<json> 把区间倒出来，跟已知正确的字幕时间戳对齐核对

# VAD 自身正确性（合成音频：20s 静音 + 真语音 + 20s 静音）
VT_VAD_MODEL_DIR=<models 根> \
  cargo test -p vtrim-core --lib diagnose_vad_synthetic -- --ignored --nocapture

# 端到端 A/B（跑真转写）：工程 vtrim.toml 里改 `[asr] vad = false/true`，各跑一遍对比
vtrim -c <工程>/vtrim.toml transcribe
```

## 没做的事

- **hybrid 没接 VAD**：它的时间几乎全在 qwen3（实测 3 小时素材 12.4 min vs 打轴 2.5 min），
  VAD 只能省打轴那一小段（约 10%）；而且 VAD 会把语音切得更碎、qwen3 窗口数变多。
  要提速得先动 qwen3（模型替换 / 标点模型替代，见上一轮分析）。
- **没做 VAD 的"多实例并行"**：现在是"按块并行、每块一个 detector"（块数 = worker 数），
  已够用；真要再多路，注意块首状态是冷的，接缝余量别小于 1s。
