# 底座文字能力的根因：为什么"HTML 能做、底座做不到"

> 2026-10-12。起因是一个质疑：**"缺字不变方框多做一个判断就行了吧？libass 的代价是不是太大？"**
> 结论：**这个质疑成立**。但真正的代价不在"缺字回退"上，而是另一件没被写下来的事。

---

## 〇、先纠正一个前提

libass 换来的**不只是**"缺字回退"。文档（`text_raster.rs` 头注释）里明确列了它同时解决的：

| libass 带来的 | 说明 |
|---|---|
| **逐字形字体回退** | 你说的那一条 —— 缺字换另一副字体补上 |
| **`%` 不用转义** | `drawtext` 要 `expansion=none`，一个散落的 `%` 直接报错；libass 拿的是 SRT 内容，`%` 就是普通字符 |
| **非 ASCII 字体文件名** | `drawtext` 的 `fontfile=` 遇到中文文件名会**静默画不出来**；libass 按**家族名**找字体 |

所以"多做一个判断"只覆盖了第一条。第二条（`%`）和第三条（中文文件名）都是**真实的、踩过的坑**，
各自也需要一次处理。

**但这仍然不足以证明 libass 划算** —— 因为后两条同样"多做一个判断"就能解决
（`expansion=none` 本来就写了；中文文件名可以改走 `fontconfig` 或先复制成 ASCII 名）。
**所以你的直觉方向是对的：这三条加起来，也撑不起"放弃逐字控制权"这么大的代价。**

---

## 一、真正的代价（文档里没明说，但架构上是硬约束）

### 1.1 根因：libass 是**进程外的黑盒**，且只吐回一张位图

底座的文字路径：

```
生成 SRT 文本 → 起 ffmpeg（subtitles 滤镜 → libass）→ 拿回一张 RGBA8 位图 → 自己 tint 上色
```

⚠️ 关键：**libass 把一整行栅格化成一张位图还给你**。底座拿到的是"一个整体"，
**不是"每个字的位置/包围盒/变换"**。

于是逐字效果做不到 —— 不是"没实现"，是**信息在这一步就丢了**。

### 1.2 更麻烦的：颜色和描边还得靠"白墨"反解

文档里这一段是同类问题里最尖锐的：

> libass 输出的是**已合成**的颜色、且 alpha 恒为 0：黑描边的像素是 `(0,0,0,0)`，
> 与"完全透明的背景"**逐字节相同**（实测一张 640×90 的图里 56806 个 `(0,0,0,0)`），
> 覆盖度**数学上恢复不出来**。两处都画白墨，覆盖度才回得来。

⇒ 也就是说，**为了让底座能自己染色，必须骗 libass"全画白色"**，然后从 RGB 反推覆盖度
（`coverage_from_libass`）。这是一个**绕路**，而且它意味着：
**一旦 libass 那边多画任何东西（比如真正的颜色、阴影），覆盖度就恢复不出来。**

### 1.3 副作用：每一次 ffmpeg 进程调用

文档还提到缓存问题：

> 一条字幕在 30fps 下要在几十帧上出现……不缓存就是每条字幕几十次 ffmpeg 进程。
> **位图尺寸是键的一部分**

⇒ 每一条**不同的**字幕（文本/字号/描边/字体/尺寸任一变化）都要起一次 ffmpeg。
这对"逐字动画"是致命的 —— 逐字效果意味着**每一帧文字都不一样**，
按这个缓存键就是**每帧一次 ffmpeg 进程**。

### 1.4 精度：字宽是**估算模型**，不是真实度量

底座自己有一层布局（`dhampir-timeline/src/text_layout.rs`），字宽是**模型**：

```rust
/// 一段文本的前进宽度（em）。**不计换行** —— 调用方先按行切开。
pub fn measure_em(text: &str) -> f32 {
    text.chars().map(advance_em).sum()
}
```

全角 1em / 半角 0.5em。文档自己承认这是**已知残差**：

> 参照的 `pw` 是 **canvas 量出来的真实字宽** —— 量字与画字同一个引擎。
> 而这里……偏移用**布局的逻辑字宽**（`measure_em`）累加。
> 影响：全角字（中文）逻辑宽与实际推进一致，**偏移是准的**；
> 中英混排时英文半角的逻辑宽是估算值，**偏移会差几像素**。

⚠️ 这一条很关键：**要逐字变换，就必须知道每个字在哪儿**。
而底座现在**连每个字的确切宽度都是估算的** —— 因为"量字"和"画字"是**两个引擎**
（模型 vs libass/FreeType）。参照实现里这两个是同一个（canvas 既量也画）。

## 二、所以真正的取舍是什么

| | 参照实现（HTML + GSAP） | 底座（libass） |
|---|---|---|
| 文字模型 | **逐字 DOM 元素** | **一行一张位图** |
| 量字与画字 | **同一引擎**（canvas） | **两个**（em 模型 / FreeType） |
| 逐字变换 | 免费 | **信息已丢，做不到** |
| 缺字 | 变方框 | **逐字形回退** |
| `%` | 无所谓 | 不用转义 |
| 中文文件名 | 无所谓 | 按家族名找，没问题 |
| 每帧成本 | 浏览器合成 | **每张新位图一次 ffmpeg** |

**结论：libass 真正买到的，是"缺字回退 + `%` + 文件名"这三条工程健壮性；
真正卖掉的，是"逐字控制权 + 度量精度 + 每帧成本"。**

你的判断成立：**这三条工程健壮性，撑不起"永久放弃逐字表现力"这个代价** ——
尤其当"文字元素"的定位本来就是**贴纸**（要表现力），而不是"字幕"（求准确）。

---

## 三、出路：把两条路拆开，而不是二选一

底座现在用一条路（libass）同时服务两种需求相反的东西：

| | 字幕 | 文字元素 |
|---|---|---|
| 求什么 | **准**（缺字、`%`、文件名都不能出岔子） | **炸**（逐字变换、竖排、圆角、倾斜） |
| 谁在用 | 语音转写的字幕轨 | 贴纸式的情绪文字 |
| 该走哪条 | **libass（保持现状）** | **自绘** |

### 3.1 自绘需要什么

底座**已经有一半了**：

| 已有 | 位置 |
|---|---|
| 布局层 + em 度量 | `dhampir-timeline/src/text_layout.rs`（`measure_em` / `advance_em` / `LINE_HEIGHT_EM`） |
| 逐段偏移绘制 | `dhampir-worker/src/text_overlay.rs::paint_parts`（`parts: &[TextRun]`） |
| 底衬矩形 + 圆角字段 | `PlateRect`（4×i32）；`Layer` 上**已有 `corner_radius`** |
| 逐帧合成 + 仿射变换 | wgpu 合成层；`TransformV2 { x, y, scale, rotation }` |

缺的是：**一个"逐字变换"的表达 + 让文字路径读 `transform`**。

### 3.2 关键洞察：`TextRun` 现在太小了

```rust
pub struct TextRun {
    pub text: String,
    pub color: [u8; 4],
}
```

**只有两个字段。** 而它是"逐段绘制"的输入 ——
把它扩成带 `dx/dy/rotate/scale/font_px` 的结构，逐字变换就有了表达位置。
这条路**不用换栅格化器**（字仍然是 libass 画的），缺的是：
- 每个字要**单独渲染一次**（于是回到"每帧一次 ffmpeg"的成本问题）
- 或者改成**自绘字形**（cosmic-text / swash），一次到位

## 四、我的建议（待你拍板，先不动手）

**不要整体替换 libass** —— 那会赔掉缺字回退，且所有老片子的像素再变一次。

**推荐分两步：**

**第一步（低成本，先验证价值）**：让文字路径读**已有**的 `TransformV2.rotation`。
字段现成，`text_overlay.rs` 现在完全不读它（grep 零命中）。
→ 解锁「倾斜 3 档」+「摇摆 3 档」，共 6 档，且**不碰栅格化器**。

**第二步（中等成本）**：把 `TextRun` 从 2 个字段扩到带逐字变换，
文字元素改走"逐字单独栅格化 + 自己摆放"。
→ 解锁逐字字号/旋转/位移（15 档样式）。代价是每帧 ffmpeg 成本，
需要用**同一句文本一次进程渲多个字**的方式摊掉。

**不建议**：现在动竖排（要重写折行，成本最高，且只有 3 档用到，都有替代）。

## 五、遗留判断

1. **每帧 ffmpeg 的成本能不能摊掉？** 逐字动画意味着每帧文字都不同。
   如果摊不掉，逐字动画（跳起/逐字弹出）就永远只能在 HTML 侧预览、成片降级。
2. **要不要把"文字元素"独立成一条轨类型？** 现在的文字轨既服务字幕又服务贴纸式文字
   —— 需求相反，共用一条路必然有一方吃亏。
3. **像素再变一次能不能接受？** 自绘会再改一次所有文字像素（像 0.2.0 换 libass 那样）。
   如果文字元素独立成轨，**旧工程走 libass 不变**，这条就能绕开。
