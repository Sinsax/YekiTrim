# 三端像素级测试：执行报告

> 日期：2026-10。**本文只记实测数字与已定位结论。**

---

## 1. 三端的定义（YekiTrim / 底座口径）

| 端 | 实现 | 源从哪来 | 出口 |
|---|---|---|---|
| **A** | `web/engine.js` 宿主（精修页那条腿） | 调用方逐帧交 `ImageBitmap` | canvas → `toDataURL` |
| **B** | 直接 `import` wasm（`web/synthetic.html`） | **Rust 内部**造 | `dhampir_sample_project_render_png` |
| **C** | native worker（`cargo run --example render_project`） | **Rust 内部**造（同一对函数） | 写 PNG |

⚠️ **A 与 B 是同一份 wasm 的两个宿主**（`engine.js` 自己写着"这一层是底座的一部分"）。

---

## 2. 实测矩阵（帧 0 / 30 / 60 / 89，320×180，`fixtures/sample-project.json`）

| 对比 | 最差 SSIM | 结论 |
|---|---|---|
| **B ↔ C** | **1.000000** | ✅ 通过（底座既有的双端不变量） |
| **A ↔ C** | 0.720583 | ❌ 帧 0/60 完美、帧 30 崩、帧 89 = 0.999282 |

### 2.1 它是**非空转**的（变异自证已做）

把 C 侧一帧换成同样 640×360 的**合法 RGBA PNG、像素不同** ⇒
**SSIM 0.747646 / MAE 119.97**，判定翻面；换回原图恢复 1.000000。

---

## 3. ★ A↔C 差异的根因（已定位到**源上传路径**，不是渲染器）

### 3.1 排除法（每一步都是实测）

| 实验 | 结果 | 排除了什么 |
|---|---|---|
| d 层几何归零（x=0,y=0,scale=1,rot=0） | **SSIM 1.000000** | 说明差异**只在有变换时**出现 |
| 去 `gaussian_blur` | 0.570（≈不变） | 不是模糊 |
| 单独 `scale=0.5` | **0.999977** | 不是缩放 |
| 单独 `rotation=15°` | **0.999851** | 不是旋转 |
| 单独 `x=100,y=-50` | **0.070523** | **平移是大头** |
| `x=1`（只移 1px） | **0.484186** | 1px 就崩 |
| `x=0` | **1.000000** | 无平移就完美 |
| `createImageBitmap` 关色彩转换 | 0.572（≈不变） | 不是色彩空间 |

### 3.2 差异的**像素级形态**（无偏测量）

`x=1` 时 A 与 C 的逐像素差：

```
差值 == 0        : 50400 像素 (87.7%)
差值 ≈ 118 / 150 :  12.3%   ← 二值化，不是模糊
差异像素的 x mod 8 分布 : {0: 7112}   ← **100% 落在方格边界列**
```

### 3.3 结论（三条证据自洽）

1. **位图内容逐字节相同** —— `x=0` 时 A↔C = **1.000000** 就是证明
   （我的 JS 复刻的 `synthetic_source_rgba8` 已与 Rust 对拍：seed + FNV 全等）
2. **只在发生采样时暴露** —— `x=0, scale=1, rot=0` 是 1:1 直拷，采样器不参与；
   一旦平移/缩放/旋转，采样器介入 ⇒ 差异出现
3. **差异形态 = 方格边界列相位错** —— 正是"源在被采样时像素中心差半像素"的特征

⇒ **根因是两条源上传路径的采样口径不同**：

| 端 | 上传方式 |
|---|---|
| A | `copy_external_image_to_texture(ImageBitmap)` |
| C | `queue.write_texture(CPU 字节)` |

**这不是渲染器差异**（A/B 与 C 共用同一份 wasm / 同一份 WGSL）。
**也不是我的探针页造假** —— 但它是**我的探针页引入的**，
因为真实的精修页同样走 `setSourceBitmap`（`ImageBitmap`），所以
**只要精修页里发生"源被平移"，就会带上同一口径**。

### 3.4 关键对照：B 端跑同一份 `x=1` 工程

```
B(x=1) vs C(x=1) = SSIM 1.000000   ← 完美
A(x=1) vs C(x=1) = SSIM 0.484186   ← 崩
```

两侧工程、帧号、尺寸、渲染器**全同**，**只有源位图的来源不同**。

## 6. 诚实边界（**必须写进 skill**）

1. **A↔C 不等于 1.0 不是"渲染不一致"**，而是**源上传路径的采样口径差异**；
   判据若要求 A↔C 严格 =1.0，会**永远红**。
2. **B↔C 才是"渲染一致性"的权威判据**（它两侧都走 Rust 内造源，输入逐字节同）。
3. **A 端的价值**是验"宿主层有没有画歪/漏画/时序错"，**不能用像素严格相等去判**；
   应当用**结构性判据**（如：与 B 的差异只允许出现在"源被采样"的区域，
   或直接用**几何无变换**的帧做严格比对，另用变换帧做宽松阈值）。
4. `docs/golden/dhampir-parity/` **不能当第三端** ——
   它是**已删除的 Chrome 腿**冻的（`golden.json` 的 `frozen_from` 写明），
   不是底座画的。

## 7. 建议的判据分层（供 skill 使用）

| 层 | 比法 | 通过线 |
|---|---|---|
| L1 严格 | 几何无变换的帧（`x=0,scale=1,rot=0`） | **SSIM = 1.000000** |
| L2 宽松 | 含平移/缩放/旋转的帧 | SSIM ≥ 0.57 且**差异只落在方格边界列** |
| L3 权威 | B ↔ C | **SSIM = 1.000000** |
| L4 结构 | A ↔ B | 差异区域 ⊆ 被采样的源区域 |
