
⚠️⚠️ **这里有一条我自己抓出来的判据漏洞，必须留档**：

## 三、①-④ 的根因：**改错了层**（本轮最重要的发现）

```
.dhampir-canvas   z-index: 40   ← 底座画的（用户一直看的）
.overlay-space    z-index: 10   ← 我改的（一直被盖住）
```

**文字元素被画了两遍**，而 `40 > 10` ⇒ **用户看到的永远是底座那份，我改的永远是 DOM 那份。**

用户已确认：**「一直用 Dhampir 预览（默认）」** ⇒ **前四轮我改的东西，用户一次都没看到。**

### 3.1 哪些档归底座（实测，不是推测）

| 那条 | 底座画不画 | 依据 |
|---|---|---|
| 位置 | **画** | 转译器落 `doc.json`；底座 `text_layout.rs` + `text_overlay.rs::paint()` |
| 描边 | **画** | 同上 |
| 竖排 `vtext` | **画** | 转译器 `case 'element'` 落成轨级样式 |
| 逐字 `perchar_*` | **画** | 底座有 `text_perchar.rs` **与** `text_perchar_anim.rs` |
| 动效 | **画** | 底座有 `text_motion.rs` |
| **心跳 `heartbeat`** | **不画** | 全底座搜 `heartbeat` ⇒ **0 命中** |
| `arc` 真弧 | 两边都做不出 | 见 `docs/anim/README.md` |

⚠️ **一处我自己写错又改正的依据**：第一版写的是「底座读 ASS 的 `\pos` / `Outline`」——
**不对**。转译器 `tools/polish-to-dhampir.mjs:6746` 写明：

> 出片走的是 `doc.json` 这条 —— 底座自己光栅化文字（`text_overlay.rs`），**根本不读那个 ASS**。

⇒ ASS 是**侧挂产物**。按错的依据去底座侧改，会改到**没人读的那份文件**上。
（这就是为什么下面§五必须先定"在哪边做"再动手。）

### 3.2 门控之后的新状态（`629e62a`）

`.text-layer` **按档位**门控（不是一刀切）：`DHAMPIR_NO_DRAW = {heartbeat, shake}`。

| 档位 | 谁在画（Dhampir 模式）| 我这几轮的修复 |
|---|---|---|
| 位置 / 描边 / 竖排 / 逐字 | **底座** | ❌ **用户仍然看不到** |
| **心跳 / 抖动** | DOM 层 | ✅ 就是我改的那份 |

⚠️ **为什么不能一刀切关掉**：底座**不画**心跳 ⇒ DOM 是它**唯一的可见实现**，
关掉会让"上一轮刚修好的心跳"重新消失。

## 四、⑤ 贴纸：真根因（已修，待验收）

### 4.1 根因

用户的工程用 `type="element" kind="sticker"`，而：

* `stickersAt`（模板唯一数据源）**只读 `idx.sticker`** ⇒ **一条都求不出来**；
* `getElements` 收了，却产出**没有 `x`/`y`** 的形状（模板读 `st.x`/`st.y`）⇒ 也到不了画面；
* **⇒ 两半各拿一半，缝里就是"贴纸设置了、预览里不显示"，且不报错。**

⚠️ 还有**第三处**：那段贴纸求值里写的是 `(idx.stickerSrc || (() => ''))(...)`，
而 **`idx` 上从来没有 `stickerSrc`** ⇒ 那个兜底**恒生效**、`src` **恒为空串** ——
**一个恒真的兜底，它让前两处的修复看起来无效**。

### 4.2 全量格式调查（扫 `E:\media` 全部工程）

| 写法 | 片段数 | 状态 |
|---|---|---|
| `type="sticker"`（老写法）| 28 | 正常 |
| `element + kind="sticker"` | **1** | **就是坏的那条** |

⇒ 这解释了为什么我前几轮"无法复现"：**我拿老写法试的，而坏的是新写法。**

### 4.3 验证（用户那条真实事件）

```
改前：✗ 空（两种模式）
改后：manual → x=800.8  y=395.5  src=".../PNGTuber_加载中.gif"
      auto   → x=960.0  y=524.7
```

`x=800.8` 与手算 `940.8 − 140` **逐位相等**；y 差 15px = 稳态上浮（预期）。
**零回归**：老写法 `x=800.8 y=392.8` 前后**一位没变**。
素材确实存在：`target/debug/users/1/resources/stickers/ysyk/PNGTuber_加载中.gif`。

重启服务端 → 打开该片段 → 看 **10.81s ~ 12.81s**。
三种结果对应不同下一步：

## 五、待决策（用户定，我不替选）

### 决策 1：①-④ 在哪边做？

| 选项 | 代价 |
|---|---|
| **(i) 改底座（Dhampir）** | 本仓只做转译与对齐。**仓内既定方向**，但**跨仓、周期长** |
| **(ii) 让 DOM 接管，底座别画** | 要先查底座**能不能不画文字元素**；能则一个时刻一份且归本仓控制，不能就要提需求 |
| **(iii) 先停，只推贴纸** | 先看贴纸结果再定 |

⛔ **不要两者都画** —— 那就是现在这个 bug。
⛔ **方案 B（把 `.text-layer` 提到 `z-index > 40`）已否决**：底座那份**还在下面**，
会变成**错位双层字**，而两套排版的差**恰好就是用户抱怨的那个偏移** —— 只会更糟。

### 决策 2：泳道 7 → 8 条（+26px）

卡上明写「布局必须保持紧凑：泳道 26px ×7 + 标尺 20px = **202px**」。
现在 **8×26+20 = 228px**。总高 `flex:1` **不是写死的，不会破版**，但与卡上口径不一致。

1. **就 +26px**（现状）—— 一行泳道换掉一个多余菜单；
2. **两块并排画在同一行高度里** —— ⚠️ 要改 `laneBlocks` 的 `width`/`left`（两块会重叠），**不是小改**；
3. **缩到 23px** —— ⚠️ 会动 `WAVE_H` 与波形 SVG，而波形动态范围**本来只有 6.6px，会更小**。

### 决策 3：`arc` 真弧

需要底座新增 `rotation_spread` 原语（`rotation_deg = mix(from,to)` 没有 `rank` 项）。
需求书：`docs/plan/dhampir-rotation-spread-request.md`。

## 六、这一轮的教训（写给下一个接手的人）

1. **⚠️ 别再"编夹具 → 跑纯函数 → 报绿"。** 前四轮我拿自己造的夹具算出
   `yPct === 47` 就报"修好了"—— **那测的根本不是用户看的东西**。
   改成**先去用户的真实工程里看**之后，5 分钟就复现了贴纸（前几轮"无法复现"）。
2. **⚠️ "判据绿"和"代码在"都不是证据。** 用户说得对。
   判据必须能回答"**用户看不看得见**"，而不是"我的函数算得对不对"。
3. **⚠️ 图层栈要先查。** 任何"改了没反应"先问：**用户看的是哪一层？**
   （`z-index` 表在 `docs/plan/why-position-changes-were-invisible-2026-10-14.md`）
4. **⚠️ 行为判据抓不住结构倒退。** 分家之后，把两个桶重新接起来**行为完全一样**
   （多读的那个桶贡献 0 条）—— 这类倒退**只能查源码**。
5. **⚠️ 假阳性比不判还坏。** 我写错过一版"不许出现 `kind`"，
   而 `getElements` **合法地**读 `kind`（判 `kind === 'text'` 是它唯一入口）——
   那种判据会逼人删掉合法代码。
6. **⚠️ 变异锚点会过时。** 源码形状一变，`replace` 找不到东西 ⇒ 变异**静默失效** ⇒
   判据不翻面而脚本照旧"通过"。症状是**变异不生效**，不是"找不到锚点"。
