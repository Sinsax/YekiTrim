# §18-A LLM 取样报告：`zoom = "特写"` 产出率

> 命题：**"LLM 真会产出 `zoom=\"特写\"`"**。
> ⚠️ 与另两条**不同命题**，勿混：① 消费侧支持 1.8（像素证明已过）
> ② 提示词接线完好（单测 + 4/4 变异已过）。本条只回答"**LLM 走不走进那扇门**"。

## 结论：**PASS 3/3**

| 次 | 耗时 | `zoom` 总数 | **`特写`** | 判定 |
|---|---|---|---|---|
| run1 | 10s | 21 | **4** | ✅ |
| run2 | 10s | 16 | **2** | ✅ |
| run3 | 10s | 19 | **3** | ✅ |

**PASS 标准（跑前定死，不事后挑）**：3/3 每次 ≥1 条 `特写`；任一次 0 条即整体 FAIL。
⇒ **三次全过，且带自然波动（4/2/3）** ⇒ 是真采样，不是冻结值。

### 基线对比（批0.1，改动前）
```
zoom 列总计 20/19/21；zoom="特写" = 0/0/0
```
⚠️ 改动前的 0 **不是"少"而是"不可能"** —— 词根本不在枚枚举里。

### 分布的完整形状（三次各不同 ⇒ 真随机性）
```
run1: 远1 中8 近8 特写4
run2: 远1 中8 近5 特写2
run3: 远1 中6 近9 特写3
```
★ `远` 三次都是 **1**，`中` 稳定在 6~8 —— **新档位没有挤掉旧档位**（§18-A 的顾虑之一）。

## ★ 端到端（不止"写进 TOML"）
光"TOML 里有这个词"不算数 —— 还得看**消费侧认不认**：
```
process 后：特写 3 条**仍在**，且每条 anchor 都被守成 "liver"
日志：🎯 运镜锚点已解析 21 个
```
⇒ **特写事件走完了 `polish llm → process`**，且 `cap_closeup_anchor` 焦点守卫生效
（LLM 按提示词写了 `anchor`，守卫确认它合法）。
⇒ **这不是"只写进配置文件"的空头数字。**

## ★ 一个必须交代的方法论事故（我差点交付假结果）
**第一次取样我跑错了命令** —— 用的是 `polish process` 而不是 **`polish llm`**：
```
polish process：后处理（解析 emoji/keyword、下载资源、计算位置）—— **不调 LLM**
polish llm    ：LLM 分析生成 segments 和关键词  ← 真调 LLM 的是这条
```
`polish process` 只是把**已有的** `polish.toml` 重新规范化，所以：
- 三次"结果"是 `特写 = 0/0/0`，看着像 **FAIL**
- **耗时 1s**、且 zoom 分布三次**完全相同**（8 中/12 近/1 远）

★ **抓出它的是一致性本身**：真 LLM 采样**不可能**三次逐字节同分布，也不可能 1 秒跑完。
⇒ **如果我只跑一次、或者没看耗时，我会交付一个"提示词修了没用"的假结论。**
⚠️ **教训**：**"命令跑成功了"不等于"命令做了那件事"** ——
`exit 0` + 产物存在 + 数值合理，**三个都对，而整件事是错的。**
**唯一识破它的是"耗时 1s"这个与"LLM 调用"常识矛盾的旁证。**

## 复现
```bash
# 每次都必须删 checkpoint，否则续传会把 3 次变成 1 次

```
