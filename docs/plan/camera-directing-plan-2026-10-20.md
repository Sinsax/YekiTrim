# 运镜导演化方案（2026-10-20）

> 用户口径：「除了 10 以外都可以做，**记录下来然后开展**」（10 = 速度线贴纸，另议）。
> 背景：用户看 `clip-15` 觉得「**太平行、少内容**」；实测内容事件 **0.13/s**、camera 占 **57%**、段1 **14s 零内容事件**。
> 结论：camera 现在只是"每段补一个中景"的**底噪**，不承担叙事 —— 本方案把它变成**手法**。

## 零、边界（先说清哪些不归本仓）

| 项 | 为什么不在本仓 |
|---|---|
| **⑪ 方向性/运动模糊（真 whip pan）** | 要底座新原语（C 层，`docs/plan/camera-vfx-editing-catalogue.md` §1.5）。**只记录，不实施**；等底座的"方向性模糊"落地后再接。 |
| ⑩ 速度线贴纸（流背） | 用户本轮明确排除（要 5 张素材）。留位。 |

## 一、五项零成本（本仓 `process` 侧，确定性、幂等）

### ① 爆点驱动景别 ⭐
**做什么**：景别不再"每段一个中景"，而是按**热度曲线**分配 —— 峰值段 ⇒ `近`/`特写`，平缓段 ⇒ `全`/`中`。
**信号**：`popularity` / 弹幕密度（`polish/heat.js` 同一口径，后端已有 `DanmakuStyle` 统计）；**不用 LLM**。
**判据**：同一工程两次 `process` 出来的景别序列**逐值相同**（确定性）；峰值段的景别严格大于同工程均值段；
**变异自证**：把热度输入打平 ⇒ 景别回落到"全部默认档"。

### ② 句读级微推（Ken Burns）
**做什么**：段内每 **3–6 秒**（按字幕句读切）加一次**极轻**的推近/拉远（`1.0 ↔ 1.06`），交替方向，避免单调。
**判据**：>6s 的静止窗口数 = **0**；相邻两次方向必须相反（同向连续 ≤2 次）；幂等。
**注意**：强度要小 —— 1.06 在 1080p 上是 ~57px，肉眼可见但不"动"。

### ③ 切镜必须"变化一个维度"
**做什么**：任何 `cut:true` 的运镜，必须至少改变**景别**或**锚点**之一；否则把 `cut` 去掉（退回平滑）。
**判据**：全片 `cut` 事件里"零变化"的数量 = 0；**变异自证**：构造一条"切了但什么都没变"的事件 ⇒ 必须被降级。

### ④ 运镜与音效同步
**做什么**：运镜**起点**（硬切或 snap）配一声 whoosh/riser（走既有 `sfx` 规则引擎与预算）；`slow`/`med` 不配。
**判据**：每个 `cut`/`snap` 事件 0.3s 内存在一条 sfx；不占用"字幕命中规则"的预算（或明确共享并说明）。

### ⑤ 段首段尾的"呼吸"
**做什么**：段首 0.2s 从上一镜平滑接（非硬切）、段尾 0.3s 微微拉远收束。**只在段边界**，段中不动。
**判据**：段边界处出现"平滑过渡"的比例 ≥90%；段中不出现额外运镜（幂等）。

### ⑨ 竖素材不再整条屏蔽运镜
**做什么**：竖素材现状是**整个运镜屏蔽**。改成**纵向推拉 + 上下位移**（不做横摇，因为竖屏横摇必露边）。
**判据**：竖素材工程的运镜事件数 > 0 且**只含纵向变化**；横素材行为**一个字节不变**（R4）。

## 二、两项 prompt 侧（`llm/segment.rs`）

### ⑥ 正反打 / 反应镜头"命名化"
**现状**：主播↔弹幕的来回切**已经在做**，但 prompt 里没名字 ⇒ 模型不会刻意用。
**做什么**：给手法起名（「正反打」）、给使用时机（对话/反应）、给配额（每段 ≤2 次）。

### ⑦ 话题切换用"换镜头"（回应"摇镜转场"的提议）
**做什么**：**段边界**（= 话题切换）优先用 `cut` + **景别跳档**（如 `全 → 特写`），而不是平移。
**理由**：平移会露边（目录 §0.3 实测 622px）、且没有方向模糊就不像甩镜；而"换镜头"是硬切的原生能力。
**判据**：段边界处 `cut` 的景别跳档率 ≥ 60%（prompt 契约用例）。

## 三、一项配置放宽

### ⑧ 画中画：从"整片 1 条"改为"每段 1 条、全片 ≤3"，并规定用途
**现状**：`MAX_PIP_SHOTS = 1`，且只当"拉远"用。
**改**：配额放宽 + prompt 里规定**只在同屏有两个信息源时**用（对比/揭穿）。
**判据**：`cap_pip_shots` 的用例改成新配额；同段两条仍被降级（保持互斥）。

## 四、验收总口径

拿 `clip-15` 的**临时副本**跑 `process`，对比：

| 指标 | 现在 | 目标 |
|---|---|---|
| 内容事件密度 | 0.13/s | ≥0.35/s（`task-46` 负责） |
| 最长静止窗口（运镜无变化） | 14.0s | **≤6s**（②） |
| camera 占比 | 57% | ≤40%（①+`task-46`） |
| "零变化"的 cut | 未统计 | **0**（③） |
| 段边界平滑过渡比例 | 0 | **≥90%**（⑤） |
| 竖素材运镜事件数 | 0 | **>0 且只纵向**（⑨） |

外加：`diagnose_process_idempotent`（字段级 diff = 0）与三次运行收敛必须绿；每项都有**变异自证**。

## 五、依赖与顺序

1. **先等 `task-47`**（景别改档：特写 2.0 + 新增「全」=1.0 作默认）落地 —— ①的"平缓段用全/中"依赖新档位；
2. 再分两条并行：**process 侧 ①②③④⑤⑨**（不碰 prompt）、**prompt 侧 ⑥⑦**；⑧ 与 ⑧ 的配额改动并入 process 侧；
3. ⑪ 单独挂"待底座"清单，不在本方案范围。
