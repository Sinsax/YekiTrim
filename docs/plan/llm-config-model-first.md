# LLM 配置：三层收成两层（模型优先）

> 状态：**M1 已落地**（2026-11-27，`webui/src` + `dist` 已改并重建）。M2/M3 仍待做。
> 落地时的实际改动与判据同步见文末 §9。
> 触发：用户「首先分接口-模型-链路的模型选择。还是说有更简化的方案，当前的交互逻辑都有点不太合理。先整合和重新设计一套方案」。
> 参考稿：`docs/web-ui-mockups/llm-config-demos/model-first.html`（可交互）。
> 前序：`docs/plan/llm-config-refactor.md`（D1–D6 已拍板）、`docs/plan/llm-chain-standardization.md`。

## 0. 一句话

**把「接口 + 模型」绑成一个原子实体（模型），链路只指向它。**
字段仍然分开存，但语义合一 —— 非法组合在结构上不存在，页面从「模型配置 / 链路配置」两个子页收成**一页**。

## 1. 证据：为什么现在"不太合理"

### 1.1 三个字段各自可写，靠用户配对

`llm.toml` 里能独立写的三样东西：

| 位置 | 写的是什么 | 界面入口 |
|---|---|---|
| `[[llm.providers]]` | 怎么连（协议 / 地址 / 密钥） | 左栏「接口清单」 |
| `[[llm.models]]` | 有哪些模型、属谁（**主键 = (接口, id)**） | 右栏「模型清单」 |
| `[llm.links.<link>]` 的 `provider` + `model` | 这条任务用谁 | 链路表**两列独立下拉** |

### 1.2 解析是**两条独立线**

`crates/yekitrim-core/src/config/llm_v4.rs`：

- `provider_for(link)`（:303）= 链路写了 `provider` 就用它（认不出回落 `active`），没写就用 `active`；
- `model_for(link)`（:313）= 链路写了 `model` 就用它 → 否则**该接口的默认模型** → 否则**该接口清单里的第一条** → 否则空。

两者**互不参照**。于是「接口 = cheap、模型 = deepseek-chat」这种组合在文件里完全合法。

### 1.3 运行时才把它们配成一对

`materialize()`（:824-831）：把 `active` 设成该链路的接口、把`provider.model` 设成该链路的模型 ——
**"配对"这件事是在执行前一刻完成的，而配对所需的两半是用户分别填的。**

### 1.4 漏了没有任何兜底

`problems()`（:391）查的是：接口 id 空/重复、协议认不出、没有任何接口、`active` 悬空、
清单 `(接口, id)` 重复、清单 `provider` 认不出、`run` 的 0 值提示 ——
**不查 `link.model` 是否属于 `link.provider`**。

所以这条规则只能住在界面里（`components/AGENTS.md` 写着链路表要「选了别家的当场标黄（`modelMismatch`）」）。
一条**正确性规则**只有前端一份实现，CLI / 直接改 toml 的用户拿不到任何提示。

### 1.5 顺带两处"看不懂"的地方

- `model_for` 的回落会**静默**用"接口默认模型"甚至"清单第一条" ⇒ 界面上"我没选模型"和"我选了"可能发出同一支请求，用户无从分辨。
- 主键是 `(接口, id)` ⇒ 同名的两支模型（官方 `gpt-4o` 与代理 `gpt-4o`）必须**靠接口区分**，而界面上模型清单是按接口分栏的 —— 换个接口就看不到另一边。

### 1.6 结论

> 现在要求用户做的，是**在两个任意组合的下拉里手工配对**，而这个配对唯一合法、且漏了没人管。

这不是"排版潦草"，是**概念多了一层**。

## 2. 更简的方案

### 2.1 概念表

| 概念 | 是什么 | 用户要不要管 |
|---|---|---|
| **接口**（provider） | 地址 + 密钥 + 协议 | **不管**。只在"添加模型"和"修密钥"时出现 |
| **模型** | 接口 + 模型 id + 能力 + 额外参数 | **主实体**，加一次就够 |
| **任务**（link） | 检测 / 精修 / 标题 / 工具 | 每行选一支模型 |
| **默认模型** | 其余任务的基准 | 一行 |

判据一句话：**能在界面上被"选中"的东西只有模型**。接口是模型的属性，任务是指向模型的引用。

### 2.2 与"再简一档"的比较

还有一档更狠的简化：**只保留一支当前模型，全部任务共用**（= 四套方案里的 B）。不选它的理由：
D1 已拍板"检测用便宜、精修用贵的"是刚需，取消按任务分配等于砍功能。本方案保留了这个能力，
但把它的**表达成本**从"两个下拉配对"降到"一个下拉"。

## 3. 界面：两个子页，**默认落在哪一页由配置状态决定**，全部就地展开（零浮层）

沿用现有的子页结构（`模型配置` / `链路配置`，页内 tab + localStorage `yekitrim.settings.llmTab`），
只改两件事：**默认落地改由状态决定**、**子页内部全部就地展开**。

参考稿 `model-first.html` 实现了三种状态：首次（未配置）/ 已配置 / 未配置时点进链路页的引导页；
以及组内草稿行、组头连接编辑、模型行编辑三种就地展开 —— **没有任何抽屉、模态或浮层**。

### 3.0 默认落地规则

```text
configured = providers.length > 0 && models.length > 0 && 默认模型所在接口有 key
默认页  = configured ? "链路配置" : "模型配置"
```

- **记忆与状态的优先级**：`configured === false` 时**忽略** localStorage 记忆，强制落到「模型配置」
  —— 否则"上次停在链路页 + 后来把模型删空"会让页面打开即空页。
- `configured === true` 时优先用记忆；没有记忆才落「链路配置」。
- **一次性引导**：第一次从"未配置"变成"已配置"（加完并测通第一支模型）时，主动落到「链路配置」一次，
  并在「模型配置」页底部留一句"加好之后默认落到链路配置"。
- **不拦路**：未配置时「链路配置」tab 仍然可点（虚线 + 「（未配置）」标注），进去是一张引导卡
  「先加一支模型 → 去模型配置」。**别做成点不动** —— 仓库纪律：门控不是"不许点"。

### 3.1 链路配置页 ① 任务用哪支（第一屏）

一张表，5 行（`correct` 仍隐藏但生效）：

```
任务            用哪支                      参数                状态
默认 [基准]      [deepseek-chat ▾]          温度 0.7 · 4096 · …  正常
检测 挑亮点      [Qwen2.5-72B   ▾]          温度 0.3 [已覆盖]    接口 401
精修 剪辑/字幕   [deepseek-chat ▾]          跟随默认             正常
标题 起名        [deepseek-chat ▾]          跟随默认             正常
工具 杂项        [qwen2.5:14b   ▾]          跟随默认 · 并发 2    正常
```

- **一个下拉**：`<optgroup label="接口">` 分组，`<option>` = 模型 id。选中的那一行自带"它在哪份接口下"。
- 「默认」行是**基准**：其余行显示「跟随默认」。
- 参数列只显示**被覆盖的键**，未覆盖的写「跟随默认」——不再出现"灰字实值"与编辑态混在一起。
- 「状态」是每行真实可用性（接口健康 + 模型能力是否满足该任务），不再是纯装饰。

### 3.2 模型配置页 ② 模型：**接口当分组头**（不是抽屉）

模型清单按接口分组 —— 接口不单独占一块，它就是每一组的表头：

```
main · DeepSeek   api.deepseek.com   ● 412ms   2 支模型共用这份密钥      [改密钥] [+ 模型]
  deepseek-chat      [默认] 文本·8K·推理档3级·JSON   被 3 个任务用 · 精修/标题   [编辑][删除]
  deepseek-reasoner        推理·64K                    没人用 · 删了不影响          [编辑][删除]
cheap · 硅基流动  api.siliconflow.cn  ● 401 密钥无效  1 支模型共用这份密钥     [修密钥] [+ 模型]
  Qwen2.5-72B        [401] 文本                         被 1 个任务用 · 检测         [编辑][删除]
local · Ollama    127.0.0.1:11434    ● 88ms          免密钥                   [改地址] [+ 模型]
  qwen2.5:14b       文本·本地                          被 1 个任务用 · 工具         [编辑][删除]
[ + 添加一份接口（地址 + 密钥） ]
```

- **分组头 = 接口**：名称 · 主机 · 延迟 / 错误 · **"N 支模型共用这份密钥"**。接口因此只出现一遍，
  且天然解释了"改它会影响谁"。
- **模型行**：id + 状态徽标 + 能力 chips + **被 N 个任务使用** + 编辑 / 删除。
- **全部就地展开，零浮层**（见 §3.4 / §3.5）。

### 3.3 链路配置页 ③ 参数与提示词

- **默认参数**（温度 / 输出上限 / 推理档 / 并发）：任务表下方第一块；
- **检测评分权重**：单独一块，不进请求体；
- **提示词**（参考标题 / system / 模板）：折叠 + **自己的保存按钮**（写 `[llm.links.detect.prompt]`）；
- **额外请求参数**：不在这里 —— 它按模型存，在「模型配置」的模型行「编辑」里；
- 订正（隐藏任务）仍生效，不占行。

### 3.4 加模型 = **组内一行草稿**（不是抽屉、不是模态）

点组头的 `+ 模型`，在该组**内部**插入一行：

```
[ 模型 id，如 deepseek-coder            ]  [取候选]  [加入]  [取消]
```

- **"连哪儿"这一步自动消失**：接口已由所在分组确定 ⇒ 三步变一步。
- 草稿行天然说明了归属（它在这一组的框里），不需要"选择接口"的下拉。
- `取候选` 探一次 `/models`；勾选批量加入（现状是每点一次写一次文件、越攒越多）实现为
  「候选列表替换草稿行」，仍是就地、不浮。
- 加**接口**同样就地：清单底部一行 `+ 添加一份接口` → 展开名称 / 地址 / 协议 / 密钥（+ 测试）。

### 3.5 改密钥 = **组头就地展开**

点组头 `改密钥`，**在该组内部**展开 协议 / 地址 / 密钥 + [测试] [保存] [取消]，
并附一句影响面：

> 改这里 = 改 main 这份连接：下面 2 支模型一起变；用它们的 4 个任务下次请求即生效。

- 这是 401 那类故障的**唯一入口**，故障组头本身就是红色的。
- 互斥规则：同一时刻只开一个连接编辑器 / 一个模型草稿 —— 打开连接编辑会收起草稿行，
  反之亦然（"一块地只放一个编辑态"，避免两个半成品同时躺着）。

### 3.6 为什么坚持不留抽屉

| 抽屉的问题 | 就地展开 |
|---|---|
| 盖住任务表 —— 而"加完模型立刻去看任务"正是这个页面的主循环 | 任务表始终可见 |
| 加模型本来只要一个输入框，套抽屉反而多两层步骤 | 一步：填 id → 加入 |
| 打开后忘了自己在哪一层、取消要记得按 Esc | 取消退回原位，位置即上下文 |
| 与既有交互冲突（本仓只有 `JobDrawer` 一个抽屉，弹层都是 `AppModal/AppDialog`） | 不新增任何浮层范式 |

### 3.7 保存反馈只留一个位置（页头右上角）

删掉常驻的 sticky 保存条（`data-llm-savebar`），把「存没存」并进页头那一个位置 —— **一个位置两种面孔**：

| 状态 | 显示 | 可点 |
|---|---|---|
| 没触发自动保存（刚进页面 / 没有任何改动） | `[ 保存 ]` 按钮 | ✅ |
| 改动后停手 1.2s 的窗口内 | `● 自动保存中…` | ✗ |
| 正在落盘 | `● 保存中…` | ✗ |
| 落盘完成 | `● 已自动保存 · HH:MM` | ✗ |
| 失败 | `● 自动保存失败 · 重试` | ✅（重走一遍） |

- 常驻保存条每天挡一行内容，而"存没存"本来一个点就能说清；按钮只在**还没触发**自动保存时出现，
  触发了就不给按 —— 避免"自动保存着还能手动再存一次"的重复动作。
- ⚠️ **合并不能丢信息**：现在 `.llm-savebar` 承担四种文案（未保存 / 保存中 / 保存失败 / 回读不一致），
  合并后**失败必须是可点的重试**（仓库纪律：读失败/写失败都要留下可追溯痕迹，不能一闪而过），
  「回读不一致」保持文字 + `title` 展开原因。
- ⚠️ 自动保存的既有纪律一条不改：停手 1.2s、**自动路径不重读**、额外参数 JSON 非法时**拒绝写入**
  （此时保存位直接转 err 态，而不是假装存上了）。

## 4. 它顺手解决的七件事

1. **非法组合不可能** —— 两个下拉合成一个，`(接口, 模型)` 由 UI 保证一致。
2. **故障可见** —— 401 挂在**模型**行（被引用的实体）上，而不是藏在一张接口表里。
3. **加模型不用翻找、也不用等浮层** —— 在所属接口组里点 `+ 模型`，就地出一行输入框（原话："每一次添加模型都要翻找很不合理"）。
4. **两个子页消失** —— 因为"接口清单"不再是独立概念，不需要一个子页专门装它。
5. **意图可见** —— "跟随默认"与"我指定了这一支"在参数列分得开，不再靠灰字。
6. **删除有依据** —— 「被 N 个任务使用」在删之前给答案。
7. **不新增浮层范式** —— 本仓只有 `JobDrawer` 一个抽屉、弹层一律 `AppModal/AppDialog`；这套方案一个都不加。

## 5. 数据与迁移：**零迁移**

### 5.1 不动 `llm.toml` 形状

- `[[llm.providers]]` / `[[llm.models]]` / `[llm.links.*]` 原样保留，`config_version` 不升。
- 写入时由前端**派生**：`link.provider = model.provider`。读路径一个字不用改 ——
  `provider_for()` 本来就以 `link.provider` 为准，派生值必然与模型一致。
- `[llm] active` 语义改为「默认模型所在的那份接口」；`active_provider()` 的回落不变。

### 5.2 历史不一致要能修，不能崩

打开页面时算一次体检，命中任一条件就出顶部一条横幅 + 「一键修正」：

- `link.model` 非空但**不在清单里**（老文件常见：模型被删了）；
- `link.provider` 非空且 ≠ 该模型的 `provider`；
- 清单里没有「默认模型」对应的条目。

修正 = 按模型补齐 `link.provider`、把认不出的 `link.model` 清空（回到跟随默认）。
**只改这三类，不碰用户手写的参数覆盖。**

### 5.3 唯一建议的后端改动（可选，M2）

给 `problems()` 补一条：

> 「链路 {link} 指定的模型 {model} 不在接口 {provider} 的清单里」

把前端那条 `modelMismatch` 搬成**唯一实现**（CLI 与直接改 toml 的人也拿得到）。同时前端那条标黄可以删掉 ——
判据从"界面提示"升级为"保存时就拦"。

- 链路本身的数量与语义（`detect/polish/correct/title/utility` 不动，`correct` 继续隐藏）；
- 协议注册表、模型能力来源（catalog / 探针 / 手填三源的合并规则）；
- 用量统计页。
