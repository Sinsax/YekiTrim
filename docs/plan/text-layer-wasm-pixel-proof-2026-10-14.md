## 二、⚠️ 我第一版测错了（留档，免得下一个人重踩）

第一版渲的是**帧 250-260**，差异像素 **0** —— 我当时以为"文字没画出来"。
**错在窗口**：文字层的 `layers[0]` 是 `start: 466 / end: 586`（事件 `time=7.78 end=9.78`，
60fps）。**250-260 在窗口外**，当然一个像素都不差。

> **教训**：差分法的前提是**两组输入只在被测那一条上有区别，且被测那条在采样区间内**。
> 渲之前先打印 `layer.start/end`，确认窗口覆盖了要测的帧。

## 三、⚠️ 第二版撞上的**真**问题：底座的 `--font-file` 是硬前提

不给字体时底座**明确拒绝**（不是静默画不出来）：

```json
{"code":"subtitle_font_missing",
 "message":"这一帧要画「怎么这样！」，却画不出来：宿主没有给字体…" +
           "不给字体就不出一份「看起来成功、其实没有字幕」的片子"}
```

`lines_failed: 21 / lines_drawn: 0` ⇒ **整段文字一个字都没画**。

**这正是本仓 `render/dhampir.rs::find_font` 存在的原因**（它按预览那份字体栈解析出常规体 +
粗体，再传给底座）。**生产路径 `yekitrim polish render` 已经这么做了** —— 我手工调用底座时
漏了参数，不是产品缺陷。

## 四、⚠️ 第三版撞上：底座写字幕临时文件用系统 TMP，**权限被拒就整行画不出**

```
{"code":"subtitle_raster_failed",
 "message":"画文字阴影失败（这一行的字仍会画出来）：写不了字幕临时文件
            C:\Users\para\AppData\Local\Temp\dhampir-sub-….srt：拒绝访问。 (os error 5)"}
```

`lines_failed: 21 / lines_drawn: 0` ⇒ 仍然一个字都没画（**它说"仍会画出来"，但实测没有**）。

把 `TMPDIR/TEMP/TMP` 指到一个**可写目录**之后：

```
"failed":false  "lines_drawn":21  "lines_failed":0
```

### ⚠️ 结论（已逐条核对过源码，我先前两条判断**都是错的**，留档纠正）

**一、那句报错文案是准确的，不是缺陷。**
`"这一行的字仍会画出来"` 住在 `text_overlay.rs:895` 的 `draw_shadow` 里 ——
它只管**影子**那一张位图，字由**另一次独立调用**画。所以这句话在**它自己的作用域内是对的**。
我先前说"文案与实测不符"是**误判**：当时 `lines_drawn: 0` 是因为**字**那条路
（与影子同源，都走 `rasterize()` → 都要写 `%TEMP%`）**也**失败了，
两个失败被我当成一个。

**二、`issues` 只有 2 条而 `lines_failed` 是 21，也不是"静默失败"。**
`pipeline.rs::IssueLog::record` 按 `(code, path)` **有意去重**（注释写着"90 帧的渲染里同一个缺陷
会被撞到 90 次，原样列出来等于没列"），超出 `MAX_ISSUES`(24) 的部分走 `suppressed` 计数。
实测这 2 条正是**两段不同的文字**（`overlay[怎么这样！]` / `overlay[我看不懂啊！]`），
21 = 这两段在 11 帧里的重复命中。**去重是对的。**

**三、系统 TMP 这条：底座已经知道，且**有意**当环境问题处理。**
`text_raster.rs:2505` 的注释原话：

> 正常情况下就是 `std::env::temp_dir()` 底下的一层。但**沙箱化的开发环境**（例如 DSH 的文件沙箱）
> 会让某个路径下的可执行文件**写不了 `%TEMP%`** …… **那不是产品缺陷**，所以这里返回 `None`
> 让用例自己如实跳过。

⇒ 所以这条**不建议改**（至少不该按我原来那句"临时文件挪去 data/"去改）：
受限环境下写不了系统 TMP 是**环境属性**，底座的做法（如实报告 + 判失败，而不是静默出片）
正是它对的那一面。

**实测复现（本机，可复跑）**：

| 条件 | `lines_drawn` | `lines_failed` | issues |
|---|---|---|---|
| 系统 TMP | **0** | **21** | 2 × `subtitle_raster_failed` |
| `TMPDIR/TEMP/TMP` 指到可写目录 | **21** | **0** | 无 |

⚠️ 上面这条差分同时是**文字层像素证明的前置**：不给可写 TMP 时
`lines_drawn = 0` ⇒ 一个文字像素都不会有 —— 我第一版就是栽在这里，
差点把"环境限制"报成"文字层没实现"。

## 五、文字层「两边各画一份」的归位决策 —— **已落地且有判据**

| 项 | 状态 |
|---|---|
| 口径 | **两边都画的档，DOM 本层不画**（让底座那份说话，一个时刻只有一份） |
| 例外 | 底座**不画**的档（`heartbeat` / `shake`）本层必须留 —— 那是它们唯一的可见实现 |
| DOM 模式 | `!dhampirMode` ⇒ 一律本层画（那时底座根本没画面） |
| 实现 | `PolishPreview.vue` 的 `byDom` + `DHAMPIR_NO_DRAW` |
| 判据 | `node scripts/check-text-layer-not-doubled.mjs` —— **19 项全过** |

逐档依据（实测，非推测）：

| 档 | 底座画不画 | 依据 |
|---|---|---|
| 位置 / 描边 / 竖排 | **画** | ASS `\pos` / `Outline` / 样式 |
| 逐字 `perchar_*` | **画** | `text_perchar_anim.rs`（6 个 `pub fn`）|
| `pop` / `fade` | **画** | ASS 有该轨 |
| **`heartbeat`** | **不画** | 全底座搜 `heartbeat` ⇒ **0 命中** |

## 六、顺带确认：文字层的事件类型叫 `element`，不是 `text`

全库 55 个 `polish.toml` 的事件类型分布：

```
camera 398 / sticker 131 / sfx 65 / shake 39 / overlay 36 /
flash 11 / vignette 6 / **element 5** / zoom_bounce 3 / blur 1
```

- **`text` 事件：0 个** —— 文字元素走的是 `element`（转译器里 `kind === 'text'`，
  DOM 侧 `element: 'sticker'` 座位别名）。
- 有 `element` 的只有 4 个片段，**全部**在 `[和我说话]` 与 `[说会话z'z]` 两个项目下。

## 七、这一轮暴露的**判据缺口**

| 缺口 | 现状 |
|---|---|
| 「文字到底画没画」 | **没有判据**。源码级判据（19 项）只锁"不许画两遍"，**不锁"到底画出来没有"** |
| 「贴纸到底画没画」 | 本轮新增 ㊲（数轨道/素材去重数）是第一步，但它数的仍是**工程结构**，不是像素 |

⇒ 两者都缺同一件东西：**一条真渲染 + 数像素的判据**。
这次的差分法（摘掉目标轨 → 重渲 → 数差异像素）就是它的形状，建议据此落成常驻判据
（见本文件第零节的四步）。
