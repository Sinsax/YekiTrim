# 换一个范式：不做"效果库"，做"编辑决策"

> 立档：2026-10（提案，**未拍板、未动手**）。**这是第三份，也是与前两份思路不同的一份。**
> 前两份（[`polish-enrichment-proposal.md`](polish-enrichment-proposal.md) 补零件、
> [`emotion-narrative-engine.md`](emotion-narrative-engine.md) 编情绪）都还在**"往画面上加什么"**这个问法里。
> **这一份换问法**：*专业剪辑师到底在做哪几件事？* —— 然后发现**本仓做错了一件事**。

---

## 1. 先说结论：本仓的切片边界可能是"结构性错的"

我读了一篇直接对口的论文 —— HIVE（[arXiv 2507.02790](https://arxiv.org/html/2507.02790v1)，USTC + 字节），
它做的事和我们几乎一样：**把长视频剪成短切片**。它的核心发现值得本仓认真看：

> 论文原话（两个"major challenges"）：
> **① 视觉与文本模态融合不足 ⇒ 对叙事的理解不完整；**
> **② 缺少系统性的剪辑策略 ⇒ 产生突兀的转场与不连贯的叙事。**

**它把"剪辑质量"分解成三件事**（作者访谈了专业剪辑师后总结）：

| # | 子任务 | 一句话 |
|---|---|---|
| **1** | **Highlight Detection** | 哪里是爆点 |
| **2** | **Opening / Ending Selection** | **从哪里开始、在哪里结束** |
| **3** | **Content Pruning** | 中间哪些该删 |

**而本仓这三件事里，第 2 件几乎没做、第 3 件做成了"去静音"。**

### 1.1 最刺眼的一条：切片边界

论文里有一句关键设计：

> *"we adopt an improved video scene segmentation... to divide the video into **semantically complete scenes**.
> This ensures that **clip boundaries do not interrupt ongoing dialogue or character actions**."*

**"切片边界不许切断正在进行的对话"** —— 这正是本仓今天会犯的错。
本仓的段边界来自 LLM 切话题（`Segment`），**它只看字幕文本**，不看：

- 一句话说到一半；
- 一个动作/笑点正在展开；
- 弹幕正在爆发（观众的注意力在下一句上）。

⇒ **表现是"剪得莫名其妙"**：观众感觉"这块还没说完就切了"。
**这不是特效问题，是边界问题 —— 而且特效再多也盖不住。**

论文的量化对照很说明问题（Table 2）：

| 方法 | Smoothness | Engagement | VEI（综合） |
|---|---|---|---|
| **人工剪辑（golden）** | **6.84** | 0.93 | **6.35** |
| 端到端（纯 ASR 文本） | 0.65 | 0.82 | 0.54 |
| **HIVE（三子任务分解）** | **4.48** | 0.89 | **4.01** |
| 去掉 highlight 检测 | 4.42 | **0.62** | 2.74 |
| **去掉边界选择** | 4.17 | 0.81 | 3.38（**Hook 0.87 → 0.28**） |

**两个读数值得记住**：
- **"纯文本 ASR"那条腿的 Smoothness 只有 0.65，而分解成三子任务是 4.48** ——
  差距**不是特效**，是**策略**；
- **去掉边界选择，Hook Rate 从 0.87 掉到 0.28**（掉 2/3）——
  **开头选在哪里，比开头加什么更重要。**

## 2. 换问法：把"效果"降级，把"决策"升级

前两份文档的隐含假设是"**本仓缺效果**"。这篇论文的读数是"**本仓缺决策**"。

### 2.1 三个本该是"一等公民"、今天却不是的东西

| # | 今天的状态 | 应该是什么 |
|---|---|---|
| **边界** | `Segment` 的 `start/end`，由 LLM 按话题切 | **一个独立的、可校验的"剪辑点"决策**（含"这里不能切"的硬约束） |
| **删减** | `mute_ranges`（去静音），定位是"清理" | **一门剪辑语言**（删什么、留什么，是叙事手段） |
| **开头/结尾** | 没有这个概念（切片一剪出来就是全程） | **显式选择**（论文证明它最影响 Hook） |

### 2.2 核心重构：从"事件流"到"决策流"

今天 `polish.toml` 的中心是 **`segments[].events[]`**（一堆效果事件）。
**建议加一层更上面的东西**：

```
今天：  段 → 事件（效果）
建议：  素材 → 决策（边界/删减/开头/结尾）→ 演出（效果）
         ↑ 这一层今天几乎没有        ↑ 前两份文档在做的
```

⚠️ **关键：这一层不等于"再加字段"，它是"谁决定"的转移。**
今天的边界是 LLM **顺手**切的（它只顾话题）；
建议把它变成**显式的、有守卫的、可单独重跑的决策**。

### 2.3 论文里三个可直接抄的机制

#### ① **Opening / Ending 候选集**（而不是"随便从哪开始"）

论文的做法（Algorithm 1，第 8–10 行）：

```
开头的候选 = 爆点之前的"普通场" + 所有爆点的第一场
结尾的候选 = 爆点之后的"普通场" + 所有爆点的最后一场
⚠️ 硬约束：不选爆点内部的场当开头/结尾（否则切断叙事完整性）
然后：枚举所有 (开头, 结尾) 组合 → 每个组合产出一条候选成片 → 去重
```

**"产多条候选、让用户挑"** —— 这是本仓完全没做的形态（今天是一条道走到黑）。
而且成本极低：**同一份效果事件，换个起止点就是另一条片子**。

#### ② **Highlight 规则打分**（而不是"让 LLM 自由发挥"）

论文把爆点抽象成**一组规则**，让 LLM 判断每个场**匹配了几条**，
命中多条才合并成"highlight clip"，分数相加当重要度。

**这正好是本仓该走的路**（用 LLM 做判断、用规则做确定性）——
比前两份文档里"让 LLM 直接生成事件"稳得多。

#### ③ **Pruning 规则**（"删"是有语言的）

论文让 LLM 评估"每个普通场与主线的关系"，删掉不抓人的。
**而本仓的"删"只有一招**：字幕间隔 > 3.5s 就剪（去静音）。

| 形态 | 说明 | 前两份能做吗 |

| 文档 | 问法 | 层次 |
|---|---|---|
| `polish-enrichment-proposal.md` | "往画面上加什么" | **零件**（`elements` 文字、`role`） |

**三者的正确顺序（这才是重点）**：

```
本文（决策层）  →  emotion（演出层）  →  enrichment（零件层）

```

⚠️ **前两份把顺序搞反了**：它们先做零件，但**如果边界是错的，零件再好在错的位置上也没用**
（论文读数：去掉边界选择，Hook 从 0.87 掉到 0.28）。

## 5. 落地方案（决策层）

### 5.1 数据形态

```toml
# 新增：剪辑决策（与 segments 平级，不是塞进 segments）
[editing]
# 边界决策：每个剪辑点 + 理由（可审计）
[[editing.boundaries]]
t = 12.4
reason = "sentence_end"        # sentence_end | topic_shift | applause | hard_pause
locked = false                 # true = 用户手工锁定，后处理不许动

# 删减决策（今天只有 mute_ranges，这是它的升级版）
[[editing.prune]]
start = 30.0
end = 45.0
reason = "off_topic"           # off_topic | redundant | slow
keep_secs = 3.0                # 压成几秒（0 = 整段删）

# 头尾候选（论文的 Opening/Ending Selection）
[editing.openings]
candidates = [0.0, 4.2, 9.8]
selected = 4.2
[editing.endings]
candidates = [88.0, 92.5]
selected = 92.5
```

### 5.2 硬约束（守卫，照本仓 `cap_pip_shots` 的先例）

| 守卫 | 规则 | 依据 |
|---|---|---|
| **不切断句子** | 边界必须落在**句末**（字幕文本以 `。！？…` 结尾，或与下一条间隔 > 0.35s） | 论文"boundaries do not interrupt ongoing dialogue" |
| **不切断爆点** | 爆点窗口内不许设边界 | 论文"avoid selecting internal scenes" |
| **开头/结尾不取爆点内部** | 同论文硬约束 | 论文 Algorithm 1 |
| **`locked` 优先** | 用户锁过的边界，后处理一律跳过 | 本仓既有 `manual` 先例 |

⚠️ **"不切断句子"这条需要词/句级信息** —— 但**不必上词级时间戳**：
字幕本身有 `text` + `start/end`，**"这条字幕是不是以句末标点结尾"** 就够了。
（对比：词级 Karaoke 才需要词级时间戳。）⇒ **这条成本很低。**

### 5.3 多版本成片（论文最有价值的形态）

```
决策层为同一素材产出 N 组 (opening, ending, prune) 组合
       ↓
共用同一份效果事件（演出层不变）
       ↓
出 N 条成片，用户挑一条
```

⚠️ **本仓的既有约束**：`cmd_render` 是"一个工程 → 一条成片"，产物走 `unique_output_path`
（同名加 `_1`/`_2`）。**多版本不需要改这套** —— 就是跑 N 次，每次覆盖 `[editing]` 的 selected。

## 6. 论文里另外两条值得注意的

| 发现 | 对本仓的含义 |
|---|---|
| **视觉模态缺失是"两大挑战"之一**（"neglecting the rich visual context"） | 本仓也**完全没有**视觉信号（只有 ASR + 弹幕）。论文用 MLLM 看画面。**这是一条独立的大路**（要 CV/多模态模型），本仓短期不碰 —— 但**要知道自己缺什么** |
| **脚本文本可以 OCR 出来纠正 ASR**（"use OCR to extract subtitles... align and correct ASR outputs"） | ⚠️ 本仓是**直播录播**，不是短剧 —— **没有硬字幕可 OCR**。这条**不适用**（记下来免得以后有人照抄） |

## 7. 明确"不做"与"暂缓"

| 项 | 理由 |
|---|---|
| **多模态（看画面）** | 需要 MLLM/CV，是独立大工程。**但要在文档里承认这是本仓的结构性欠缺** |
| **OCR 纠字幕** | 不适用（直播录播没有硬字幕） |
| **DramaAD 那套短剧评测指标** | 那是**广告投放**场景（Hook Rate / Suspense Rate 要人评），与本仓"切片"场景不同 —— 但 **Smoothness 的构造**（"两次干扰之间的平均观看时长"）**非常值得抄**，它能给"剪得好不好"一个**自动可算的数** |

### 7.1 ⭐ 一个可以立刻用上的东西：**Smoothness 作为自动指标**

论文定义：

```
Smoothness = Duration(V) / (1 + Interruption(V))
Interruption = 可感知的干扰次数
```

**本仓可以把它具体化**（全自动、不需要人评）：

| 干扰项 | 本仓可算吗 |
|---|---|
| 边界落在句子中间 | ✅ 字幕文本判 |
| 切在爆点上 | ✅ 弹幕/情绪判 |
| 静默突变（突然没声） | ✅ 音轨判 |
| 两次视觉变化间隔 < 0.8s | ✅ 事件表判 |

⇒ **一个"剪辑质量分"**，可以**在切片列表里显示**，也可以**用来对比不同参数**。
**这是本仓今天完全没有的东西** —— 今天没有任何"这条切片剪得好不好"的量化。

## 8. 结论

**前两份问"加什么"，这份问"怎么剪"。**

论文的读数说明：**剪辑质量的差距主要不在特效，而在策略** ——
纯文本端到端那条腿 Smoothness 0.65，分解成"爆点/边界/删减"三子任务后是 4.48；
而**去掉边界选择，Hook Rate 直接掉 2/3**。

⇒ **本仓最该补的不是第 12 个特效，是"剪辑点"这一层**：
它今天由 LLM 顺手切（只看话题），既没有硬约束（不切断句子/不切断爆点），
也没有"多版本候选"这个形态，更没有"这条剪得好不好"的量化。

**优先级建议**：
1. **不切断句子的边界守卫**（成本极低、收益直接）；
2. **Smoothness 指标**（今天完全没有，且可自动算）；
3. **多版本成片**（论文最独特的形态，本仓零基础但改动可控）；
4. 之后才是前两份的零件与演出。
