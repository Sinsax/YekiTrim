# 节奏强化方案：把"总量配额"升级成"节拍曲线"

> 范围：`crates/yekitrim-polish/src/process`（调度与守卫）、`llm/segment.rs`（提示词口径）、
> `project/config.rs`（`[rhythm]` 表）、`render/ffmpeg.rs`（音效闪避）｜ 验证：见 §7
> 状态：**待拍板**（§8 三个开关）｜ 关联：`docs/plan/editing-techniques-catalog.md` §2.3 / §4

## 0. 一句话

今天的节奏由**四类素材的总量配额**决定（贴纸每 5 条字幕、音效每 8 条、画中画整片 1 条、跳切只在屏蔽接缝），
**没有"什么时候该给一下"的时间分布**。方案不改渲染器、不加特效种类，而是把四类素材按
**节拍网格 + 强度分层 + 能量曲线**重新排布 —— 用现有原语拿到"更抓眼"的观感。

---

## 1. 体检：今天的节奏是怎么产生的

### 1.1 四个节奏素材（都已有，缺的是"排布"）

| 素材 | 现状参数 | 表达力 |
|---|---|---|
| 运镜 | 每段 ≥1s 默认补 `zoom="中"(1.3) + anchor="liver"` **整段**；三档 中1.3 / 近1.5 / 画中画0.55 | 档位差、硬切 `cut`、位移 `anchor_to`、`handheld`、荷兰角 |
| 瞬时特效 | shake/flash/blur/noise/pulse/hue_shift/vignette，跨度 0.3~0.6s | 爆点重音 |
| 元素 | 贴纸每 5 条字幕或每 12s 一个（`content_budget`） | 具象吐槽；文字已降级为候补 |
| 声音/切点 | sfx 每 8 条字幕或每 15s 一个；跳切只在 `mute_ranges` 接缝、相邻 ≥20s | 音画同步、硬切 |

### 1.2 三条结构性失效（这是"尚可但不抓眼"的真正原因）

**① §23 节奏求解器从结构上就报不出空档。**
`pacing.rs::is_visual` 的判据是"**除音效以外的事件都算视觉变化**"，而且是按事件的
`time..end` **整段**算。可是 `process` Step 1 会给**每个 ≥1s 的段补一条铺满整段的默认运镜**
（`zoom=中`，画面其实是**静止的裁剪**）⇒ 只要段表铺满时间轴，视觉区间就铺满全片，
`find_idle_gaps` **恒为空**，`data/pacing.json` 几乎永不产出，"每 3–6 秒一次视觉变化"
这条唯一被写进代码的节奏纪律**从未生效**（而且今天它也只报告、不落实）。

**② 密度是"总量"不是"分布"，抽稀还可能正好抽掉爆点。**
`cap_events` 是**等距保留**：9 个事件预算 4，留下的是第 0/2/5/8 个 —— 与"哪里是爆点"无关。
`data/punches.json`（字幕密度 + 弹幕 + 响度，`punch.rs`，阈值 0.6、窗口 5s）**已经算出来了，
但没有任何节奏消费者**。

**③ 跳切被"屏蔽接缝"绑死。**
`find_jump_seams` 只认 `cut:true` 且 `time` 落在 `mute_ranges` 边界上。**没有屏蔽区间的工程 =
一次跳切都用不上** —— 而跳切正是短视频的招牌节奏手法（提示词第 195 行自己就这么写）。

**④ 声音不敢多用。**
`mix_sfx` 是 `amix=inputs=N:normalize=0` **等权相加，没有闪避**；人说话时音效照样满音量，
所以只能把全局音量压到 0.1 —— 于是"没说话的地方也不够响"。`envelope_filters` 这套**包络能力
已经存在**（按区间写 `volume` 增益），只是没人用它做闪避。

### 1.3 实测样本（探针工程，非生产素材）

`.workbuddy/llm-prodrate/proj`：92.6s / 5 段 / 21 条运镜（中 12、近 8、远 1；slow 9、handheld 3）
/ 7 元素 / 4 贴纸 / 4 sfx / 3 shake / 2 flash —— 这是**事件密度接近上限**的一档，
仍可用"重音表"重新排序：47 个可感知变化点、30.5 个/分钟，但**强度不分层**（没有"轻/中/重"），
观众读到的是"一直在动"，而不是"一下、又一下"。

## 2. 目标："更抓眼"= 三个可量化的东西

| 指标 | 定义 | calm（今天的行为） | balanced（默认） | punchy |
|---|---|---|---|---|
| 重音密度 | 可感知变化 / 分钟 | 4–6 | **9–12** | 15–20 |
| 最大空档 p95 | 连续无变化时长 | 12s+（且测不出） | **≤ 6s** | ≤ 4.5s |
| 强度分层 | 轻/中/重占比 | 无分层 | **60 / 30 / 10** | 50 / 35 / 15 |
| 档位变化 | 运镜档位切换 / 分钟 | 0–2 | **≥ 4** | ≥ 7 |
| 爆点命中 | 重音落在 punch ±1s 的比例 | — | **≥ 60%** | ≥ 75% |
| 音画同步 | sfx 起点 vs 画面重音起点偏差 | ~ | **≤ 80ms** | ≤ 60ms |
| 打断数 | `quality.rs` interruptions / 分钟 | 现状 | **不升高** | 不升高 |

> 依据：catalog 引的"每 3–6 秒一次视觉变化"（Zella）、`MIN_VISUAL_GAP_SECS=0.8`（两次变化
> 少于 0.8s 会被知觉成一次）、`punch.rs` 的三路信号。**"重音"比"变化"更稀**：变化可以只是
> 字幕换行，重音是"画面真的强调了一下"。

## 3. 方案总览

```
爆点表(punches.json) + 段表 + 字幕句末 + 屏蔽接缝
        │
        ├─▶ ①节拍网格 beat_grid(段内相位对齐)   ← [rhythm] beat_secs=4.0
        │
        ├─▶ ②重音规划 plan_accents()            ← 强度：轻/中/重，受 3 条分布约束
        │        · 爆点 ±0.4s 必占一个 slot（≥中）
        │        · 相邻重音 ≥3.0s；重音之间 ≥12s
        │        · 空档 >5.5s 必补一个"轻"
        │
        └─▶ ③落实 apply_accents()  ── 只写带 auto 标记的派生事件（幂等重建）
                 · 轻：中→近 1.2s→回中（两条 camera）
                 · 中：近 1.8s + shake(0.3)/flash(0.25) + sfx
                 · 重：hard cut 到 特写/画中画 2.5s→回位 + sfx（配额内）
```

三条分布约束是**闸门**（防止"更丰富"变"更吵"）：
1. `min_accent_gap = 3.0s`（轻与轻之间；重的旁边可以更近，但总间隔仍 ≥2.4s）；
2. `heavy_every = 12s`，且**每段 ≤2 个重音**、单段 Heavy ≤1；
3. **空档优先**：任何 >5.5s 无重音的区间必须先补一个"轻"，再谈别的。

## 4. 分批实施

### P0（半天~1 天，几乎零新原语，先把"结构失效"修好）

| # | 改什么 | 落点 | 验收 |
|---|---|---|---|
| P0-1 | `is_visual` 语义拆开：新增 `visual_spans()` —— 静态运镜**只算** `time..time+0.6`（过渡）与 `end-0.6..end`；只有 `handheld` / `anchor_to` / `speed` 才算"持续变化" | `process/pacing.rs` | `static_camera_does_not_count_as_visual_change`（默认运镜铺满 20s ⇒ 必须报 1 个空档）；变异回整段 ⇒ 红 |
| P0-2 | 空档补位**从"只报告"改成可落实**：`[rhythm] idle_punch = "auto"\|"report"\|"off"`；补 `zoom=中`、2.0s、末尾回位 | `pacing.rs` + `process/mod.rs` Step 1d4 | `idle_gap_gets_one_punch_in`；幂等（重建不叠加） |
| P0-3 | `cap_events` 改**爆点加权保留**：距 punch ≤1.5s 权重 3 > 段首尾 2 > 其它 1，同预算先保高权重再等距填满 | `process/mod.rs` | `punch_adjacent_events_survive_cap`（9 预算 4、punch 在第 7 个 ⇒ 必留） |
| P0-4 | 音效闪避：字幕区间 = 人声区间，说话时 sfx 降 `[sfx] duck_db`（默认 -4dB，calm 下 0），起落 60ms 淡 | `render/ffmpeg.rs::mix_sfx`（复用 `envelope_filters`） | 纯函数单测 `duck_envelope_matches_subtitle_intervals` + 真出片波峰对比 |
| P0-5 | `data/rhythm.json` 落盘指标（只读，先不驱动任何东西） | `process/mod.rs` | 文件形状单测；无重音时也要写出"0 重音" |

### P1（2–3 天，节拍网格 + 重音调度 —— 观感提升的主体）

| # | 改什么 | 说明 |
|---|---|---|
| P1-1 | 新模块 `process/rhythm.rs`：`beat_grid` / `plan_accents` / `apply_accents` | 纯函数，便于钉判据；`apply` 只碰 `auto` 事件 |
| P1-2 | **派生事件标记**：`Event` 新增 `auto: Option<String>`（serde skip，老工程零迁移） | 幂等 = 每次先删 `auto` 旧事件再重建；`manual` 与 LLM 事件只"避让"不修改 |
| P1-3 | 长段 A/B 双镜：段长 >9s 且段内无 LLM 运镜 ⇒ 45% 处插一个"轻" | 解决"30s 段一个机位到底" |
| P1-4 | 跳切资格放开：`cut` 允许落在**字幕句末边界**（复用 `is_sentence_end`）；相邻 20s→8s、单段 2→1 | 无屏蔽工程也能用招牌手法 |
| P1-5 | 静默保护：爆点后 1.2s 内不加瞬时特效/贴纸/中重音 | catalog §7"笑点要发酵" |

### P2（2–3 天，全片结构与转场）

| # | 改什么 | 说明 |
|---|---|---|
| P2-1 | 能量曲线：`hook(0–3s) 必有"中"` / `body 每 12–15s 一个"中"` / `climax（最大 punch ±10s）一个"重"` / `结尾 8s 只"轻"或静` | 三段预算分配，不做自动切 |
| P2-2 | 转场节奏：话题/角色转折处的段间插 `dissolve`（EDL `transition_in`，0.4s，全片 ≤3） | 复用第 7 批已验证的叠化 |
| P2-3 | 鬼畜重复（catalog B13）：爆点 0.6–1.2s 区间在 `edl.clips` 连放 2–3 次（`kind="stutter"`，全片 ≤1） | 与冷开场同构：意图收走 + 幂等 |

### P3（可选，需要拍板）

- **变速**（废话段 1.25x / 爆点 0.9x）：动音频，风险最高；
- **音乐卡点**：需要 BGM + 节拍检测，catalog 已标注"不适用"，不建议现在做；
- **编辑器节奏热力条**：重音/空档/爆点三条叠加显示 + "换一版节奏"按钮（profile 切换）。

## 5. 与当前节奏的对比（优点逐条）

| 维度 | 今天 | 方案落地后 | 为什么更好 |
|---|---|---|---|
| 变化的**驱动力** | 段边界 + LLM 心情 | 节拍网格逐 slot 决定"要不要给一下" | 段内 20–40s 的静止不再靠运气 |
| **对比度** | 每段默认同一档 `中/1.3` 铺满 ⇒ 一直在推 = 已经没有"推"的语义 | 默认**静**，只在重音点动 ±1~2 档，随后回位 | 有"呼吸"才有重音；同样的推近在静之后才有意义 |
| 强度**分层** | 只有"有/没有" | 轻（推近+sfx）/ 中（近景+抖动）/ 重（硬切或画中画） | 观众记住的是"重的那一下"，不是"一直在动" |
| **分布** | 总量配额 + 等距抽稀（可能抽掉爆点） | 爆点 ±0.4s 必占 slot，其余 slot 按空档优先级填 | 同样预算，落在该重的地方 |
| **爆点数据** | `punches.json` 算出即闲置 | 成为重音规划的输入（三路信号、无弹幕可降级） | 零新判据，把已有能力接上 |
| **长段** | 一个机位到底 | >9s 段自动 A/B 双镜 | 20s 不动是最直接的流失点 |
| **招牌手法** | 跳切只在屏蔽接缝（无屏蔽 = 0 次） | 句末边界也能跳切，8s 间隔、单段 1 次 | 直接借用短视频语法 |
| **声音** | sfx 等权叠加，只能整片压低 | 人声出现自动闪避 4dB，sfx 敢放 | 音画一起"打点"才有打击感 |
| **全片结构** | 无 | hook / body / climax / 收尾四段预算 | 前 3 秒抓人、结尾不吵 |
| **可观测** | 只有 quality 分数 + 一份没人读的 pacing.json | `data/rhythm.json`（重音表/空档/命中率/档位变化） | 节奏第一次可测、可回归、可 A/B |
| **可控性** | 只能改 prompt | `[rhythm] profile = calm\|balanced\|punchy` + 每个闸门可关 | calm = 今天的行为，随时回退 |
| **风险** | — | 全部新行为挂在 `[rhythm]`，`manual` 一律豁免，派生事件可整批重建 | 不污染 LLM 产物、可幂等重跑 |

**代价（说清楚）**：每条片段的事件数会从"个位数"涨到"十几~几十条"（每个重音 2–4 条事件）；
`polish.toml` 会变大，编辑器时间轴要能折叠 `auto` 事件（P1-2 顺带要做）。

## 6. 风险与闸门

| 风险 | 闸门 |
|---|---|
| 变吵（every frame a party） | `min_accent_gap 3s`、`heavy_every 12s`、单段 ≤2、静默保护 1.2s |
| 晕（连续硬切） | Heavy 单段 ≤1、全片按 12s 摊、跳切 8s 间隔 |
| 与 LLM 打架 | LLM 管"哪里值得"（punch/emotion），调度器管"多密/怎么排"；**已有 LLM 事件优先占位**，调度器只填空 |
| 与用户手改打架 | `manual` 全豁免；`auto` 事件每次重建；用户删掉某个 `auto` 事件后**不再复活**（除非整批重算） |
| 幂等 | 派生事件带 `auto` 标记 + 每趟先删后建；`[rhythm] profile` 改变时整批重算 |
| 存量观感突变 | `calm` = 今天行为；升级后默认 `balanced` 但**只在跑过 process 的片段上生效**，可随时切回 |

## 7. 验收与 A/B

```bash
cargo test -p yekitrim-polish --lib rhythm          # 网格/规划/闸门/幂等
cargo test -p yekitrim-polish --lib process         # 既有守卫不回归
VT_POLISH_DIR=<片段> cargo test -p yekitrim-polish --lib diagnose_rhythm -- --ignored --nocapture
```

A/B 方法（同一片段、同一素材）：

1. `[rhythm] profile = "calm"` 跑一遍 process + 出片 → A；
2. 改 `balanced` 再跑 → B；
3. 对比 `data/rhythm.json` 的四项指标 + 人眼看 3 个片段（开场 5s / 中段 10s / 结尾 5s）；
4. 判据：B 的 `accents_per_min` 落在 9–12、`max_gap ≤6s`、`interruptions` 不升高。

## 8. 拍板结论（2026-10-19）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 默认档位 | **整体升一档**：`balanced` 不再用最初那张表的数，而是**再密一档**（节拍 3.6s、重音之间 10s、每段 2 个）；`calm` 只作回退档 |
| 2 | 音效闪避 | **只做「音效闪避人声」**（人声是主角、音效是配角；不压人声、不压原声）；默认 `-4dB`。⚠️ 今天的 §21 闪避是**跟随响度曲线**，不是「人声区间」——改成字幕区间驱动是下一批 |
| 3 | 鬼畜重复 / 变速 | **暂不做**（P2-3 / P3） |

## 9. 落地进度

**已落地（2026-10-19）**

- `process/rhythm.rs`：节拍网格 + 三档重音 + 空档补位 + 指标；**手法表**（2026-10-19 二次口径：
  「呼吸感运镜应该作为一个预设，只应用于一次事件，不要频繁出现，有点刻意了」）：
  `Punch`（轻，只抖不动机位）/ `Hold`（中，换近档并**保持**）/ `Cut`（重，硬切特写+闪白）/ 
  `Breathe`（呼吸，推近→回位，**整片最多 `[rhythm] breath_max` 次，默认 1**）；
  **第二批手法**（2026-10-19 用户「节奏手法增加几个」）：`Push`（慢推，只给 ≥8s 的段）/

  `Impact`（重击：重抖 + 白闪、**不换机位**）—— 每个都有整片上限（`push_max/pan_max/dutch_max/impact_max`），

  同档连续重音**不重复插运镜**（只有真的换档才动镜头）；
