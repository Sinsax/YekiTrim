# 报告格式

`scan.mjs` 往 `.workbuddy/topic-scan/scan-<时间戳>.md` 写一份固定七段的 Markdown。
**段序是判据的一部分**（"没有"这件事必须比"有"更早被看见），别重排。

## 一、范围

服务版本 / 项目数 / 事件数 / 未剪切数 / 有弹幕的项目数。

紧跟一张**「项目明细与数据可用性」**表：逐项目列出事件数、未剪数、弹幕数，
以及**数据缺失告警**（`⚠️ 无转写` / `⚠️ 无弹幕` / `⚠️ 弹幕：root_dir 不可读`）。

> 这张表是**防误判的关键**：如果某个项目弹幕读不到，那"没搜到"是**数据问题**而不是"内容不存在"。

## 二、⚠️ 三种「没有」

| 判定 | 依据 | 本次结果 |
|---|---|---|
| ❌ 真没有 | 三源全文都搜不到 | 是 / 否 |
| ⚠️ 有但漏检 | 命中落在事件缺口里 | N 处 |
| ⚠️ 有但碎了 | 命中段无归属 | 见下方清单 |

下面直接列**无归属命中**（`00:48:22 感觉要是带VR，就不会被开了` 这种）——
它们**目前剪不出来**，要先合并相邻事件或手建事件。

## 三、命中明细

- **3.0 分组概览**（仅发现模式）—— 每组命中数 / 涉及项目 / 最高热度。
  词表宽的时候先看这张表决定追哪一组，**不要**逐条读几百行。
- **3.1 未剪切（可剪）** —— 按事件聚合，一个事件一条：项目 · rank · 区间 · 类型 ·
  热度 · 弹幕/字幕量 · 标题 · 命中来源（`字幕「vr」` / `弹幕「维阿」`）· 原话 · 打开链接。
  发现模式下**每组只列前 5 条**，并提示用 `--json` 或 `--kw` 收窄。
- **3.2 已剪切对照** —— 这个话题有没有已经被剪过的。

## 四、缺口分析

> 这些时间段**一个字都没进过检测** —— 里面即使有你找的东西，也**不可能**出现在切片列表里。

按缺口时长降序：项目 / 区间 / 时长 / 字幕段数 / 内容摘录。

末尾固定附上修法与警告：重新检测会**按热度整体重排 rank**，已有片段对应可能错位。

## 五、未剪切热度榜 Top N

弹幕+字幕密度算出来的热度（就是 `popularity`）。**蹭流量先看这个。**
每行：项目 / rank / 区间 / 热度 / 弹幕 / 字幕 / 标题。

## 六、建议

- 可剪命中按热度排序（带 workbench 链接）
- ⚠️ 无归属命中的处理提示
- ⚠️ 缺口处理提示
- ⚠️ 没有弹幕的项目数（粉丝向内容会系统性排不高）

末尾固定一句：*本报告只读生成，未修改任何项目数据。剪切请在界面自行操作。*

## JSON 形态（`--json`）

```jsonc
{
  "stats":   { "server", "version", "projects", "events", "uncut", "cut", "keywords", "mode" },
  "hits":    [ { "projectId", "kind": "uncut|cut|orphan", "rank", "t", "source", "kws", "text" } ],
  "gaps":    [ { "projectId", "start", "end", "secs", "segCount", "excerpt" } ],
  "heat":    [ { "projectId", "rank", "pop", "dm", "sub", "start", "end", "label" } ],
  "projects":[ { "id", "name", "events", "uncut", "danmaku", "danmakuNote", "subtitleNote" } ]
}
```

`kind` 三档与报告第二节一一对应：`uncut` 可剪 / `cut` 已剪 / `orphan` 无归属。
